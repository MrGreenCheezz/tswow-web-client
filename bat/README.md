# Лаунчеры WebClient

Все bat-файлы проекта — в этой папке. Номер в имени — группа: `0x` играть, `1x` шлюз, `2x` сборка,
`3x` другие игроки. Запускать двойным щелчком; параметры — из консоли, например
`"bat\02 Играть - приложение (разработка).bat" --priority=high`. Каждый скрипт сам переходит в
папку WebClient, берёт Node.js из `WEBCLIENT_NODE_DIR` или встроенного `.runtime\node` (иначе —
системный), а при ошибке оставляет окно открытым.

| Файл | Что делает | Параметры |
| --- | --- | --- |
| `01 Играть - браузер.bat` | разработка в браузере в один клик: запускает шлюз в своём окне, если он не работает, затем Vite dev-сервер с горячей перезагрузкой и открывает http://127.0.0.1:5173/, когда оба ответят. Если Vite уже запущен, второй не стартует: скрипт только откроет страницу | `--no-browser` — не открывать браузер (так его запускает `02`) |
| `02 Играть - приложение (разработка).bat` | разработка в окне Electron: недостающие Vite (через `01 --no-browser`) и шлюз (`10`) — в отдельных окнах, затем окно Electron; пока шлюз собирается, окно пишет «Шлюз не запущен» и открывает игру, как только тот заработает | параметры оболочки (ниже), например `--priority=high`, `--webclient-url=…`, `--web-dir=dist\web` |
| `03 Играть - приложение (собранное).bat` | собранная Electron-версия `dist\electron\WoWWebClient.exe` (её собирает `21`): сама раздаёт страницу на 5173 и сама запускает шлюз, если его нет | параметры оболочки, например `--allow-stale` |
| `10 Шлюз - запустить.bat` | собрать и запустить шлюз (`npm run gateway:dev`). Лаунчеры `01`/`02` делают это сами | — |
| `11 Шлюз - перезапустить.bat` | остановить работающий шлюз и запустить снова — после сборки TSWoW, которая поменяла патчи клиента. Пересоберёт шлюз, если `src\` новее сборки | `build` — пересобрать всегда |
| `12 Шлюз - остановить.bat` | остановить шлюз на 8090; если это раздача для игроков (`32`), останавливается и её страница. Чужую программу на порту не трогает | `--dry-run` — только сказать, что было бы остановлено |
| `20 Сборка - игра.bat` | сборка веб-версии (`npm run build`): `dist\web\` — страница, `dist\code\` — шлюз | — |
| `21 Сборка - приложение.bat` | полная сборка Electron-версии: веб-версия, затем упаковка (`electron\build.mjs`) в `dist\electron\` | — |
| `22 Сборка - ресурсы.bat` | один раз: извлечь из клиента иконки заклинаний и семейств, имена предметов и существ, иконки предметов. Остальное шлюз делает сам по запросу | — |
| `23 Страница - собранная.bat` | раздать собранную `dist\web\` на http://127.0.0.1:5173/ без пересборки (`npm run preview`); шлюз запустите сами | — |
| `30 Игроки - собрать набор.bat` | приложение для игроков `dist\player\WoWWebClient.zip` и набор `dist\Для игроков\` (+ `dist\Для игроков.zip`), в конце открывает папку набора | `--url=http://…:8091/` — другой адрес для этой сборки |
| `31 Игроки - проверить у себя.bat` | проверка всей связки у себя: тот же сервер, что у `32`, но только на `127.0.0.1`, и то же приложение из `dist\player` против него | `browser` — та же страница в браузере |
| `32 Игроки - начать раздачу.bat` | раздать игру: страницу `dist\web` на порту 8091 и шлюз на 8090, на всех сетевых интерфейсах | `build` — пересобрать игру всегда |

`01`, `03` и `23` занимают один порт 5173 — запускайте что-то одно: шлюз по умолчанию принимает
страницу только с http://127.0.0.1:5173/.

Внутри bat-файлов только латиница: cmd читает их в кодировке консоли, и русский текст там
превратился бы в мусор. Поэтому сообщения скриптов английские, а друг друга скрипты находят по
номеру — переименовывать файлы можно, номера и пробел после них надо сохранить.

## Чёткие текстуры эффектов

Настройка «Чёткие текстуры эффектов» (улучшенная графика) берёт текстуры заклинаний, заранее увеличенные нейросетью
на видеокарте. Набор лежит в `.runtime\hd-textures\effects\` (в git не попадает) и собирается из вашего клиента
одной командой из папки WebClient, около минуты:

```
.runtime\node\node.exe tools\upscale-textures.mjs --set effects
```

- Нужна программа Real-ESRGAN в `.runtime\tools\realesrgan\` (уже скачана). Пока команда работает, видеокарта занята.
- Повторный запуск доделывает только недостающее. Запускайте его, если патч клиента поменял текстуры заклинаний: до этого
  шлюз отдаёт для изменённых текстур оригиналы. После обычной сборки TSWoW шлюз сам переподписывает набор за секунды.
- `--dry-run` — только сказать, что будет сделано; `--max-side 256` — увеличивать слабее (меньше памяти).
- Шлюз увидит новый набор без перезапуска; отключить набор — `HD_TEXTURES=0` в `.env`. Раздача игрокам (`32`)
  набор не отдаёт, пока в `.env` не стоит `PUBLIC_HD_TEXTURES=1`.

## Чёткие текстуры мира

Настройка «Чёткие текстуры мира» (улучшенная графика) берёт текстуры земли, зданий и (с 24.10) предметов обстановки,
деревьев и неба, увеличенные нейросетью вдвое и сжатые в формат видеокарты BC7 (видеопамяти столько же, сколько у
обычных). Существа, персонажи, предметы экипировки, миникарта, интерфейс, иконки и вода не увеличиваются — так решено
24.10, это последний шаг. Набор лежит в `.runtime\hd-textures\world\` (в git не попадает) и собирается из вашего клиента
одной командой из папки WebClient, с нуля около полутора часов:

```
.runtime\node\node.exe tools\upscale-textures.mjs --set world
```

- Сначала работает видеокарта (сеть realesrgan-x4plus, около 50 минут чистого времени, партиями), потом процессор
  сжимает текстуры (4 потока, около 15 минут). Пока команда работает, компьютер нагружен — не запускайте её во время игры.
- `--compress-only` — только пересжать (без видеокарты), `--workers 2` — меньше потоков процессора.
- Повторный запуск доделывает только недостающее; после обычной сборки TSWoW шлюз сам переподписывает набор.
  Одна текстура (статуя водопада в Ревущем фьорде) каждый раз не проходит проверку и остаётся оригиналом — это нормально.
- Набор занимает около 8,7 ГБ (PNG и BC7, 12 670 текстур). Шлюз отдаёт его только браузеру с поддержкой BC7 и только
  при включённой настройке; `HD_TEXTURES=0` и раздача игрокам (`32` без `PUBLIC_HD_TEXTURES=1`) его не отдают.

## Electron-версия: разработка и собранная

Перед первым запуском: `npm install` в папке `electron` (ставит Electron).

`02` запускает недостающее в отдельных окнах и открывает окно Electron. F11 — полный экран,
F12 — DevTools, Ctrl+R — перезагрузка.

Собранная версия (`21`, затем `03` или сам `dist\electron\WoWWebClient.exe`):

1. Vite **не** должен быть запущен: собранная версия сама раздаёт страницу на
   http://127.0.0.1:5173/ — единственном адресе, который шлюз принимает по умолчанию.
2. Шлюз отдельно запускать не нужно. Если на 127.0.0.1:8090 никто не отвечает, exe сам запускает
   его из папки WebClient и останавливает при закрытии окна (журнал
   `.runtime\logs\electron-gateway.log`). Уже запущенный шлюз (`10`, `11`, `32`) он использует как
   есть и не останавливает.
3. Если `dist\code` старше исходников шлюза, exe его не запускает: окно пишет «Шлюз собран из
   старых исходников» и ждёт, пока вы запустите `10` (он пересоберёт шлюз). Запустить прежнюю
   сборку как есть: `03 … --allow-stale` или `WoWWebClient.exe --allow-stale`.

`dist\electron\` распространять нельзя — в нём страница, собранная из данных вашего клиента.
Игрокам отправляется набор из `30`. Код оболочки, выбор страницы и все параметры запуска описаны
в [`../electron/README.md`](../electron/README.md#параметры-запуска).

## Для других игроков

Ваш компьютер раздаёт игру по сети, а игроки подключаются к нему. У игрока два способа:

- **браузер** — открыть ссылку `http://<PUBLIC_HOST>:8091/`;
- **приложение** — распаковать присланный `WoWWebClient.zip` и запустить `WoWWebClient.exe`.
  Это Electron-окно с той же страницей с вашего сервера.

В обоих случаях World of Warcraft у игрока не нужен: страница, текстуры, модели и звуки идут с
вашего компьютера, игровое соединение — через ваш шлюз к вашим authserver и worldserver.

### Плейтест со знакомыми: по шагам

1. **Порты.** На роутере (или там, куда смотрит ваш внешний адрес) проброшены на этот компьютер
   TCP **8091** (страница) и **8090** (шлюз). Больше ничего открывать не нужно: 3724 и 8085 остаются
   внутри машины. При первом запуске раздачи разрешите Node.js доступ к сети в окне Windows.
2. **Учётные записи.** Каждому тестеру — своя запись на вашем authserver (в консоли worldserver:
   `account create <логин> <пароль>`, в игре от ГМ — `.account create <логин> <пароль>`). Без неё не
   войти ни через браузер, ни через приложение.
3. **Серверы игры.** authserver и worldserver запущены, как для вашей обычной игры.
4. **Набор.** `30 Игроки - собрать набор.bat` → папка `dist\Для игроков\` и рядом
   `dist\Для игроков.zip`. Проверьте у себя: `31 Игроки - проверить у себя.bat` (только
   `127.0.0.1`, снаружи не видно).
5. **Раздача.** `32 Игроки - начать раздачу.bat` — держите окно открытым, пока идёт тест.
6. **Отправить тестерам** `Для игроков.zip` (или файлы из папки) и каждому — его логин и пароль:
   впишите их в строку «Логин: ______ Пароль: ______» файла `Как начать.txt` или пришлите отдельно.
7. **После теста** закройте окно раздачи (или `12 Шлюз - остановить.bat`); `11 Шлюз -
   перезапустить.bat` вернёт обычный локальный шлюз.

### Набор для игроков

`30` сначала собирает приложение, затем `tools\player-kit.mjs` складывает в `dist\Для игроков\`:

| Файл | Что это |
| --- | --- |
| `WoWWebClient.zip` | приложение игрока (копия `dist\player\WoWWebClient.zip`) |
| `Как начать.txt` | что это, два способа войти (приложение; браузер по ссылке `http://<PUBLIC_HOST>:<PUBLIC_WEB_PORT>/` из `.env`), строка для логина и пароля, клавиши |
| `Плейтест.txt` | [`docs/PLAYTEST.ru.md`](../docs/PLAYTEST.ru.md) простым текстом: что проверить и как сообщать о проблемах |

Рядом — `dist\Для игроков.zip` с этой же папкой, чтобы отправить один файл. Текстовые файлы — в
UTF-8 с BOM и переводами строк Windows: Блокнот откроет их правильно. Настоящий адрес попадает
только в эти локальные файлы (`dist` в git не идёт). Без `dist\player\WoWWebClient.zip` или без
`PUBLIC_HOST` в `.env` (и без `--url=`) набор не собирается — скрипт скажет почему.

### Проверить у себя, прежде чем отправлять

1. `30` — собрать приложение и набор.
2. `31` — запустить сервер для игроков в отдельном окне и открыть против него собранное
   приложение. `31 … browser` открывает ту же страницу в браузере (http://127.0.0.1:8091/).
3. Закрыть окно сервера (или `12`) — проверка окончена.

Сервер при этом слушает только `127.0.0.1`: снаружи его не видно, даже если порты проброшены.
Приложение то же, что уйдёт игрокам; адрес сервера ему подменяет параметр `--server-url`.

Одно отличие от настоящего адреса: `127.0.0.1` браузер считает безопасным, поэтому вход в
браузере здесь идёт через Web Crypto, а у игроков — через встроенный SHA-1. Этот путь покрыт
тестом `tests/sha1-fallback.test.mjs`.

### Настройка (один раз)

1. В `.env` указан адрес, по которому игроки видят ваш компьютер: `PUBLIC_HOST`. Порт страницы —
   `PUBLIC_WEB_PORT` (по умолчанию 8091). Всё остальное берётся из обычных настроек.
2. Наружу должны быть проброшены на этот компьютер TCP-порты **8091** (страница) и **8090** (шлюз).
   Порты 3724 и 8085 игрокам WebClient не нужны: к authserver и worldserver подключается шлюз на
   этой же машине.
3. При первом запуске `32` Windows спросит, разрешить ли Node.js доступ к сети. Нужно разрешить,
   иначе извне никто не подключится.

### Запуск раздачи

`32 Игроки - начать раздачу.bat`:

1. останавливает шлюз, работающий только для этой машины;
2. пересобирает игру, если `src\` новее сборки (`32 … build` — пересобрать всегда);
3. запускает страницу и шлюз для игроков в одном окне.

Закройте окно (или `12`), чтобы прекратить раздачу. Разработка на этой машине в это время работает
через тот же шлюз: Vite, `02` и `WoWWebClient.exe` его подхватят. После сборки TSWoW шлюз
перезапустится сам (`GATEWAY_RESTART_ON_PATCH`): сразу, если никто не подключён, иначе не позже чем
через 5 минут — игроки видят обратный отсчёт и сообщение «Сервер перезапускается после обновления»
(`GATEWAY_RESTART_DEADLINE_MIN`, `0` — ждать игроков сколько угодно). `11` вернёт обычный
локальный режим, и раздачу придётся запустить снова.

Изменения игры доходят до игроков без пересборки приложения: они получают страницу и ресурсы с
сервера. Пересобрать приложение нужно при изменении самой оболочки (`electron\`) — тогда
установленные приложения обновятся сами (см. «Обновление приложения») — и при смене `PUBLIC_HOST`
или `PUBLIC_WEB_PORT`. Смену адреса обновление не доставит: установленное приложение хранит свой
`server.json` со старым адресом, новый архив игрокам придётся прислать.

### Приложение для игроков

`30` собирает `..\dist\player\WoWWebClient\` и архив `WoWWebClient.zip` (~130 МБ). Внутри:

- Electron;
- оболочка `electron\main.cjs`;
- `server.json` с адресом страницы;
- `update.json` с версией приложения и открытым ключом обновлений;
- `README.txt` с инструкцией для игрока.

Страницы, шлюза и файлов клиента WoW в архиве нет.

Чем приложение отличается от браузера:

- **Вход по http.** Адрес сервера помечен как безопасный. Поэтому работают Web Crypto и
  cross-origin isolation, как на `127.0.0.1`.
- **Сервер недоступен.** Окно пишет «Нет связи с сервером» и подключается само, когда сервер
  заработает.
- **Процессор.** Приложение не закрепляет процессы за ядрами и не запускает PowerShell: неподписанный
  exe с PowerShell слишком похож на то, что ловят антивирусы. `--cpu-class=fastest` включает
  закрепление вручную.
- **Предупреждение Windows.** Windows может показать «Система Windows защитила ваш компьютер»,
  потому что у exe нет цифровой подписи. Об этом написано в `README.txt` игрока и в `Как начать.txt`.
- **Обновления.** Новую версию приложение находит и ставит само (ниже).

### Обновление приложения

Новый архив рассылать не нужно: установленные приложения обновляются сами.

1. **Версия.** Каждая сборка `30` получает следующий номер: `0.1.0.<N>`, где `0.1.0` — версия из
   `electron\package.json`, а `N` — счётчик сборок для игроков на этой машине. Править номер не
   нужно. Версии сравниваются как числа по частям: `0.1.0.10` новее `0.1.0.9`. Первые три числа
   можно поднять, понизить нельзя — сборка откажется.
2. **Подписанное описание.** Рядом с архивом сборка кладёт `dist\player\latest.json` — версию,
   размер, SHA-256 и имя архива — и `latest.json.sig`, подпись Ed25519 точных байтов
   `latest.json` (одна строка base64).
3. **Раздача.** `32` отдаёт их вместе со страницей: `/player/latest.json`,
   `/player/latest.json.sig`, `/player/WoWWebClient.zip` — только чтение, с ETag и `no-cache`.
   Новую сборку сервер подхватывает сразу, без перезапуска, а при запуске пишет, какую версию
   предлагает.
4. **Проверка в приложении.** Когда страница сервера открылась, приложение один раз запрашивает
   `latest.json` и подпись (3 секунды; при любой ошибке молчит). Если подпись сходится с ключом,
   встроенным в приложение, и версия новее, в правом верхнем углу окна появляется «Доступна новая
   версия N» с кнопками «Обновить» и «Позже».
   - **«Обновить».** Архив скачивается с прогрессом. Размер и SHA-256 сверяются с подписанным
     `latest.json`, затем архив распаковывается во временную папку (`tar` из Windows). Небольшой
     `update.cmd` ждёт, пока приложение закроется, и копирует новые файлы поверх его папки.
     `server.json` игрока и его собственные файлы в папке остаются. Затем приложение запускается
     снова. Журнал — `update.log` рядом с exe.
   - **Не получилось.** Если папка приложения закрыта для записи (например, `Program Files`) или
     что-то не удалось, окно пишет почему и предлагает «Скачать в браузере».
   - **«Позже».** Закрывает окно до следующего запуска, ничего не запоминая.

#### Ключ подписи

- Создаётся при первой сборке `30` в `..\.runtime\player-update-key\`: `private.pem`, `public.pem`
  и `release.json` со счётчиком версий. Папка `.runtime` в git не попадает.
- Открытый ключ встраивается в каждое собранное приложение, закрытый остаётся только на этой
  машине. Поэтому по обычному http обновление не подменить: приложение примет только `latest.json`,
  подписанный этим ключом, и только архив с подписанными размером и суммой.
- Сохраните копию этой папки. Без неё новые сборки получат другой ключ, а установленные приложения
  их не примут — игрокам придётся один раз скачать архив вручную.
- Приложения, собранные до появления обновлений, сами не обновятся: им новый архив нужно прислать
  один раз.

#### Проверить обновление у себя

1. `30` и скопировать `..\dist\player\WoWWebClient` в другую папку: это «установленное»
   приложение.
2. `30` ещё раз — версия станет на единицу больше.
3. `31 … browser` (сервер только на `127.0.0.1`; браузер можно закрыть) и скопированное
   приложение с параметром `--server-url=http://127.0.0.1:8091/`. Оно предложит новую версию, а после
   обновления запустится с тем же `--server-url`.

### Ограничения

- **Без HTTPS.** Страница идёт по обычному http. SRP6-вход и игровые пакеты защищены так же, как
  у оригинального клиента: пароль не передаётся, заголовки пакетов шифруются, содержимое (например,
  чат) — нет. В браузере по http нет Web Crypto — для входа используется встроенный SHA-1
  (`src/auth/Sha1.ts`) — и нет cross-origin isolation, поэтому позы толпы считаются в основном
  потоке. В приложении этих ограничений нет.
- **Файлы клиента доступны всем.** Любой, кто откроет ссылку, получает файлы клиента WoW с вашего
  компьютера. Прежний README проекта называл публичное размещение неподдерживаемым; кого пускать,
  решаете вы.
- **Лимит соединений.** Не больше 8 WebSocket-соединений с одного адреса и 256 всего. Если
  переадресация скрывает настоящие адреса игроков, все они делят один лимит — это примерно 4–8
  одновременных игроков.
- **Нагрузка на сервер.** Первые игроки запускают извлечение ресурсов на сервере: кеши в `data\`
  заполняются по мере игры. Сжатия и ограничения частоты запросов нет (см.
  [`docs/DISTRIBUTION_PLAN.ru.md`](../docs/DISTRIBUTION_PLAN.ru.md)).
