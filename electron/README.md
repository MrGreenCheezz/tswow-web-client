# Electron-версия

Та же страница, что и в веб-версии, в отдельном окне Electron. Отличия от браузера:

- процессы окна закреплены за производительными ядрами: на i7-12700KF с Windows 10 браузер иначе
  может оказаться на энергоэффективных, а кадр там в ~1,7 раза дороже;
- повышенный приоритет процессов, окно не притормаживается в фоне;
- вместо чёрного экрана окно говорит, чего не хватает (шлюза, Vite, связи с сервером), и само
  открывает игру, когда это появится;
- F11 — полный экран, F12 — DevTools, Ctrl+R — перезагрузка.

Код игры здесь не дублируется: страница берётся из общего `../src/browser/`. Из этой же папки
собирается приложение для других игроков.

Запуск и сборка — bat-файлы в [`../bat/`](../bat/README.md): `02` — разработка, `21` — сборка,
`03` — собранная версия, `30` — приложение и набор для игроков. Там же — как работает собранная
версия и раздача другим игрокам. Здесь — код оболочки, выбор страницы и параметры запуска.

## Файлы

| Файл | Что это |
| --- | --- |
| `main.cjs` | главный процесс: окно, выбор страницы, закрепление за ядрами, приоритет, экраны ожидания |
| `static-server.cjs` | раздаёт собранную страницу: в собранной версии вместо Vite; им же пользуется `tools\start-server.mjs` |
| `gateway.cjs` | запускает шлюз, если собранная версия не нашла уже работающий; проверка портов и свежести сборки шлюза |
| `gateway-target.cjs` | где шлюз страницы: порт 8090 на адресе страницы или настройка из `server.json` / параметров |
| `cpu-policy.ps1` | вычисляет маску производительных ядер и применяет её к процессам окна |
| `player-update.cjs` | обновление приложения игрока без Electron: формат и проверка подписанного `latest.json`, сравнение версий, загрузка с проверкой, распаковка, `update.cmd` |
| `update-notice.cjs` | окошко «Доступна новая версия» и порядок обновления в приложении игрока |
| `build.mjs` | упаковка: `..\dist\electron\` (для этой машины) или `--player` → `..\dist\player\` (для игроков) |
| `player-release.mjs` | для `build.mjs --player`: ключ подписи, номер версии, подписанный `latest.json`; в приложение не входит |

Перед первым запуском: `npm install` в этой папке (ставит Electron).

## Собранная версия и шлюз

Собранная версия (`build.mjs` → `..\dist\electron\WoWWebClient.exe`: Electron + эта оболочка +
собранная страница) запускает шлюз сама, если на 127.0.0.1:8090 никто не отвечает:
`node tools/start-gateway.mjs` из папки WebClient — на коде, собранном той же сборкой — и
останавливает его при закрытии окна. Пока шлюз стартует, в окне надпись «Запуск шлюза…». Если он
упал, в окне будет его ошибка, а журнал лежит в `.runtime\logs\electron-gateway.log`. Уже
запущенный шлюз exe использует как есть и не останавливает.

Перед запуском exe спрашивает `node tools\build-gateway.mjs --check`, не старше ли `dist\code`
исходников шлюза. Если старше, шлюз не запускается: окно пишет «Шлюз собран из старых исходников»
и ждёт, пока шлюз запустят (`bat\10` пересоберёт его). `--allow-stale` запускает прежнюю сборку
как есть.

Собранная версия ищет папку WebClient на два уровня выше себя. Если перенести `dist\electron\` в
другое место, шлюз придётся запускать вручную: окно подождёт его. Распространять эту папку
нельзя — в ней страница, собранная из данных вашего клиента. Игрокам отправляется приложение из
`build.mjs --player` (`bat\30`).

## Какую страницу открывает окно

Первое подходящее:

1. `--webclient-url=<адрес>` — открывается как есть, без проверок (так работает бенчмарк).
2. `--server-url=<адрес>` или `server.json` рядом с `main.cjs` — это приложение игрока
   (`build.mjs --player`). Открывается страница с сервера; пока сервер или его шлюз не отвечают,
   окно показывает «Нет связи с сервером».
3. Собранная страница: `--web-dir` или вложенная в `dist\electron`. Шлюз запускается сам.
4. Vite dev-сервер на http://127.0.0.1:5173/. Шлюз запускает разработчик, окно его ждёт.

Если страница открыта по обычному http не с `127.0.0.1` (сервер для игроков), оболочка помечает
этот адрес и адрес шлюза как безопасные. Иначе Chromium не даёт cross-origin isolation, и позы
толпы считаются в основном потоке (вход по http работает и без этого — через `src\auth\Sha1.ts`).

Шлюз оболочка ждёт там же, где его ищет страница: на порту 8090 адреса страницы. Если шлюз сервера
слушает другой порт или живёт на другом адресе (TLS, прокси), это пишется в `server.json`
(`"gatewayPort": 9000` или `"gatewayUrl": "https://gw.example"`; `build.mjs --player` берёт их из
`--gateway-port=`/`--gateway-url=` или `GATEWAY_PORT` в `.env`) либо передаётся параметрами ниже.
Тогда оболочка открывает страницу с `?gateway=<адрес>`. Шлюз на другом имени страница примет,
только если ему доверяет её сборка (`VITE_GATEWAY_ORIGIN` или `VITE_GATEWAY_ALLOWED_ORIGINS`).

Разработка и собранная версия делят один профиль, поэтому настройки интерфейса общие. У приложения
игрока профиль свой.

## Обновление приложения игрока

Обновления проверяет только приложение игрока: только `build.mjs --player` кладёт рядом с
`main.cjs` файл `update.json` с версией и открытым ключом. Проверка идёт, лишь когда окно открывает
сервер для игроков (`server.json` или `--server-url`). Собранная версия для этой машины
(`..\dist\electron\`) и разработка такого файла не имеют и обновлений не ищут.

Как это устроено для владельца и игрока — в [`../bat/README.md`](../bat/README.md#обновление-приложения).
Коротко:

- **Сборка.** Каждая сборка `--player` получает версию `<версия package.json>.<N>` и подписывает
  `latest.json` ключом Ed25519 из `..\.runtime\player-update-key\`.
- **Проверка.** При первой загрузке страницы сервера приложение запрашивает
  `player/latest.json` и `player/latest.json.sig` относительно адреса страницы. Подпись
  проверяется по точным байтам ответа, затем версия сравнивается по числам.
- **Окошко.** Это отдельное маленькое окно без рамки поверх правого верхнего угла. Его страница
  (`data:`) кнопками ведёт на `http://update.invalid/<действие>`, а `will-navigate` перехватывает
  переход. Ни preload, ни IPC нет, страница игры до него не дотягивается.
- **Установка.** `update.cmd` из двух ступеней. Первую приложение запускает не отсоединённой
  (иначе у cmd нет консоли, и `robocopy`/`ping` открыли бы свои окна) и ждёт её выхода. Вторая через
  `start /b` выходит из job-объекта, который libuv закрывает вместе с приложением. Она ждёт, пока
  exe приложения можно открыть на запись, и копирует файлы через `robocopy` без `/MIR`. Пути
  передаются в переменных окружения `WOWUPD_*`: файл скрипта cmd читает в кодировке консоли, а
  окружение — в Unicode, поэтому кириллица в пути не ломается. PowerShell не используется.

## Параметры запуска

Передаются через `bat\02 Играть - приложение (разработка).bat`, `bat\03 Играть - приложение
(собранное).bat` или `WoWWebClient.exe`:

| Параметр | Значение |
| --- | --- |
| `--webclient-url=<url>` | открыть этот адрес, например `http://127.0.0.1:5173/?framexml=1` |
| `--server-url=<url>` | сервер для игроков вместо адреса из `server.json`: так `bat\31` (проверка у себя) направляет приложение на `127.0.0.1` |
| `--web-dir=<папка>` | раздавать собранную страницу из папки, например `dist\web` (путь от папки WebClient при запуске через `bat\02` и `bat\03`) |
| `--port=<порт>` | порт собранной страницы, по умолчанию 5173; другой порт добавьте в `ALLOWED_ORIGINS` |
| `--cpu-class=fastest\|fastest-cores\|slowest\|none` | ядра: производительные (по умолчанию; у приложения игрока — `none`), по одному логическому CPU на производительное ядро (для замеров, выигрыша не дало — PERF_STATUS, шаг 29), энергоэффективные, на выбор Windows |
| `--priority=normal\|abovenormal\|high` | приоритет процессов, по умолчанию `abovenormal` (у приложения игрока — `normal`) |
| `--window=<ширина>x<высота>` | размер окна, по умолчанию `1600x900` |
| `--uncapped` | без vsync и ограничения частоты кадров (для замеров) |
| `--inactive` | окно открывается, не забирая фокус (стенд, пока вы играете) |
| `--no-isolation` | без заголовков cross-origin isolation: позы толпы останутся в основном потоке |
| `--no-js-profiling` | без заголовка `Document-Policy: js-profiling`: запись фризов (`O` → «Записать фризы») пойдёт без выборок стеков |
| `--gateway-port=<порт>` | шлюз на этом порту адреса страницы, вместо 8090 и вместо `server.json` |
| `--gateway-url=<url>` | шлюз по этому адресу (другое имя, https), вместо `server.json` |
| `--allow-stale` | собранная версия запускает шлюз, даже если `dist\code` старше исходников |
