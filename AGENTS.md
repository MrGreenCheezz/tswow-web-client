# WebClient

Браузерный клиент WoW 3.3.5a build 12340 для TSWoW/TrinityCore. Стек: TypeScript, Vite, Three.js, Node.js gateway. Пути и команды ниже заданы от `F:\tswowRoot\WebClient`.

## Карта проекта

- `src/browser/` — отображение, ввод и интерфейс браузера. `src/browser/app/NativeAppShell.ts` глушит поведение страницы (выделение, перетаскивание картинок, браузерные клавиши, масштаб, навигацию): новый перетаскиваемый элемент помечай `draggable="true"`, выделяемый текст — только в полях ввода.
- `src/gateway/` — серверная часть gateway; `src/auth/`, `src/transport/`, `src/protocol/`, `src/world/` — авторизация, транспорт, протокол и состояние мира.
- `src/generated/` — фасады и таблицы; `client-data/` и `protocol-data/` внутри него — локально сгенерированные данные.
- `tools/` — генерация, работа с ресурсами, запуск gateway и проверки; `tests/*.test.mjs` — Node-тесты.
- `index.html`, `glue.html`, `framexml.html`, `character-lab.html` — точки входа Vite; параметры сборки в `vite.config.mjs`.
- `README.md` — карта для человека: веб-версия и Electron-версия, их запуск и сборка.
- `web/` — bat-файлы запуска и сборки веб-версии (`start-dev` поднимает недостающие gateway и Vite через `tools/port.mjs`, `build`, `start-built`); код страницы остаётся в `src/browser/`.
- `electron/` — Electron-версия: `main.cjs` (окно, P-ядра, выбор страницы: `--webclient-url` → `server.json` приложения игрока → собранная страница → Vite; экраны ожидания вместо чёрного экрана; http не с loopback помечается безопасным), `static-server.cjs` (раздача собранной страницы, её же использует `tools/start-server.mjs`), `gateway.cjs` (собранная версия сама запускает gateway на 8090, если он не слушает, и останавливает свой при выходе; журнал `.runtime/logs/electron-gateway.log`), `build.mjs` (упаковка в `dist/electron/`, с `--player` — приложение игрока в `dist/player/WoWWebClient.zip`), свой `package.json` и `node_modules`, bat-файлы. `bench/run.mjs --browser electron` использует эту папку.
- `online/` — для других игроков: `start-server.bat` (`tools/start-server.mjs`: `dist/web` на `PUBLIC_WEB_PORT`=8091 и gateway на 8090 на всех интерфейсах для `PUBLIC_HOST` из `.env`, `MODULE_UI_WRITE=0`; `tools/stop-gateway.mjs` его тоже останавливает), `build-player.bat` и `test-local.bat` (`tools/test-local.mjs`: тот же сервер только на 127.0.0.1 и приложение из `dist/player` с `--server-url`). Страница по http без TLS: вход в браузере идёт через `src/auth/Sha1.ts`, когда нет `crypto.subtle`.
- `start-gateway.bat`, `restart-gateway.bat`, `build-assets.bat` в корне — общие для всех вариантов.
- `docs/` — планы и отчёты: `CLIENT_PARITY_PLAN.ru.md` с матрицами в `docs/parity/`, `DISTRIBUTION_PLAN.ru.md` (раздача другим игрокам), `PERF_STATUS.md` и другие отчёты о производительности.
- `dist/` (`web/` — страница, `code/` — gateway, `electron/` — упакованная Electron-версия, `player/` — приложение игрока, единственное из `dist/`, что можно отправлять), локальные кеши `data/`, извлечённые ресурсы и `node_modules/` — результаты и зависимости. `CPPClientExample/` — отдельный проект для сравнения.

## Контракты

- Проверяй опкоды, поля пакетов и схемы данных по совместимому серверному ядру и существующим генераторам. Не заменяй неизвестные значения предположениями ради прохождения тестов.
- Сохраняй границы browser/gateway и строгие настройки `tsconfig.json`. Сервер определяет результат игровых действий.
- Производные таблицы исправляй через источник или генератор. Различай отслеживаемые фасады и локальные клиентские данные; следуй `.gitignore` для ресурсов, конфигурации и кешей.
- Настройки среды определены в `.env.example` и загружаются инструментами проекта. Секреты и содержимое локального `.env` не переноси в исходники, инструкции или отчёты.

## Окружение и запуск

- Версии и команды сверяй с `package.json` и lock-файлом. Указаны Node.js 22+, npm 10+; source test hook использует `registerHooks` и требует Node.js 22.15+.
- Перед установкой зависимостей прочитай lifecycle scripts. Для восстановления npm-зависимостей используй `npm ci`, когда это нужно задаче.
- `npm run dev` запускает Vite; `npm run gateway` — gateway. Их pre-hooks выполняют подготовку данных/сборку.
- `npm run build` собирает TypeScript и Vite. `npm test` сначала выполняет эту сборку, затем Node-тесты.
- `npm run preview` раздаёт `dist/web` на `WEB_PORT`; `npm run electron:build` собирает веб-версию и упаковывает Electron-версию; `npm run server` и `npm run player:build` — раздача другим игрокам и их приложение. Запуск раздачи открывает порты наружу — это действие по просьбе владельца; для проверок привязывай её к локальному адресу через `PUBLIC_BIND`. Страницу на 5173 раздаёт что-то одно: Vite, `vite preview` или собранная Electron-версия — gateway принимает только origin из `ALLOWED_ORIGINS`.

## Проверки исходников

При установленных зависимостях и подготовленных локальных данных:

```powershell
node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit
# Пример узкой проверки; выбирай тест изменённой подсистемы.
npm run test:file -- tests/asset-path.test.mjs
# Полный набор тестов текущих исходников при широкой области изменений.
npm run test:source
```

- Тесты запускай через `tools/run-tests.mjs` (`test:file`, `test:source`, `test`). Он ограничивает параллельность и кучу, берёт Node 22 из `.runtime/node` и завершает тестовый процесс, чья память превысила 6 ГБ. Полный набор — один прогон за раз, не параллельно с другими прогонами.
- Source hook читает текущие TS-исходники без обновления `dist`; он не заменяет проверку типов.
- `npm run typecheck` имеет `pretypecheck`, который генерирует данные. Для проверки без генерации используй прямой вызов `tsc` выше.
- `npm run check:generated` проверяет соответствие генераторов; `npm run check:workspace` добавляет проверку модулей. Для них нужны входные данные текущей конфигурации.
- `npm run build:autonomous` также собирает client pack; это отдельный workflow упаковки. Выбирай его, когда упаковка входит в задачу.
- При отсутствии исходных данных явно укажи ограничение и выполни доступные проверки. После визуальных изменений проверь затронутый экран и взаимодействие в браузере.
- Различай проверку исходников, сборку, браузерный сценарий и живое подключение к серверу. Для изменения только документации достаточно проверки текста и ссылок.

## Источники данных и связи проектов

- `tools/generate-protocol.mjs` получает опкоды, направления пакетов, поля обновлений, коды ответов (`ResponseCodes`) и результаты авторизации (`AuthResult`) из выбранного TrinityCore; `TRINITYCORE_DIR` задаёт источник. Реальные таблицы лежат в `src/generated/protocol-data/`, а соседние `src/generated/opcodes.ts`, `opcodeCoverage.ts`, `responseCodes.ts` и `authResults.ts` только экспортируют их.
- `D:\WowTest\Tools\ProtocolGen\generate-protocol.mjs` читает эти реальные таблицы для Unity-каталога `WowOpcodeCatalog.cs`. Для его параметров `--opcodes` и `--coverage` нужны файлы из `protocol-data/`, а не фасады.
- Ресурсы исходного клиента читаются из `CLIENT_DIR`. `CLIENT_PACK_DIR`, если задан, переключает ресурсный pipeline на готовый пакет с `Data/` и `client-pack.json`.
- Dataset предоставляет DBC, карты, vmaps и `luaxml/Interface`; `tools/paths.mjs` разрешает `TSWOW_INSTALL`, `TSWOW_DATASET`, `DBC_DIR`, `MAPS_DIR`, `VMAPS_DIR`. Метаданные из world-БД инструменты получают через выбранный `WORLDSERVER_CONF`.
- Для UI-модулей по умолчанию сначала читается `data/ui/`, затем `TSWOW_INSTALL/modules/*/content/`; черновик перекрывает соответствующий файл модуля. `MODULE_DIRS` заменяет оба источника.
- WowTest также использует инструменты и собранный код WebClient при подготовке локального RuntimeBundle; runtime собранного Unity-клиента читает установленный комплект.

## Выбор игрового окружения

Проверенные локальные ориентиры; перед запуском сверяй текущие значения. `tools/env.mjs` загружает `.env`, сохраняя приоритет переменных вызывающего процесса; `WEBCLIENT_SKIP_ENV=1` отключает загрузку файла.

| Настройка | Текущее значение / результат разрешения |
| --- | --- |
| `TRINITYCORE_DIR` | `F:\tswowRoot\tswow\cores\TrinityCore` |
| `TSWOW_INSTALL` | `F:\tswowRoot\tswow-install` |
| Dataset и realm-конфиг по умолчанию | `modules/default/datasets/dataset/` и `modules/default/realms/realm/worldserver.conf` внутри выбранной установки |
| `CLIENT_DIR`, locale | `F:\Circle`, `ruRU` |
| Web / gateway | `127.0.0.1:5173` / `127.0.0.1:8090` |
| Auth / world | `127.0.0.1:3724` / `127.0.0.1:8085` |

Текущие файловые входы относятся к Tswow. Для CleanTswow согласованно выбирай его `source/cores/TrinityCore`, `tswow-install/`, клиент `F:\CircleClean` и realm-конфиг с MySQL `3308` вместо `3306`. Один адрес `localhost` не определяет установку: сверяй путь серверного процесса. LegionTest использует другие версии протокола.

При правках игровых модулей или runtime прочитай `../AGENTS.md`: сборка данных/аддонов может автоматически публиковать клиентские патчи.

## Завершение задачи

- По запросу определи проверяемый результат и доведи до него реализацию, необходимые проверки и исправления. Не останавливайся на первой версии ради промежуточного согласования, если пользователь его не запросил.
- Читай исходники, документы и конфигурации по затронутой области; карта проекта служит указателем, а не обязательным маршрутом чтения перед каждой правкой.
- Самостоятельно выполняй локальные правки и проверки в согласованной области. Исправляй вызванные ими ошибки и повторяй затронутые проверки. После успеха расширяй проверки только при новых изменениях, сбоях или конкретном непроверенном риске; для правок документации достаточно проверки текста.
- Учитывай уже выданные разрешения и уточнения пользователя. Не считай рабочую БД одноразовой тестовой фикстурой. Публикацию, установку, перезапуск рабочих сервисов и изменения рабочих данных выполняй, когда они входят в согласованную задачу; если разрешения не хватает, сначала закончи независимую подготовку и уточни конкретное действие и цель.
- При недоступной проверке продолжай независимую работу, затем укажи блокер и непроверенный критерий; не объявляй задачу полностью выполненной. Если остановку вызывает инструкция, назови файл и конкретное правило. Уточнения пользователя имеют приоритет над этим файлом в рамках системных ограничений.
- В результате сообщи, что изменено, чем подтверждён результат и что осталось непроверенным. В длительной задаче сохраняй критерии готовности, разрешения и оставшуюся работу в заметках задачи, не в постоянном AGENTS.md.
- Для изменения клиента проверь затронутые типы/тесты, для UI — экран и взаимодействие; если запрошен автономный пакет или подключение к серверу, проверь именно этот результат.
