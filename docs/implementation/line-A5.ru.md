### М-A5-1 «Единый тултип» (4.01; используют 4.04, 4.10, 1.28, 4.14, 4.08 и все окна с `title`)
- **Назначение.** Один элемент подсказки на весь интерфейс вместо `title` браузера (задержка ~1 с, без стилей, не показывается на отключённом контроле, не читается клавиатурой) и вместо разнобоя собственных `div`.
- **Форма.** Новый `src/browser/ui/Tooltip.ts` (реэкспорт из `Widgets.ts`, потребители не меняются): `attachTooltip(target, () => TooltipContent | undefined, {onHide})` (уже есть), `setTip(target, string | provider | undefined)`, `getTip(target)`, `showTooltipAtPoint(key, content, x, y)`/`hideTooltipAtPoint(key)` (режим у курсора для мира), `hideTooltip()`, `refreshTooltip()`; `TooltipContent` получает `titleColor?: string` (#rrggbb) и `plain?: boolean`. Константы `TIP_DELAY_MS = 250`, окно «тёплого режима» 400 мс; карточки предметов и заклинаний остаются мгновенными. Доступность: `role="tooltip"`, `aria-describedby` только пока показана, показ по `:focus-visible`, скрытие по нажатию/прокрутке/Escape/`dragstart`. Сетка безопасности: `installTitleTooltips(doc)` в `NativeAppShell.installNativeAppShell` — перехват `pointerover` (capture) + `MutationObserver` по атрибуту `title` переносит любой `title` в тултип до нативного показа и не теряет имя для скринридера (`aria-label`, если имени нет, иначе `aria-description`).
- **Как применять.** Новый код — только `attachTooltip`/`setTip`; `el.title = …` запрещён ратчетом `tests/title-audit.test.mjs`. Причина «серой» кнопки — `aria-disabled` + `.ui-unusable` + подсказка, а не `disabled` (браузер не шлёт событий отключённым контролям).
- **Файлы.** `ui/Tooltip.ts`, `ui/Widgets.ts`, `app/NativeAppShell.ts`, `style.css` (`.ui-tooltip`: `pointer-events: none`, z-index выше штатных окон).
- **Тесты.** `tests/tooltip.test.mjs`, `tests/native-app-shell.test.mjs`, `tests/title-audit.test.mjs`, существующий `tests/widget-dom.test.mjs`.
- **Типичные ошибки.** Сравнивать `el.title` после переноса (читает пустоту → запись каждый кадр; использовать `getTip`); показывать подсказку внутри окна с `overflow: auto` (она на `body`); оставлять подсказку по `blur` после клика (нужен `:focus-visible`); Escape закрывает окно вместо подсказки (обработчик подсказки перехватывает первое нажатие).

### 1.04 — Клавиши 1–= и бонус-панель (стойки, формы, незаметность)
- **Подход.** Стоковый `ActionButtonDown(id)` выбирает кнопку `BonusActionButton<id>`, когда показан `BonusActionBarFrame`; её действие считает `ActionButton_CalculateAction`: `page = GetActionBarPage()`, и **только если `page == 1`** (или `alwaysBonus`) `page = NUM_ACTIONBAR_PAGES + GetBonusBarOffset()`; действие = `id + (page-1)*12`. Значит слот клавиши = 0-based `(5 + offset)*12 + column` при основной странице 1 и `offset > 0`; при странице 2–6 бонус-панель игнорируется. Клик мышью в штатном HUD уже верен, потому что штатный код сам считает абсолютное действие, а `useAction` (`FrameXmlWorldMount.ts`, поле `useAction`) переводит его в `(column, page)`. Ломается ровно один путь: native `Controls → runAction → useSlot(column)` берёт `page` из локальной переменной `ActionBar.ts` и не знает про форму. Этот путь обслуживает клавиши **и** штатный HUD, и native HUD, поэтому чинить нужно в одном месте: сделать страницу по умолчанию у `useSlot` бонус-aware. Решение: чистая функция `bonusActionPage(mainPage0, offset)` в DOM-free `world/ActionBarProtocol.ts` + чистое вычисление `bonusBarOffset(world, spell)` в новом DOM-free `game/BonusBar.ts` (сейчас оно спрятано внутри `LiveWorldSeam.bonusBarOffset`, а native без штатного шва его вызвать не может). Native-панель тоже должна рисовать бонус-страницу, иначе клавиша нажмёт то, чего на панели не видно.
- **Сверено.**

### 4.02 — Значок вместо «полупрозрачной копии кнопки» при перетаскивании (`setDragImage`)
- **Подход.** Пять источников HTML5-перетаскивания не вызывают `setDragImage`, поэтому браузер рисует под курсором полупрозрачный снимок всей кнопки (рамка, подпись, таймер восстановления, счётчик), а в оригинале к курсору «приклеен» сам значок. Один помощник `beginIconDrag(event, source)` строит значок 36×36 (иконка кнопки, рамка качества предмета, счётчик стопки) и передаёт его в `event.dataTransfer.setDragImage(ghost, 18, 18)`; вызывается из пяти обработчиков `dragstart`. **Вне этого пункта — «предмет на курсоре»** (подхват щелчком и опускание щелчком в native-окнах): это модель курсора, а не перетаскивание, она есть только в штатном HUD (`FrameXmlCursorModel`, `FrameXmlCursorDom.ts` — картинка у курсора и сброс по нажатию на мир/Escape). Для native — отдельный пункт объёма L, только если native остаётся полноценным HUD (0.4h): открытый вопрос владельцу.
- **Сверено.** Источники: `ActionBar.ts` `buildButton` (:90-98, дополнительные панели) и `build` (:184-192, главная панель) — `setData(DRAG_FORMAT, …)`; `ItemSlots.ts` `attachDragAndDrop` (≈540-552) — `ITEM_DRAG_FORMAT` и второй формат для панели (`itemActionDragPayload`); `PetBar.ts` (:84-87) — `text/pet-slot`; `Spellbook.ts` (:789-793) — `actionDragPayload(spellId)`; `Macros.ts:302` — `macroDragPayload` пока без вызовов (4.05). Оболочка: `NativeAppShell.ts` `nativeShellAllowsDrag` разрешает `dragstart` только у `[draggable="true"]` (правило, зафиксированное в AGENTS.md); картинки и ссылки — `-webkit-user-drag: none` в `NATIVE_APP_SHELL_CSS`, поэтому `<img>` внутри кнопки сам не тащится. `setDragImage` принимает элемент, который уже нарисован: для открепленного элемента Chromium иногда рисует пустоту — помощник кладёт призрак в фиксированный контейнер за экраном (`position: fixed; left: -1000px`) и убирает его на следующей задаче.
- **Изменения.**
  1. Новый `src/browser/ui/DragGhost.ts`: `beginIconDrag(event: DragEvent, ghost: { icon?: string; quality?: number; count?: number; label?: string })` — строит `div.drag-ghost` (фикс. контейнер), `img` с тем же `src` (значок уже загружен кнопкой; кэш браузера), рамка по `data-quality` (стили — `style.css`, класс `.drag-ghost`), счётчик; `setDragImage(el, 18, 18)`; `setTimeout(() => el.remove(), 0)`; если `dataTransfer` нет — ничего. - **Тесты.** Новый `tests/drag-ghost.test.mjs` (фиктивный DOM `tests/fixtures/fake-ui-document.mjs`): `beginIconDrag` вызывает `setDragImage` ровно один раз с элементом 36×36 и смещением `(18, 18)`; призрак убирается после таймера; для слота без значка (`label`) — `setDragImage` всё равно вызван (буква), а не пропущен; без `dataTransfer` — исключений нет. ### 4.06 — Члены группы вне видимости на карте и миникарте; метка на миникарте обычным щелчком
- **Подход.** Карта мира (`WorldMap.ts` `drawMarkers`, ≈698-712) и миникарта (`Minimap.ts` `collectBlips`, ≈742-748) рисуют члена группы только если `state.objects.get(guid)?.position` есть, то есть пока он в зоне видимости клиента. В оригинале точка остаётся: положение члена вне видимости приходит пакетом `SMSG_PARTY_MEMBER_STATS` (`GROUP_UPDATE_FLAG_POSITION`), и клиент уже разбирает его, но положит в `partyStats` «сырые» `positionX/positionY` (`PartyProtocol.ts` ≈76-90, `WorldClient.ts:998, 7593-7596`) и никто их не читает. Значения — обрезанные до `uint16` мировые координаты: отрицательная координата приходит как `65536 + x`, разбор однозначен через знаковое 16-битное (диапазон карт ±17066 умещается в ±32767), дробная часть потеряна. Решение: DOM-free `game/PartyPositions.ts` — `partyMemberPosition(world, guid) → { x, y, precise } | undefined`: точная позиция объекта, иначе грубая из `partyStats` (знаковое декодирование), только если участник на той же карте и в сети. Карта и миникарта берут позицию у него; грубая точка рисуется тем же цветом, но без обводки/полупрозрачно (не выдавать округлённые ярды за точные). Метка: обычный щелчок по миникарте отправляет пинг, как стоковый `Minimap_OnClick`.
- **Сверено.**
  - Ядро: `GROUP_UPDATE_FLAG_POSITION = 0x100` — два `uint16` (`Group.h:109`), пишутся как `uint16(player->GetPositionX())`/`GetPositionY()` (`GroupHandler.cpp:805-809` и полный набор `:974, :1019-1020`); `Player.cpp:6538-6539` при каждом обновлении позиции члена группы ставит флаг (`SetGroupUpdateFlag(GROUP_UPDATE_FLAG_POSITION)`), а вне видимости члены получают пакет от `Group::UpdatePlayerOutOfRange` — то есть данные приходят именно для тех, кого клиент не видит. Позиция без карты: только `GROUP_UPDATE_FLAG_ZONE` (`uint16 zoneId`).
  - Клиент: `PartyProtocol.ts:34-37, 138-141` — оба поля читаются `reader.u16()`; `mergePartyMemberStats` копит; событие `PARTY_MEMBER_STATS {guid}` (`EventBus.ts:407`); `world.group.members[i]` = `{name, guid, online, status, subGroup, flags, roles}` (`GroupProtocol.ts:32-40`) без позиции.

Стоково: `Minimap.lua:177-188` `Minimap_OnClick` (`OnMouseUp`, `Minimap.xml:692`) пингует **любым** щелчком внутри радиуса, `Minimap:PingLocation(x, y)`; клиент шлёт `MSG_MINIMAP_PING` (координаты float). Круг радиуса — `sqrt(x²+y²) < width/2`.

### 4.13 — Счётчик 20-секундного выхода в native-панели
- **Подход.** В штатном HUD счётчик есть: стоковый `CAMP` (`StaticPopup.lua:1476-1494`, `timeout = 20`, `hideOnEscape`, `OnHide` при `timeleft > 0` вызывает `CancelLogout`) считает вниз секунды и печатает `CAMP_TIMER` «До выхода в меню выбора персонажа: %d %s.» (`GlobalStrings.lua:1337`, формат по `StaticPopup.lua:3321-3326`: `ceil(timeleft)`, до 60 — секунды `SECONDS = "с"`, дальше минуты). ### 4.15 — Ожидание NPC без тайм-аута и клик по объекту вне дальности без отклика
- **Подход.** Два молчащих провала одного корня: **сервер не отвечает, а клиент молчит.** (1) Клик по NPC отправляет `openGossip`/`openVendor`/… и сразу показывает заглушку «Ожидание ответа NPC…» (`Npc.ts` `showPendingNpcDialog`, ≈204-218). Если игрок дальше `INTERACTION_DISTANCE` (5 ярдов плюс досягаемости обоих, `ObjectDefines.h:24`; `Player::GetNPCIfCanInteractWith`, `Player.cpp:2283+`, при отказе возвращает `nullptr`, а обработчики просто `return`), NPC мёртв, чужой фракции или под контролем — ответа не будет никогда, заглушка висит до ручного закрытия. (2) Клик по объекту (`interactWithGuid`, ветка `typeId === 5`) вне дальности: `gameObjectAction` (`game/Interaction.ts` ≈36-60) возвращает `undefined` по `distance > interactionDistance(type)`, и вызов молча выходит. Решение: (1) — тайм-аут заглушки с осмысленным сообщением, **без** предварительной блокировки клика (клиентская проверка дальности без досягаемостей может отказать законному клику); (2) — сообщение о дальности.
- **Сверено.** `Npc.ts` `interactWithGuid` (≈95-190): NPC-ветка вызывает `showPendingNpcDialog()` перед `world.openGossip(guid)`/`openQuestList`/`requestPetitionVendor`/`requestTaxiMenu`/`battlemasterHello`/`openTabardVendor`; стоковый GossipFrame/TaxiFrame при опубликованном штатном UI заглушку не рисует (:206-212). GO-ветка: `gameObjectAction` → `undefined`, затем `gameObjectLockHint` (тоже `undefined` вне дальности, `Interaction.ts` ≈75-95) → молчание. Готовый канал сообщений — `notice()` (`ui/Notices.ts`; уже используется в GO-ветке для подсказки про отмычку). Стоковые тексты (`GlobalStrings.lua`): `ERR_OUT_OF_RANGE = "Слишком далеко."` (:3341), `ERR_LOOT_TOO_FAR` (:3230), `ERR_TAXITOOFARAWAY`, `ERR_NO_BANK_HERE` — специальных строк «слишком далеко до NPC/объекта» для беседы и `GameObject` в GlobalStrings **нет** (искал по «слишком далеко»): оригинал показывает общий `ERR_OUT_OF_RANGE`.
- **Изменения.**
