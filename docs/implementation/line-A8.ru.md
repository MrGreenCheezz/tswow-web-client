## Общие механизмы

Линия A8 не владеет механизмами М1–М8 и ни на один не опирается. Ниже — механизмы, которые возникли внутри линии; другие линии ссылаются на них по имени.

### A8-М1 «Очередь входа кастомных сообщений» (9.03)
- **Назначение.** Ни одно сообщение модуля на 0x102 не пропадает только из-за того, что потребитель (окно, Lua-аддон) поднялся позже пакета. Сообщения держатся общей FIFO-очередью и выпускаются по порядку прихода, когда готовы все ожидаемые потребители или истёк запасной таймер.
- **Форма.** `CustomPacketRegistry` (`src/world/CustomPacketRegistry.ts`): `beginBacklog({ expect, maxMessages?, maxBytes?, ttlMs? })`, `offer(opcode, body): "delivered" | "held" | "unclaimed"`, `consumerReady(name)`, `flushBacklog(reason)`, `dispose()`, геттер `backlog`; опции конструктора `schedule`, `onBacklogUnclaimed`. `deliver` остаётся синхронным «доставить сейчас» и вызывается из выпуска. Потребители идентифицируются строкой: сейчас `"modules"` (загрузчик JSON-окон) и `"lua"` (монтирование FrameXML с аддонами).
- **Как применять.** Новому потребителю кастомных пакетов: (1) добавить его имя в `expect` в `EnterWorld.ts` перед `loginCharacter`; (2) вызвать `world.customPackets.consumerReady("<имя>")` в `finally` того асинхронного шага, после которого потребитель подписан на опкоды; (3) подписываться обычным `on(...)`/`define(...)` — доставка из очереди произойдёт сама, не внутри вызова подписки. Пустой `expect` (аддоны выключены) — очереди нет.
- **Файлы.** `src/world/CustomPacketRegistry.ts`, `src/world/WorldClient.ts` (ветка 0x102, конструктор реестра, `close`), `src/browser/app/EnterWorld.ts`, `src/browser/ui/Diagnostics.ts`.
- **Тесты.** `tests/custom-registry.test.mjs`, `tests/custom-packet.test.mjs`, `tests/framexml-socket-vertical.test.mjs`, `tests/framexml-world-mount-lifecycle.test.mjs`.
- **Типичные ошибки.** Вызвать подписчика внутри `on()` (Lua-колбэк побежит посреди загрузки аддона); забыть `consumerReady` в ветке ошибки (тогда выпуск только по таймеру, 30 с); хранить сообщения после выпуска (воскрешение старого состояния при горячей перезагрузке схем); класть в очередь не склеенные фрагменты (реассемблирование остаётся на `CustomPacketReassembler`, очередь хранит готовые сообщения).

### A8-М2 «Классы из датасета» (9.05)
- **Назначение.** Один источник правды о классах: перечень, имена (мужское и женское), токен `ChrClasses.Filename`, цвет. Код не содержит чисел «десять/одиннадцать классов».
- **Форма.** `src/browser/ui/UnitSnapshot.ts`: `knownClassIds()`, `className(classId, female?)`, `classFileName(classId)`, `classColor(classId)`, `learnCreationNames(races, classes)` (принимает `nameFemale`/`nameMale`); данные — `/dbc/character-creation?v=4` (gateway `CharacterCreation.ts`) и `CLASS_COLOR_DATA`/`CLASS_SORT_ORDER_DATA` из `src/generated/classIcons.ts` (генерируются `tools/generate-class-icons.mjs` из `Constants.lua` датасета). Число классов на стороне Lua — глобал `MAX_CLASSES` / `MAX_RAID_CLASS_BUTTONS`, читается из VM.
- **Как применять.** Нужен перебор классов — `knownClassIds()`; нужна принадлежность к классу по маске — `1 << (classId - 1)` без верхней границы (id < 32); нужен цвет — `classColor`; нужен женский вариант — `className(id, true)`. Компилированные таблицы `CLASS_NAMES`/`CLASS_FILE_NAMES`/`CLASS_COLORS` — только запасные значения.
- **Файлы.** `UnitSnapshot.ts`, `FrameXmlMechanics.ts`, `TalentClient.ts`, `FrameXmlTalentResolver.ts`, `FrameXmlRaidLod.ts`, `CharacterCreation.ts` (gateway), `GlueNames.ts`, `FrameXmlCharacterStats.ts`, `generate-class-icons.mjs`, `client-data.mjs`.
- **Тесты.** `framexml-mechanics-seam`, `framexml-mechanics-vertical`, `framexml-talent-resolver`, `framexml-raid-grid-lod`, `gateway`, новый `class-colors`.
- **Типичные ошибки.** Забыть заглушку в `tools/client-data.mjs` (фасад не соберётся в чистой копии); не поднять версию `?v=` (кеш `max-age=3600` отдаёт старый ответ без женских имён); принять `ClassTrainerSkill1..11` и окна чата ≤ 10 за перебор классов (это не классы); округлять цвет `floor` вместо `round` (не совпадёт с компилированной таблицей).

### A8-М3 «Офлайн-проверка аддонов» (9.07)
- **Назначение.** Загрузка и поведение аддонов доказываются без клиента, сервера и игры: настоящая цепочка MPQ + каталоги `Interface/AddOns` + `FrameXmlBoot` на `CannedWorldSeam` + транспорт-заглушка пакетов.
- **Форма.** `tools/check-tswow-addons.mjs`: `TSWOW_ADDON_SCENARIOS[<модуль>]({ boot, packets, entrypoints, command, visible, sent })`, `checkTswowAddons`, `TswowAddonTestTransport`, `doublePacket`, новый `luaProbe(boot, expression)`. `tools/check-client-addons.mjs`: `CLIENT_ADDONS_FILE`, новый `CLIENT_ADDONS_INCLUDE_DISABLED=1`. `src/gateway/ClientAddons.ts`: `discoverClientAddons(root, { addonsFile?, includeDisabled? })`, `disabledByProfile`.
- **Как применять.** Новый модуль с аддоном: добавить ключ с именем модуля в `TSWOW_ADDON_SCENARIOS` (сценарий открывает окно/команду, проверяет отправленный опкод и принятый ответ); модуль без сценария роняет проверку (строка 188). Добавлять сценарий можно раньше сборки модуля — он не запускается, пока модуля нет в TOC. Отключённый в `AddOns.txt` клиентский аддон проверять переключателем `CLIENT_ADDONS_INCLUDE_DISABLED=1`, а не правкой профиля владельца.
- **Файлы.** `tools/check-tswow-addons.mjs`, `tools/check-client-addons.mjs`, `tools/tswow-patch-contract.mjs`, `src/gateway/ClientAddons.ts`.
- **Тесты.** `tests/client-addons.test.mjs`, новый `tests/tswow-minimap-hub-host.test.mjs` (компиляция модуля в памяти и прогон сценария в настоящем хосте FrameXML).
- **Типичные ошибки.** Считать число путей загрузки числом каталогов (отключённые профилем и каталоги `Blizzard_*` без `.toc` не считаются); править `WTF/…/AddOns.txt` клиента владельца ради проверки; ждать публикации модуля, чтобы написать сценарий.

### A8-М4 «SavedVariables: область, ключ, выход» (9.06)
- **Назначение.** Данные аддонов переживают перезапуск и не привязаны к адресу gateway; выход из игры (закрытие страницы) выглядит для Lua как обычный `PLAYER_LOGOUT`.
- **Форма.** `FrameXmlSavedVariablesScope { account, realm (только имя realm), character, legacyRealm? }`; ключ v2 `["webclient-addon-v2", ACCOUNT, realm, character|null, module, name]`; миграция v1 → v2 в `restore`; `SAVED_VARIABLE_LIMITS`; `FrameXmlBoot.fireLogoutOnce()`; `onProblem` → строка состояния мира.
- **Как применять.** Новое место, закрывающее Lua-мир (выгрузка, смена персонажа), вызывает `close()` (он шлёт событие через защёлку); периодические и «скрытые» сохранения `PLAYER_LOGOUT` не шлют никогда.
- **Файлы.** `FrameXmlSavedVariables.ts`, `FrameXmlBoot.ts`, `FrameXmlWorldMount.ts`, `EnterWorld.ts`.
- **Тесты.** `tests/framexml-saved-variables.test.mjs`, `tests/framexml-world-mount-lifecycle.test.mjs`.
- **Типичные ошибки.** Слать `PLAYER_LOGOUT` на `visibilitychange`/таймере (AceDB снимет метатаблицы и умолчания с живых данных); слать его на `beforeunload` (закрытие можно отменить); читать таблицу через `lua_gettable` вместо `lua_next`/`lua_rawget` (сработают метаметоды).

### A8-М5 «Двойник окна и Lua» (9.08)
- **Назначение.** Один экран студии — одно окно: JSON-окно молчит, пока Lua-аддон подписан на тот же опкод.
- **Форма.** `FrameXmlClientNetworkBridge.opcodes()` и `onChange`; `FrameXmlBoot.clientNetworkOpcodes()`; `ModuleLoader.noteLuaOpcodes(set)`, `ModuleLoader.suppressed`.
- **Файлы.** `FrameXmlClientNetwork.ts`, `FrameXmlBoot.ts`, `FrameXmlWorldMount.ts` (одна строка), `ModuleLoader.ts`.
- **Тесты.** `tests/module-loader.test.mjs`, `tests/framexml-socket-vertical.test.mjs`, новый `tests/framexml-json-lua-twin.test.mjs`.
- **Типичные ошибки.** Записывать снятие окна в `problems` (строка состояния станет красной); стирать `#sha`-ключ при снятии (окно будет перезагружаться каждые две секунды); снимать по имени вместо опкода (имена студии проходят транслитерацию).

### 9.02 — Аддоны TSWoW включены по умолчанию (после решения 0.4b)
- **Подход.** Пункт заблокирован решением владельца 0.4b; ниже — что делать при ответе «да». Код — переворот одного умолчания плюс **не сохраняемый в настройках переопределитель `?tswowaddons=0|1`** (по образцу `?framexml=`), чтобы стенд и замеры имели детерминированный способ выключить аддоны, не трогая сохранённую настройку игрока. Порядок выпуска важнее самого переворота: включать по умолчанию только **после** 9.03 (очередь входа), 9.06 (SavedVariables) и 9.08 (дубль окон) — иначе новые игроки сразу упрутся в потерянные сообщения при входе, не сохраняемые переменные AceDB и двойные окна студии.
- **Сверено.**
  - `src/browser/ui/SettingsModel.ts` 272-275: `id: "tswowAddons"`, `fallback: false`, подсказка «Lua-аддоны и пользовательские окна TSWoW. После изменения заново войдите в мир или обновите страницу.»; `defaultSettings()` (417-421) берёт `fallback`; `serialiseSettings` (469-476) пишет **только отличия от умолчаний**; `parseSettings` (452-466) недостающие ключи заполняет текущим умолчанием.
  - `src/browser/app/EnterWorld.ts` 213-215: `const tswowAddonsEnabled = settingOn("tswowAddons");` с комментарием «Both loaders stay idle by default for addon-free comparison runs» — вот «ради замеров». Значение берётся **в начале входа** из локального зеркала настроек (`AccountStore`, `mirrorKey: "webclient.settings.v1"`, `ui/Settings.ts` 33-39); серверная копия приходит позже, на `settingsStore.attach(world)` (≈1315), и `tswowAddonsEnabled` уже не пересматривается — на чистом браузере первый вход идёт по умолчанию, даже если на сервере у игрока сохранено «выключено».
  - Потребители флага: `createModuleLoader` + `modules.load()` (≈1207-1229), `FrameXmlModeController(tswowAddonsEnabled, …)` (≈1325), `mountFrameXmlVertical({ includeActiveTsAddons })` (≈1334), сообщение «Аддоны TSWoW отключены…» (≈1324). `FrameXmlWorldMount.ts` при `addonsOnly` грузит **тот же FrameXML-корпус**, что и полный режим (`FRAMEXML_VERTICAL_TOC`, 3414), рисует лишь кадры аддонов (`renderer.mount(options.addonsOnly ? boot.roots.filter(…))`, 3644) и запускает **собственный rAF-шаг** (3779-3805: `syncNativeAnchors`, `seam.tick`, `boot.bridge.tick`, `flushDeferredPaint`, `tickCooldowns`, `models.frame`).
  - Тесты, закрепляющие старое: `tests/framexml-tsaddon-contract.test.mjs` 34-36 (`defaultSettings().tswowAddons === false`, «a pre-existing settings blob starts with addons disabled»); `tests/framexml-world-mount-lifecycle.test.mjs` 429 (регулярка `const tswowAddonsEnabled = settingOn\("tswowAddons"\);`), 431-433, 438 (не менять форму `if (tswowAddonsEnabled) { const modules = createModuleLoader…`). `tests/comparison-profile.test.mjs` 34-36 требует, чтобы профиль сравнения графики **не трогал** `tswowAddons` — не меняется. `FrameXmlSettingsCVar.ts` 116 (`tswowAddons: { noDefault: true }`) и `tests/framexml-settings-cvar.test.mjs` 90 не зависят от умолчания.

### 9.03 — Сообщения модулей при входе: очередь 0x102 до готовности потребителей
- **Подход.** Не «доставлять после регистрации схем», а держать **общую FIFO-очередь целых сообщений** в `CustomPacketRegistry` с момента входа и выпустить её **одним проходом по порядку прихода** после того, как все заявленные потребители сообщили о готовности (`modules` — загрузчик JSON-окон, `lua` — Lua-аддоны TSWoW) или истёк запасной таймер. Доставка идёт через уже существующий `deliver()`, поэтому схемы, `latest()`, счётчики и raw-подписчики Lua работают без изменений. Очередь общая, а не «по опкодам»: порядок между опкодами одного модуля (состояние → дельта) сохраняется. Никаких повторов «по мере заявки» и водяных знаков на обработчик: такой повтор вызвал бы Lua-колбэк прямо внутри `OnCustomPacket(...)` (мост подписывается синхронно из вызова аддона, `FrameXmlClientNetwork.ts` `#subscribe`, `activateCallbacks` во время загрузки TOC), то есть до конца инициализации самого аддона; в реальном клиенте так не бывает.
  - Что теряется сейчас (два разных окна): (а) пакеты из `#deferred` (прочитаны в `#waitFor` до `SMSG_LOGIN_VERIFY_WORLD`) — `#dispatch` при `!#worldEntered` пишет 0x102 в `#recordUnhandled(packet, true)` **даже если обработчик уже зарегистрирован**, и до реассемблирования дело не доходит; (б) пакеты после `#worldEntered = true`, пока нет потребителя: `deliver` возвращает `false`, остаются лишь до 4 образцов по ≤256 байт в hex (`SAMPLE_LIMIT`, `SAMPLE_BYTES`) — для повтора непригодно. Потребители появляются поздно: схемы после `fetch('/modules/index')` и файлов (`ModuleLoader.#round`), Lua — в конце `enterWorld` через `FrameXmlModeController` → `mountFrameXmlVertical` → `boot.load()` (≈3,2–3,5 с по `docs/TSWOW_ADDON_LOADING_FIXES.ru.md`, на слабой машине больше).
  - Что модули реально шлют в `OnLogin` (сверено по исходникам): **ничего сразу** — вся установка построена на рукопожатии «клиент готов», потому что в реальном клиенте такое сообщение тоже теряется. Поэтому сегодня пункт **не меняет ни один видимый экран**: он страхует модули без рукопожатия, студийные экраны и серверные push'и по таймеру в первые секунды. Очередь — осознанное отступление от эталона «в лучшую сторону»; она ограничена по числу, объёму и времени.

- **Риски и открытые вопросы.**
  - Общая очередь задерживает **живые** сообщения на время загрузки Lua (до ~3–8 с, максимум 30 с). - **Подход.** Экран студии — это два артефакта из одного описания: JSON `content/ui/<id>.json` (его рисует `ModuleLoader` как окно DOM) и сгенерированный Lua-аддон (`addon/generated/ui/<Имя>.ts` → `create<Имя>`, `server/codegen/addon.mjs:3-4, 87-89, 526`). У экрана с пакетами обе стороны ссылаются на **одну пару опкодов** `packets {opcodeIn, opcodeOut}`: Lua пишет `OnCustomPacket(OP_<ИМЯ>_STATE = opcodeIn)` и `CreateCustomPacket(OP_<ИМЯ>_REQUEST = opcodeOut)` (`addon.mjs:1159-1182`), JSON читает те же числа (`WindowSchema.ts` `WindowPackets` 740-744, `parsePackets` 1816-1822; вложенные `messages` — `CustomMessage.opcode`). Студия сама требует, чтобы опкоды были уникальны на весь сервер (`addon.mjs:1164, 1186`; реестр отказывает во втором `define`), поэтому **опкод — надёжный признак «тот же экран»**, имена сопоставлять не нужно. Правило: если Lua-аддон уже подписан на опкод, которым пользуется JSON-окно, окно **не показывается** (побеждает Lua). Причина выбора: Lua-экран нельзя чисто отключить (он создаёт кадры, слэш-команду и события при загрузке TOC), а JSON-окно — запись реестра, которую можно не регистрировать или снять. Если Lua не загрузился или аддона нет в TOC, JSON-окно остаётся запасным.
