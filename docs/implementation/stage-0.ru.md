### 0.3 — Правила тестов в коде, а не только в handoff
- **Подход.**
  - Новый `tools/run-tests.mjs` — единая точка запуска тестов:
    - ставит `NODE_OPTIONS=--max-old-space-size=4096` дочерним процессам: лимит кучи превращает прежний «уход» в 101/131 ГБ в быстрое падение одного файла;
    - передаёт `--test-concurrency` (по умолчанию 1 для списка файлов, 4 для полного прогона) и `--test-timeout=240000`;
    - по ключу `--watchdog` раз в 2 с опрашивает `Win32_Process` и останавливает только процессы `node.exe` с `register-test-sources` или `--test` в командной строке и рабочим набором > 6 ГБ; процессы консоли TSWoW, gateway и Vite не трогает;
    - в конце печатает пик памяти.
  - `package.json`: `test` → `npm run build && node tools/run-tests.mjs --dist`; `test:source` → `node tools/run-tests.mjs --source --concurrency=4 --watchdog`; новый `test:file` → `node tools/run-tests.mjs --source <files…>`.
  - В `AGENTS.md` WebClient — одна строка правила: «тесты — через `npm run test:file`; полный прогон один и только оркестратором».
- **Сверено.** В `tools/` сторожа нет (Grep по `watchdog|guard|WorkingSet` — только несвязанные файлы). Прошлый «встроенный guard 6 ГБ» из handoff §6 был разовым скриптом. `npm test` сейчас запускает `node --test` с параллелизмом по умолчанию (≈19 на 20 потоках).
- **Правило для сторожа.** Опрос процессов — лёгким запросом, без перечисления модулей чужих процессов (глобальное правило машины). `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` с `CommandLine` и `WorkingSetSize` подходит; `Process.MainModule` запрещён.
- **Тесты.** `tests/run-tests-wrapper.test.mjs` (новый): разбор аргументов, сборка окружения (NODE_OPTIONS добавляется, а не затирает), фильтр сторожа — процесс Vite, gateway и консоли TSWoW по командной строке не выбирается. Мутация: убрать фильтр `register-test-sources|--test` → тест падает.
- **Размер и файлы.** S; `tools/run-tests.mjs` (новый), `package.json`, `AGENTS.md`.
