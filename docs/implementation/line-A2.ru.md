## Общие механизмы

Линия A2 владеет тремя механизмами: **М5** (событие штатного UI из мира), **М6** (стоковый файл в вертикальный TOC), **М8** (модель боевых событий). Чужие: М1–М3 (A3), М4 (A1), М7 (A9). Ссылки вида `file:line (функция)`; номера строк плавают, имя функции надёжнее. Пробы и их выводы лежат рядом: `probe-unbound.mjs` (+`*.out.txt`) — какие вызываемые глобалы нового стокового файла не привязаны; `probe-macro-conditions.mjs` — слова условий макросов из `Wow.exe` 12340.

### М5 «Событие штатного UI из мира»

**Назначение.** Довести факт мира (пакет, поле объекта, локальное состояние клиента) до стокового Lua как событие с теми же именем, порядком и аргументами, что у оригинального клиента. Стоковый обработчик после события читает состояние обратно через C API (`Get*`/`Unit*`), поэтому событие — это «ребро», а состояние уже лежит в мире.

**Форма (что есть в коде).**
- Источники. `WorldClient.events` — типизированная шина `EventBus<WorldPacketEvents>` (`world/EventBus.ts`: интерфейсы `WorldEvents` :198 и `WorldPacketEvents` :234; `on()` возвращает отписку; ошибка слушателя изолируется `onListenerError`). Поля объектов — `WorldStore` (`store.field(SELF, "PLAYER_XP", cb)`, `fieldRange`, `object(guid, cb)`, `any(cb)` — сглаженное «что-то изменилось за флаш», `store.events`). Одиночные слоты `world.onX = …` — наследие native (`EnterWorld.ts`); стоковый шов их не занимает, кроме двух исключений с цепочкой (`LiveWorldSeam.attach`: `onGroupChanged`, `onTrainerChanged`).
- Приёмник. `FrameXmlSeamPump.fire(event, ...args)` (`FrameXmlWorldSeam.ts:157`) → `FrameXmlBoot.pump.fire` (`FrameXmlBoot.ts:1266`) → `bridge.runInDeferrableBatch(() => bridge.dispatchEvent(...))` → `FrameXmlUiBridge.dispatchEvent` (`ui/framexml_compat/FrameXmlRuntime.ts:2075`: обходит копию списка `#byEvent.get(name)` и вызывает `OnEvent(self, event, ...args)`; возвращает число сработавших обработчиков). `fire` вернул 0 — никто не слушает.
- Имена. `FRAMEXML_SEAM_EVENTS` (`FrameXmlWorldSeam.ts:1056`) — только то, что стреляет сам `LiveWorldSeam`. Семейство со своей моделью держит свои константы (`FRAMEXML_HUD_MECHANICS_EVENTS` в `FrameXmlHudMechanicsLive.ts:58`, `FRAMEXML_POPUPS_EVENTS`). Новое имя событию даёт модуль семейства.
- Жизненный цикл. `LiveWorldSeam.attach(pump)` (`:1287`) вызывает `<model>.attach(pump)` каждой модели и кладёт отписки в `#unsubscribe`; `detach()` (`:2130`) их снимает; `tick(now)` раз в кадр, опрос производных состояний каждые `LIVE_POLL_SECONDS` (60 мс). Эталон семейства: `FrameXmlHudMechanics.ts` (контракт и таблица привязок) + `FrameXmlHudMechanicsLive.ts` (события мира → `pump.fire`) + `FrameXmlHudMechanicsCanned.ts` (сценарный офлайн-мир).

**Применение (шаги).**
1. Стоковый обработчик: `Grep RegisterEvent("X")` в стоковый Lua клиента (через gateway `/client/file`), прочитать ветку `OnEvent`, выписать кортеж аргументов и какие C API читает та же ветка. Тип аргумента — часть контракта: `ChatFrame.lua:730` делает `strlower(rank)` — `rank` обязан быть строкой (`""`), а не nil.
2. Источник в мире. Нет события шины — добавить запись в `WorldPacketEvents` и один `this.events.emit(...)` в обработчике пакета (`WorldClient.ts`, `#handleSpellLog` и соседи). Полезная нагрузка — разобранные факты пакета, не готовые слова. Слот `onX` не добавлять.
3. Модель семейства: `FrameXml<Семейство>Live.ts` с `attach(pump)`/`detach()`. Подписки — в массив отписок. На `attach` сеять подписи (сигнатуры) без стрельбы, чтобы первый опрос молчал.
4. Порядок: сначала обновить состояние, потом стрелять; события одного пакета — в порядке оригинала (в спецификации пункта). «Ребро, не уровень»: событие только при смене формы (`#barSignature`, `#zoneShapeKnown` — образец: `#reconcileZone`, `LiveWorldSeam.ts:2426`).
5. Дедупликация: (а) сигнатура формы на производное состояние; (б) один `store.any` на флаш; (в) для касты — личность держать с START, потому что `world.casts` стирает запись до STOP (`#castStates`, `:852`); (г) не стрелять из `attach`, кроме «посевных» рёбер, которые стоковый кадр получил бы при входе (первое `ZONE_CHANGED_NEW_AREA`, `#reconcileZone` `first`).
6. Аргументы «по стоку»: имя события точно как в `RegisterEvent`; токены юнитов строчные и только те, что смотрят стоковые кадры (`#castUnit`, `:5529`, иначе `undefined` → события нет); числа — числа, «нет значения» — nil (`optional()`), не `""`.
7. Офлайн-двойник: `CannedWorldSeam` получает то же событие сценарием (`pump.fire` из теста), иначе вертикальный тест не увидит ветку.
8. Тест шва: `tests/framexml-<семейство>-seam.test.mjs` по образцу `tests/framexml-hud-mechanics-seam.test.mjs:15-84` (`FakeEvents` вместо шины, фальшивый `world`, `pump = { fire, now }` собирает `fired[]`, `LiveWorldSeam` с `world: () => world`). Утверждение: `fired` равен `[[event, ...args], …]` по порядку.
9. Типичные ошибки: событие раньше состояния; подписка через слот `onX`; забытая отписка в `detach` (утечка после `/reload`); неверный токен юнита; лишние события при `AURA_UPDATE_ALL`/входе в мир; тип аргумента (nil против `""`).

**Файлы.** `FrameXmlWorldSeam.ts` (интерфейс шва, привязки), `LiveWorldSeam.ts`, `CannedWorldSeam.ts`, `world/EventBus.ts`, `world/WorldClient.ts`, модуль семейства.

**Какие события стреляет шов сейчас (для сверки пунктов).** `UNIT_SPELLCAST_START/STOP/FAILED/INTERRUPTED/DELAYED/CHANNEL_START/UPDATE/STOP` — есть (`LiveWorldSeam.ts:1918-1982`, `castStates`); `UNIT_COMBAT` — есть (`FrameXmlHudMechanicsLive`); `ZONE_CHANGED*` — есть (`#reconcileZone`); нет: `PLAYER_LOGIN`, `UNIT_SPELLCAST_SENT/SUCCEEDED/FAILED_QUIET/(NOT_)INTERRUPTIBLE`, `COMBAT_LOG_EVENT(_UNFILTERED)`, `RUNE_POWER_UPDATE`, `RUNE_TYPE_UPDATE`, `UPDATE_INVENTORY_ALERTS/DURABILITY`, `UPDATE_MULTI_CAST_ACTIONBAR`, `AUTOFOLLOW_BEGIN/END`.

### М6 «Стоковый файл в вертикальный TOC»

**Назначение.** Добавить файл стокового FrameXML в `FRAMEXML_VERTICAL_TOC` так, чтобы он загрузился без ошибок Lua, ничего не сломал в других режимах и был доказан тестом на настоящем MPQ.

**Форма.**
- Список: `FRAMEXML_VERTICAL_TOC` (`FrameXmlCorpus.ts:451`, порядок — как в стоковом `FrameXML.toc`; номера строк стока лежат в `Interface/FrameXML/FrameXML.toc` (через gateway `/client/file`)). Подмножество превращается в синтетический TOC (`subsetTocProvider` :683; `subsetWithActiveTsAddonsTocProvider` :757 добавляет блоки TSWoW из победившего TOC). Загрузчик сам разрешает `Script`/`Include` относительно файла.
- Заглушки. `FrameXmlStubPlan` строит план по тексту загружаемых файлов: любая вызываемая, но нигде не определённая глобальная функция становится записывающим no-op, который **ничего не возвращает**. Файл, у которого дальнейший код зависит от возвращаемого значения, упадёт позже и не там.
- Видимые корни. Родителя-`UIParent` рендерер ведёт сам. Виден корень без `parent` — обязан быть в `FRAMEXML_WORLD_VISIBLE_ROOT_NAMES` (`FrameXmlWorldMount.ts:293`, `selectFrameXmlWorldRoots` :358; скрытые корни монтируются всегда).
- Режимы. `mountFrameXmlVertical` грузит один и тот же `subset: FRAMEXML_VERTICAL_TOC` и в режиме `addonsOnly` (`FrameXmlWorldMount.ts:3414`; включается при `!frameXmlEnabled`, `EnterWorld.ts:1333`), а показывает там только кадры аддонов (`FrameXmlTsAddonPresentation.includes`). Каждый добавленный файл платит время и память загрузки и в нативном режиме.
- LoD-вариант: `boot.loadAddon(NAME)` → `renderer.addRoots(result.roots)` → `renderer.sync()` → структурный вход (gate) → публикация владельца; при неудаче остаётся native. Образцы: `FrameXmlRaidLod.ts`, `FrameXmlArenaLod.ts`, `FrameXmlMacroBindingLod.ts`; общий загрузчик `FrameXmlAddonRuntime.ts`.

**Применение (шаги).**
1. Место в TOC — по стоковому порядку (шрифты и шаблоны раньше, зависящие файлы позже). Комментарий у записи с замером «+файлов, +байт, +виджетов, 0 новых ошибок Lua», как у соседей.
2. Зависимости: `node .runtime/node/node.exe A2/probe-unbound.mjs <Файл.lua|xml…>`. «ABSENT» — вызывается и нигде не упомянуто в `src` (точно не привязано: нужен М4 или нейтральный ответ); «mentioned» — проверить вручную, что привязка отвечает нужным числом и типом значений. Считать также глобалы, которые файл **читает** при загрузке (`RuneFrame`, `VehicleSeatIndicator`): их отсутствие — nil-вызов позже.
3. Проверить, что файл нужен в `addonsOnly`: если нет — внести в будущий список `FRAMEXML_ADDONS_ONLY_SKIP` (фильтр на месте `subset:` `FrameXmlWorldMount.ts:3414`). Файл, который стоковый код вызывает безусловно (`RuneFrame:SetScale` в `UnitFrame.lua:69`), пропускать нельзя.
4. Native-дубль: если нативный интерфейс рисует то же, скрывающий селектор (`NATIVE_*_HIDE_SELECTOR`, `ui/NativeHudReplacement.ts`) публикуется только после структурного входа; нет входа — нет скрытия.
5. Отказ: gate вернул `undefined` → native остаётся; причина показывается игроку (пункт 3.24), не только `console.warn`.
6. Тесты: (а) MPQ-вертикаль `tests/framexml-<x>-vertical.test.mjs` — `FrameXmlBoot` + `FRAMEXML_VERTICAL_TOC` + `CannedWorldSeam` + `tools/mpq.mjs` над `F:\Circle` (образец: `framexml-hud-mechanics-vertical.test.mjs`): кадры существуют, число ошибок Lua не выросло, событие даёт видимое состояние; (б) обновить пороги размеров в `tests/framexml-vertical-slice.test.mjs`/`framexml-seam-inventory-gate.test.mjs`; (в) поправить комментарий `FrameXmlCorpus.ts:416-421` («два исключения» — на деле 28).
7. Мутации: убрать запись из TOC (кадр nil); сломать C API (растёт число ошибок); переставить запись раньше зависимости.
8. Ловушки: порядок; файл, который читает глобал до его определения; `toplevel`/страта над HUD; часы `GetTime` (сейчас `Date.now`, см. 3.27) — тесты анимаций затухания требуют управляемых часов.

**Файлы.** `FrameXmlCorpus.ts`, `FrameXmlWorldMount.ts` (корни, режимы, гейты), модуль привязок семейства, `tests/framexml-<x>-vertical.test.mjs`.

### М8 «Модель боевых событий»

**Назначение.** Один поток боевых фактов из пакетов, из которого получаются: `COMBAT_LOG_EVENT_UNFILTERED` и `COMBAT_LOG_EVENT` с аргументами 3.3.5 (для `Blizzard_CombatLog`, MSBT, любых аддонов), `UNIT_SPELLCAST_*` (пункт 3.02) и всплывающие числа. Строки чата вне плана.

**Состояние сейчас (сверено).**
- Пакеты уже разобраны и стреляют события шины `UNIT_COMBAT` (`world/UnitCombat.ts`: melee, spellDamage, heal, energize, periodic, miss, damageShield, immune, resist), `COMBAT_LOG` (текст; урон, лечение, instakill, dispel/steal), `FLOATING_TEXT`, `PARTY_KILL`, `SPELL_GO`, `SPELL_CAST_START/STOP/DELAYED`, `AURA_CHANGED` (`WorldClient.ts:6559-6660`, `:8360`, `:5653-5690`, `:6788`). В Lua доходит только `UNIT_COMBAT` (стоковая обратная связь портретов, `combatFeedbackOf`).
- Не идут через шину: `SMSG_ENVIRONMENTAL_DAMAGE_LOG` (одиночный слот `onEnvironmentalDamage`, `WorldClient.ts:8377`, слушает `EnterWorld.ts:495`), `SMSG_SPELLLOGEXECUTE` (`:6654`, читается только заголовок `parseExecuteLog`, `SpellLogProtocol.ts:268`), `SMSG_ENCHANTMENTLOG` (`:6658`, разобран и выброшен), `SMSG_SPELLINSTAKILLLOG`/dispel/steal — только текст.
- Причины неудачи каста теряются: `SPELL_CAST_STOP` не несёт `result` (`EventBus.ts:246`), `SMSG_CAST_FAILED` сообщает только текст (`WorldClient.ts:5721`).
- `SpellMetadata` (`gateway/SpellMetadata.ts:126`) не содержит маски школы, класса урона и флагов прерывания; для `spellSchool` пакеты урона школу несут, пакеты лечения/аур/каста — нет.
- В стоке констант `COMBATLOG_OBJECT_*` и `COMBATLOG_FILTER_*` определяет `Constants.lua:249-330`, то есть они уже в корпусе.

**Форма (что построить).**
1. `src/world/CombatEventModel.ts` — чистый модуль: `CombatFact` (объединение фактов пакетов) и `combatLogEntriesOf(fact, resolve) → CombatLogEntry[]`, где `CombatLogEntry = { subevent, source: Unit, dest: Unit, args: unknown[] }`. Таблица подсобытий и аргументов — ниже. Никакого DOM, никаких слов: только числа и токены.
2. `src/world/CombatStream.ts` — `emitCombat(events, fact)`: одна запись шины `COMBAT_FACT` (новая запись `WorldPacketEvents`) рядом с существующими `UNIT_COMBAT`/`COMBAT_LOG`/`FLOATING_TEXT`. Существующие эмиты не трогать в первом срезе; в последнем срезе они переводятся на производные от потока с тестом «старые выходы не изменились».
3. `src/browser/framexml/FrameXmlCombatLog.ts` — контракт `FrameXmlCombatLogModel` + кольцевой буфер + привязки C API (`CombatLogGetNumEntries`, `CombatLogSetCurrentEntry`, `CombatLogGetCurrentEntry`, `CombatLogAdvanceEntry`, `CombatLogResetFilter`, `CombatLogAddFilter`; для полноты `CombatLogClearEntries`, `CombatLogGetRetentionTime`, `CombatLogSetRetentionTime`). `FRAMEXML_COMBAT_LOG_BINDINGS` — в `FRAMEXML_SEAM_BINDINGS` перед `FRAMEXML_CURSOR_BINDINGS`.
4. `FrameXmlCombatLogLive.ts` — подписка на `COMBAT_FACT`, имена и флаги юнитов, отметка времени, пуш в буфер, `pump.fire("COMBAT_LOG_EVENT_UNFILTERED", …)` для всех и `pump.fire("COMBAT_LOG_EVENT", …)` для прошедших фильтр. **Ленивое включение**: пока никто не подписан на оба события (новый метод `FrameXmlUiBridge.eventListenerCount(name)` над `#byEvent`), нормализация не выполняется.
5. `FrameXmlCombatLogOwner.ts` — LoD-владелец `Blizzard_CombatLog` (М6, LoD-вариант): загрузка после `PLAYER_LOGIN`, усыновление `ChatFrame2`, выключение зеркала native-строк (`combatWindowEnabled`, `FrameXmlChatApi.ts:930` — иначе каждая боевая строка печатается дважды).

**Отметка времени и GUID.** `timestamp` — `Date.now()/1000` (эпоха, секунды с дробью): `Blizzard_CombatLog.lua:3305` подаёт её в `date()`, MSBT сравнивает разности (`MSBTParser.lua:400`). GUID — `frameXmlGuid(guid)` (`FrameXmlWorldSeam.ts:867`, «0x» и 16 цифр), тот же формат, что у `UnitGUID` (MSBT сравнивает строки). Нулевой GUID источника — `"0x0000000000000000"` (константа `GUID_NONE` в `MSBTParser.lua:54`), имя nil, флаги `COMBATLOG_OBJECT_NONE` (`0x80000000`, `Constants.lua:284`).

**Флаги юнита (`sourceFlags`/`destFlags`, значения `Constants.lua:249-285`).**
- Тип: по старшим 16 битам GUID (`HighGuid`: игрок 0x0000, объект 0xF110, юнит 0xF130, питомец 0xF140, техника 0xF150) и полям объекта. Игрок → `TYPE_PLAYER`; питомец 0xF140 → `TYPE_PET`; юнит с `UNIT_FIELD_SUMMONEDBY`/`CREATEDBY` = игрок → `TYPE_GUARDIAN`; иначе `TYPE_NPC`; объект и тотем → `TYPE_OBJECT`.
- Управление: игрок → `CONTROL_PLAYER`; юнит с `UNIT_FLAG_PLAYER_CONTROLLED` (0x8, `UnitDefines.h:138`) → `CONTROL_PLAYER`, иначе `CONTROL_NPC`.
- Принадлежность: сам игрок и его питомец/страж/тотем → `AFFILIATION_MINE`; в группе (`frameXmlGroupHas`) → `PARTY`; в рейде (`frameXmlRaidIndex`) → `RAID`; иначе `OUTSIDER`.
- Реакция: резолвер фракций шва (`LiveWorldSeamContext.reaction`, `unitIsFriend`): дружелюбный/нейтральный/враждебный.
- Особые (не исключающие): `TARGET`, `FOCUS` (0x10000, 0x20000), `MAINTANK`/`MAINASSIST` (флаги участника группы — значения сверить с `Group.h`), метка рейда n → `0x00100000 << n` (`world.raidTargets`).

`missType` — строки `ABSORB BLOCK DEFLECT DODGE EVADE IMMUNE MISS PARRY REFLECT RESIST` по `SpellMissInfo` (1 MISS … 11 REFLECT; таблица `MISS_ACTIONS`, `FrameXmlCombatFeedback.ts:46`). `auraType` — `BUFF`/`DEBUFF` по флагам ауры (`AURA_FLAGS.negative` 0x80, `AuraProtocol.ts`). `powerType` — 0..6 (`FRAMEXML_POWER_TOKENS`).

**Формат `SMSG_SPELLLOGEXECUTE` (сверено с ядром).** `Spell.cpp:4720-4750` (`SendLogExecute`): packed GUID кастера, `u32` заклинание, `u32` число эффектов; на эффект `u32` номер эффекта, `u32` счётчик целей (`InitEffectExecuteData`, `Spell.cpp:8273`), затем записи по типу эффекта (`Spell.cpp:4755-4815`): 8 и 62 — packed GUID, `u32` отобрано, `u32` тип силы, `f32` множитель; 19 — packed GUID, `u32` число атак; 68 — packed GUID, `u32` прерванное заклинание; 111 — packed GUID, `i32` предмет, `i32` слот; 33 — packed GUID объекта; 24 — `u32` предмет; 101 — `u32` предмет-еда; 102 и все призывы и воскрешения — packed GUID.

**Порядок событий одного факта.** В порядке прихода пакетов: `SPELL_CAST_START` → `SPELL_CAST_SUCCESS` (GO) → лог урона/лечения → `SPELL_AURA_APPLIED`. Первое `AURA_UPDATE_ALL` по GUID — тихая база без событий; на один урон в две школы — по одному `*_DAMAGE` на школу [гип.].

### 3.27 — Lua VM (fengari 5.3 + шимы 5.1): утечка ссылок `SetScript`/`HookScript`, `OnUpdate` без хуков, `next` без O(n²), `strsplit`, монотонный `GetTime`, `setfenv`/`newproxy`
- **Подход.** Шесть независимых правок S по одному тесту; порядок по пользе: часы → `strsplit` → `next` → ссылки → `OnUpdate`. Каждая проверена по коду.
- **Сверено.**
  - **Утечка ссылок.** `glue/GlueWidgets.ts:2091-2113`: `SetScript` вызывает `this.#vm.retain(handler)` на каждое присваивание и передаёт обёртку в `bridge.SetScript`; предыдущий обработчик кадра (его удерживаемая Lua-ссылка) нигде не освобождается. `bridge.SetScript` (`ui/framexml_compat/FrameXmlRuntime.ts:2408-2421`) заменяет `mutable.scripts` и ничего не возвращает; `HookScript` (:2429-2438) только дописывает в `scriptHooks`, удаления хука нет. Стоковый `UIFrameFade` переставляет `OnUpdate` на каждое наведение на чат (аудит §4.4) — темп утечки высокий.
  - **`OnUpdate` без хуков.** `SetScript` (:2416-2419): при `handler === null` для `OnUpdate` кадр удаляется из `#updateFrames`, хотя `scriptHooks.get("OnUpdate")` может быть непуст; `HookScript` (:2436) добавляет кадр в `#updateFrames`, но снятие обработчика его выкидывает и хуки перестают вызываться (в оригинале `SetScript("OnUpdate", nil)` снимает только основной обработчик).
  - **`next`.** `glue/GlueLua.ts:250-275`: `next(t, key)` при каждом вызове считает `_arrayLength(t)` циклом `while rawget(t, n+1) ~= nil` — O(n) на шаг, O(n²) на обход. `pairs` (:280+) считает длину один раз и не затронут.
  - **`strsplit`.** `GlueLua.ts:210-222`: `string.find(text, delimiter, start, true)` — разделитель ищется как подстрока; оригинал `strsplit(delimiter, str [, pieces])` разбивает по **любому** символу набора (`strsplit(",;", "a,b;c")` → `"a","b","c"`); параметр `limit` считается неверно для набора.
  - **`GetTime`.** `FrameXmlBoot.ts:1389` `Date.now() / 1000` и `pump.now` (`:1284`) — стеночное, немонотонное время; шов конвертирует монотонное время мира в `GetTime` через `pump.now()` (`LiveWorldSeam.ts:7397`, `FrameXmlHudMechanicsLive.ts:216`, …), поэтому менять надо оба выражения одновременно. Затухание (`FadingFrame`, 3.05) и все анимации читают `GetTime`.
  - **`setfenv`/`newproxy`.** `newproxy` в подготовке возвращает таблицу (`FrameXmlBoot.ts`, шим из `FRAMEXML_ADDED_SHIMS`), `setfenv` нет (аудит §4.4). Стоковый `SecureHandlers.lua` использует `newproxy`: `local newproxy = newproxy` (`:14`), `newproxy(true)` для прототипа управляемого дескриптора (`:52`), `newproxy(proto)` для каждого дескриптора (`:82`), `newproxy()` для `MAGIC_UNWRAP` (`:236`) — то есть `SecureHandler…Template` сторонних аддонов работают на дескрипторах, чья метатаблица общая и изменяемая, а `type()` даёт `"userdata"`; на таблицах из шима это не воспроизводится. `setfenv` в стоке и в аддонах этой установки не вызывается (`Grep` по стоковый Lua клиента (через gateway `/client/file`) и `tsaddons`: только `SecureHandlers.lua` и только `newproxy`).
- **Изменения.**
  1. Часы. Ввести `frameXmlClock(): () => number` (`FrameXmlBoot.ts`): `(performance.timeOrigin + performance.now()) / 1000` (монотонно, величина как у `Date.now()/1000`), опция `FrameXmlBootOptions.clock` для тестов; `GetTime` (`:1389`), `pump.now` (`:1284`), `tickSeam` (`:1289`) и все остальные места `Date.now() / 1000` в `framexml/` (найти `Grep`'ом) берут её. Замена не должна менять величину (аддоны хранят `GetTime()` относительно себя).
  2. `strsplit` (`GlueLua.ts:210-222`): разбор по набору символов (`for` по байтам/символам `delimiter`), `pieces` ограничивает число частей, остаток последней части не режется; пустой разделитель → возвращает строку целиком.
  3. `next` (`GlueLua.ts:250-275`): длину массива брать `rawlen(t)` (O(log n) у границы массива fengari) вместо цикла; порядок обхода сохранить. Проверить `pairs` (не менять).
  4. Ссылки: `bridge.SetScript` возвращает предыдущий обработчик; `GlueWidgets.SetScript` находит по нему удерживаемую ссылку в `#handlerSources` и вызывает `#vm.release(ref)`; для `null` — тоже. `HookScript` — учёт числа хуков на кадр с предупреждением при превышении порога (например 64) в диагностике; разовый `UnhookScript` не нужен (нет в 3.3.5).
  5. `OnUpdate`: в `SetScript` при `handler === null` удалять кадр из `#updateFrames` только если `scriptHooks.get("OnUpdate")` пуст.
  6. `setfenv`/`newproxy`: по потребности (пункт плана так и говорит); критерий начала — первый аддон, регистрирующий `Secure*HandlerTemplate`, или первая ошибка `setfenv` в `frameXmlWorld().errors`. ### 3.28 — Гейт сумок: прокси `InterfaceOptionsFrame` не должен обнулять настоящий фрейм при снятии владельца
- **Подход.** Снимать глобал только если он всё ещё указывает на кадр-заместитель, который поставил гейт. Дефект проверен по коду: механизм существует, срабатывание зависит от порядка событий (вживую не наблюдался).
- **Сверено.** `FrameXmlWorldMount.ts` `frameXmlBagGate` (≈860-960): `aliases` для отсутствующих `InterfaceOptionsFrame` и `BankFrame` (:878-885) и `lifetimeAliases` (:892-898, добавляют `MerchantFrame`, `StackSplitFrame`) — один скрытый безымянный кадр `proxy()` (:868-877). Глобалы ставятся на время пробы (`withBagGlobals`, :904-916) и на всё время жизни владельца (:946-957: `boot.vm.setGlobal(alias[0], alias[1])`), а `clearGlobals(installed)` (:899-903) безусловно пишет `setGlobal(name, undefined)`. Цепочка опций (`FRAMEXML_OPTIONS_TOC`, `FrameXmlCorpus.ts:665`) загружается **лениво при первом открытии** «Изображение/Звук/Интерфейс» (`FrameXmlOptionsOwner.ts`) — то есть настоящий `InterfaceOptionsFrame.xml` заменяет глобал-прокси уже после установки. Если затем владелец сумок снимается (демоция `demotePublishedBags`, ошибка гейта, `/reload`-очистка), `releaseLifetimeGlobals` → `clearGlobals` уничтожает **настоящий** глобал; следующий вызов стокового кода (`IsOptionFrameOpen()` в `ContainerFrame`/`StackSplit`) падает на nil.
- **Изменения.**
  1. `FrameXmlWorldMount.ts` `clearGlobals` (:899-903): для каждой пары `[name, frame]` читать `boot.vm.getGlobal(name)` и снимать, только если значение равно этому кадру (или недоступно для сравнения — тогда не трогать); вынести в экспортируемую чистую функцию `releaseOwnedGlobals(vm, installed)` (`FrameXmlBagCompat.ts`, рядом с прочими помощниками сумок) для теста.
  2. Ленивый загрузчик опций (`FrameXmlOptionsOwner.ts`) при установке настоящих глобалов пишет их безусловно поверх прокси — так и должно быть (оригинал побеждает); записать в комментарии, что владельцы прокси обязаны это терпеть.
  3. То же правило для `withBagGlobals` (:904-916): после операции не обнулять глобал, ставший чужим (настоящим) во время операции.
- **Тесты.** `tests/framexml-bag-lifetime-globals.test.mjs` (новый; фальшивый `vm` с `getGlobal/setGlobal`): (а) прокси поставлен, глобал не менялся → снят; (б) прокси поставлен, затем `setGlobal("InterfaceOptionsFrame", real)`, затем снятие владельца → `real` остался; (в) то же для `BankFrame`; порядок снятия обратный. Мутации: вернуть безусловное обнуление — (б) падает; сравнивать по имени вместо ссылки — (б) падает. Дополнить `tests/framexml-bag-mount.test.mjs`: реальная цепочка — смонтировать сумки, лениво загрузить опции, размонтировать сумки, `InterfaceOptionsFrame` существует.
- **Офлайн-проверка.** `framexml.html?toc=vertical`: открыть настройки («Интерфейс»), затем закрыть/пересоздать сумки — `IsOptionFrameOpen()` не падает; проба `frameXmlWorld().boot.vm.getGlobal("InterfaceOptionsFrame")` не nil.
- **Живая проверка.** → 14.12 (банк и сумки) и 14.20 (ошибки и повторное открытие окон): открыть настройки, затем `/reload` без потери сумок; ошибок Lua нет.
- **Зависимости.** Нет. Пересекается по файлу с 3.24 (`FrameXmlWorldMount.ts`) — вести в одном срезе или последовательно.
- **Риски.** Сравнение ссылок Lua-объекта через мост: `getGlobal` возвращает то же удерживаемое значение? — проверить в тесте на фальшивом `vm`, а в живом коде — на настоящем `GlueLuaVm` (тест `tests/framexml-bag-mount.test.mjs`).

### 9.01 — Режим «интерфейс WebClient + аддоны TSWoW» (`addonsOnly`): StaticPopup и UIErrorsFrame должны рисоваться
- **Подход.** Не менять смысл `addonsOnly` («нативный HUD, поверх него только кадры модулей TSWoW»): показывать ровно те штатные диалоги и сообщения, которые **создают сами аддоны**, а серверные подтверждения оставить native. Три правки: (1) фильтр показа включает `StaticPopup1..4` и `UIErrorsFrame`; (2) ветка `addonsOnly` до возврата ставит адаптеры диалогов и Escape; (3) `UIErrorsFrame` отписывается от событий мира, чтобы native-уведомления не дублировались. Дефект подтверждён по коду (статически) и по трём реальным потребителям в модулях.
- **Сверено.**
