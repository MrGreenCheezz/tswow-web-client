### A7-M1 «Стоячая база позы» (пункты 6.03, 6.04, частично 6.07)

- **Назначение.** То, что юнит делает, стоя на месте без пакетной позы: `Stand`, emote-состояние NPC (`UNIT_NPC_EMOTESTATE`), боевая стойка (`Ready*`), сидение/колени/сон, скрытность. Оригинал делает это подменой стойки, а не разовой анимацией: при движении играет ход, после остановки стойка возвращается сама. Очередь арбитра для этого не годится (`unitActionEndsOnMovement` для held-emote стирает запись безвозвратно).
- **Форма.** `UnitPose` (`AnimatedModel.ts`, ≈1661) получает необязательные `emoteState?: number` (уже разрешённый `AnimationData.ID` из `EMOTE_ANIMATIONS`, только для `state: true`), `ready?: WeaponPose`. Чистая функция `standingAnimations(pose): number[]` — лестница для ветки «не движется, standState = STAND, не верхом, не в воде/полёте»: `emoteState` → `[emote, Stand]`; иначе `ready` → `readyAnimation(ready)`; иначе `stealth ? StealthStand… : [Stand]`. `poseAnimation` вызывает её в ветке `default:` переключателя `standState` (≈2028-2034). Новая чистая `isBaseIdle(pose): boolean` — «база стоит»: `!moving && !mounted && !swimming && !flying && standState ∈ {STAND} && !stealth`, **независимо** от emote/ready. `#settleUnitAction` берёт `baseIdle = isBaseIdle(pose)` вместо `poseAnimation(pose).wanted[0] === Stand`.
- **Применение.** (1) `#animateUnit` (`WorldRenderer3D.ts` ≈12835-12868) заполняет `pose.emoteState` из `unitFields.emoteState(object)` и `pose.ready` из `UNIT_FIELD_FLAGS & UNIT_FLAG_IN_COMBAT` (0x00080000, константа уже экспортируется `world/FactionRules.js`) и `weaponPose(...)`; (2) `#poseBase` уже вызывает `#requestAnimations(template, poseAnimation(pose).wanted, …)` — сайдкар запросится сам; пока клипа нет, `chooseAnimation` возвращает `Stand`. (3) арбитр не меняется: `unitActionDisplay(layer, upperBody, baseIdle)` получает `baseIdle` из `isBaseIdle`.
- **Файлы.** `AnimatedModel.ts` ⚑, `WorldRenderer3D.ts` ⚑ (две строки в `#animateUnit`, одна в `#settleUnitAction`), поле в `world/` рядом с `unitFields.standState`. **Согласовать с параллельной сессией** (это её файлы и её `baseIdle`).
- **Тесты.** `animation.test.mjs` (лестница, `isBaseIdle` для каждого состояния), executor-тест арбитра: замах поверх стойки играет `full`, возвращается в стойку. Ошибка типична: оставить `baseIdle` по `wanted[0] === Stand` — тогда любой NPC с emote-состоянием или в бою получает удар только «верхней половиной» или вовсе без удара.

### A7-M2 «Снаряжение NPC» (6.01, 6.02, 6.04, 6.06, зеркальный образ 6.11)

- **Назначение.** У NPC два источника предметов: `CreatureDisplayInfoExtra.NPCItemDisplay` (одежда + шлем + наплечники, постоянная для дисплея → живёт в метаданных дисплея) и `UNIT_VIRTUAL_ITEM_SLOT_ID` (три слова, **Item entry**, не display: `Unit::SetVirtualItem` `Unit.cpp:14932`, `Creature::LoadEquipment` `Creature.cpp:1977`, TSWoW `Creature::SetOutfit` `Creature.cpp:352-368`; отличается у каждого существа с этим дисплеем → живёт на объекте).
- **Форма.** Шлем и наплечники — `appearance.attached` из шлюза (`forNpc`). Оружие — новый маршрут `GET /dbc/npc-weapons?v=1&items=slot:invType:displayId[:subClass],…` → `AttachedModel[]` (только слоты 15–17, без расы), клиент `CreatureModelClient.npcWeapons(key)` с той же кэш-/backoff-схемой, что `playerAppearance`; слияние в `ui/Frames.ts` `unitModelFor` (ветка `typeId !== 4`) через `UnitModel.held?: AttachedModel[]`; `#updateAttachments` (≈12557) и `#entryAnimation` (≈13381) читают `attachedOf(metadata) = [...appearance.attached, ...held]`. Поле `held` (а не вложение в `appearance`) нужно потому, что у не-персонажных моделей (огры, мурлоки-с-копьями) `appearance` не существует.
- **Пошагово.** `virtualEquipmentFor(object, itemMetadata)` (слова 0/1/2 → слоты 15/16/17, `itemMetadata.load`, пропуск неразрешённых, `virtualEquipmentPendingFor` — как `visibleEquipmentFor*` в `ui/Frames.ts` 225-267) → ключ → `npcWeapons` → мемо на `WorldObjectState` (WeakMap как `resolvedPlayerModels`, ключ включает `itemMetadata.generation` и слова). Овеществлённый `sheath` берётся из `UNIT_FIELD_BYTES_2` (у существ по умолчанию MELEE: `Creature.cpp:654-656` (без аддона; с аддоном — его `sheathState`, `:2861`), значит оружие в руке).
- **Тесты.** `tests/npc-equipment.test.mjs`: слова → слоты, слияние, `weaponPose` над слитым списком, дисплей со шлемом (dataset). **Типичные ошибки:** читать слова как display-id (это entry предметов); класть оружие в `appearance` (ломается на моделях без `appearance`); забыть, что `subClass` приходит с задержкой (INVTYPE 26 — и ружья, и жезлы: `visibleEquipmentMetadataPendingFor` уже знает это для слота 17).

### A7-M3 «Боевые таблицы по данным» (6.04, 6.06)

- **Назначение.** Соответствие «оружие → анимации» в клиенте — данные, а не списки в коде: `ItemSubClass.WeaponParrySeq/WeaponReadySeq/WeaponAttackSeq/WeaponSwingSize` (20 строк класса 2), `AttackAnimKits` (26 строк: ID, ItemSubclass, AttackAnimType, флаги, признак левой руки) и `AttackAnimTypes` (7 названий: 1H_Main_Swing, 1H_Main_Pierce, 2HL_Pierce, 2HL_Swing, 2HT_Swing, OffH_Swing, OffH_Pierce). Типы `AttackAnimTypes` совпадают с именами `Attack1H` 17, `Attack1HPierce` 85, `Attack2HLoosePierce` 86, `Attack2HL` 19, `Attack2H` 18, `AttackOff` 87, `AttackOffPierce` 88 (ID проверены по `AnimationData`).
- **Форма.** М2-маршрут `/dbc/weapon-anims` (A3): `{ subclasses: { [sub]: {parry, ready, attack, swing} }, kits: [{sub, type, flags, offhand}], types: {id: name} }` ≈ 3 КБ; браузер `WeaponAnimations.ts` (чистый): `weaponAnimationSet(sub)`, `attackAnimations(sub, hand, roll)`, `readyAnimations(sub)`, `parryAnimation(sub)`; при отсутствии данных — прежние списки из `actionAnimation`/`readyAnimation`. ### A7-M5 «Хозяин эмиттеров» (6.14, 6.15)

- **Назначение.** Сегодня эмиттеры собираются только для `unit.wvm` тела (`WorldRenderer3D.ts` ≈8194-8207) — у навесных предметов и маунта частиц нет; ту же дыру закрывает свечение оружия (6.14).
- **Форма.** Запись списка `wanted` (`{ key, wvm, distance, posed, visual? }`) получает варианты `posed`: `mount` (узел `unit.mount.node`, костяная поза маунта), `attached` (жёсткий меш из `unit.attached`, эмиттеры в модельном пространстве предмета, кости = единичные), `glow` (эффект зачарования на точке крепления оружия). Ключ `unit:${guid}:mount`, `unit:${guid}:att:${slot}/${side}`, `unit:${guid}:glow:${slot}:${i}`; зачистка ключей — как для `unit.effectKey` (`#dropEffects`). Ранжирование и бюджет уже есть (`EFFECT_RANGE_SQUARED`, отдельный бюджет визуалов) — новые записи идут в общий список.
- **Стоимость.** Мерить: число активных эмиттеров и мс на кадр в сцене «город, 200 NPC» и «Даларан, 40 светящихся клинков» до/после; лимит `EMITTER_CAPACITY = 256` (`Particles.ts` ≈90) не трогать.
