## Общие механизмы

Линия A10 владеет шестью механизмами (М-A10-1…М-A10-6). Механизмы М1–М8 других линий здесь не нужны; из соседних используются политика кеша `CachePolicy` (A6/10.12) и лестница повторов `RetryLadder` (М-A7b-2). Все числа — замеры чтением (без запуска генераторов, сборок и gateway); пробы и их выводы лежат рядом в этой папке.

### М-A10-1 «Реестр задач сборщика» (`10.20`; используют `10.22`, `7.23`)
- **Назначение.** Одно место, где сказано, какие виды задач умеет постоянный сборщик, в каком модуле лежит функция и к какому «классу длины» (процессу) она относится; вместо ветки `switch` на каждое семейство и вместо копий в `pregenerate` и тестах.
- **Форма.** `tools/asset-jobs.mjs`: `ASSET_JOBS[kind] = { family: "texture" | "model" | "tile", load: () => import("./generate-….mjs"), run(module, job, archives) }`; виды: `texture`, `visual-model`, `item-icon`, `spell-icon`, `creature-icon`, `terrain-splat`, `visual-tile`, `horizon`, `minimap-index`, `zone-map`, `liquid`, `client-file`, `tile-models`. Сторона gateway: `src/gateway/AssetWorkers.ts` (`createAssetWorkers({ env, cwd, track })` → `{ run(family, job, priority), recycle(), close() }`, разбор `ASSET_WORKERS` = `0` | пусто/`1` | список семейств) и `AssetWorker.run(job, priority)` с очередью по приоритету (в ребёнка — по одной задаче). Ответ сборщика: `{ id, ok, missing?, message?, rss, result? }`.
- **Применение (новое семейство).** (1) вынести из верхнеуровневого скрипта `export async function publishX(args…, archives)` и оставить запуск из командной строки под `if (process.argv[1] === import.meta…)`; (2) каталоги вывода читать **при вызове**, а не при импорте (как `textureDirectory()`); (3) на «источника нет» бросать `SourceMissing` (`tools/source-missing.mjs`) — единственное, что gateway превратит в 404; (4) добавить запись в `ASSET_JOBS` и вид в `AssetWorkerJob`; (5) в `GatewayConfiguration.ts` заменить `runAssetGenerator(...)` вызовом `workers.run(family, job, priority)`; (6) тест байтов «процесс против сборщика» в `tests/generators-bytes.test.mjs`.
- **Файлы.** `tools/asset-jobs.mjs`, `tools/asset-worker.mjs`, `tools/source-missing.mjs`, `src/gateway/AssetWorker.ts`, `AssetWorkers.ts`, `GatewayConfiguration.ts`.
- **Тесты.** `tests/asset-jobs.test.mjs` (реестр = union типа), `tests/asset-worker.test.mjs` (порядок, `recycle`, `close`), `tests/generators-bytes.test.mjs`.
- **Типичные ошибки.** Класть длинную задачу (тайл, городская WMO) в процесс короткой — приоритет в gateway не спасёт: внутри процесса FIFO; читать каталог по env на верхнем уровне модуля (сборщик живёт долго, тест подменяет env на процесс); держать DBC в памяти сборщика без ключа «путь + размер + mtime» (после `build data` — устаревшие иконки); бросать обычный `Error` на «нет в клиенте» (500 вместо 404 — браузер повторит три раза); импортировать `three` на старте сборщика тайлов (грузить лениво внутри `publishVisualTile`).

### М-A10-2 «Файловый валидатор» (`10.21`; стыкуется с `CachePolicy` из A6/10.12)
- **Назначение.** Ответить 304 без чтения и без хеша файла: ETag берётся из `stat`.
- **Форма.** `src/gateway/FileResponse.ts`: `fileEtag(stats) = "e1-<size hex>-<mtimeNs hex>[-<ino hex>]"` (сильный; `stat` с `bigint: true`), `matchesEtag(header, etag)` (слабое сравнение: без `W/`, `*` совпадает), `respondFile(request, response, filename, { origin, contentType, headers, open? })`.
- **Применение.** Порядок: `ensureCurrent` → `stat` → `If-None-Match` совпал → 304 без чтения → иначе поток файла с `content-length`. Базовые заголовки (`cache-control` и др.) даёт вызывающий: сегодня литерал, после A6/10.12 — `cacheHeaders("dataset", { etag })`.
- **Файлы.** `FileResponse.ts`, `Gateway.ts` (шесть вызовов `respondRevalidated` и `/visual/texture/<sha1>.png`).
- **Тесты.** `tests/file-response.test.mjs`; правка одного регулярного выражения в `tests/gateway.test.mjs` (форма тега).
- **Типичные ошибки.** Включить в тег штамп `.src` (переподпись `restamp` меняет штамп без смены байтов — 304 пропадает); забыть `ino` (замена файла через переименование при равных размере и mtime даёт тот же тег); сравнивать без снятия `W/` (прокси со сжатием делает тег слабым — ответ 200 вместо 304 навсегда); считать SHA-1 «для надёжности» на 304.

### М-A10-3 «Линия генерации с продвижением и тихим окном» (`10.20` срез 0; `10.22`)
- **Назначение.** Фоновая работа (предзагрузка) не должна стоять перед запросом игрока ни в очереди, ни в процессоре.
- **Форма.** `src/gateway/GenerationLane.ts` (вынесено из `Gateway.ts`): к существующему (`generationLane`, `laneRun`, `generateOnce`, приоритет по числу) добавляются `key` у ждущей записи, `promote(lane, key, priority)`, `laneStats(lane)` (`requests`, `cold`, `waitMs`, `runMs`, время последней реальной задачи), `PRELOAD_PRIORITY = -1`, предикат «линия свободна и тихо» (`!running && waiting.length === 0 && now − lastReal ≥ 250 мс`).
- **Применение.** Фоновая задача: `generateOnce(lane, key, run, PRELOAD_PRIORITY)` только если предикат истинен; реальный запрос на тот же ключ вызывает `promote` (его `generateOnce` присоединяется к ждущей задаче и повышает её). Запущенную задачу не прервать — поэтому предикат, а не «отмена».
- **Файлы.** `GenerationLane.ts`, `AssetPreloader.ts`, `Gateway.ts` (реэкспорт `SOURCE_MISSING_EXIT`, `sourceMissing`, `texturePriority`).
- **Тесты.** `tests/gateway-generation-lanes.test.mjs` (`promote`, `laneStats`), `tests/asset-preloader.test.mjs`.
- **Типичные ошибки.** Присоединить реальный запрос к ждущей предзагрузке без повышения (игрок ждёт с приоритетом −1); проверять «тишину» по своей линии, а не по всем (реальный запрос пришёл на соседнюю линию, а сборщик у них общий); забыть, что ошибка предзагрузки попадает в память отказов (`GENERATION_RETRY_TTL_MS`, 1,5 с; «нет в клиенте» — 5 мин) и отдаётся реальному запросу.

### М-A10-4 «Метка отсутствия» (`7.23`; годится для любого семейства, где «результата нет» постоянно для данных входов)
- **Назначение.** Не запускать генератор второй раз для входа, про который уже известно, что результата не будет, и пережить перезапуск gateway.
- **Форма.** Пустой файл `<ключ>.<суффикс>` (для сплата — `<x>-<y>.nosplat`) со штампом тех же источников, что у настоящей записи (`writeSourceStamp`); маршрут: `ensureCurrent(метка)` (устаревшую удаляет) → `stat(метка)` → 404; генератор: вердикт `none` → метка + `SourceMissing` (код 3).
- **Тесты.** `tests/terrain-splat-stub.test.mjs` (метка переживает `startGateway`, устаревшая удаляется).
- **Типичные ошибки.** Метка без штампа (никогда не сгорает, тайл после правки ADT остаётся «пустым»); 404 без метки (каждый перезапуск gateway — заново запуск генератора); ответ 200 с пустой записью (клиент должен различать «пусто» и «ошибка формата»).

### М-A10-5 «Журнал решений и чтение клиента» (`6.21`)
- **Назначение.** Решение, принятое без парного кадра, записано тестом с адресом доказательства; проверка по коду клиента воспроизводима.
- **Форма.** `tests/animation-decisions.test.mjs`: по одному утверждению на решение, в комментарии — способ проверки (адрес в `Wow.exe.clean`, таблица, проба). Чтение клиента: `A10/x86lite.mjs` (разбор PE, декодер 32-битного x86 для линейного просмотра) и пробы `probe-exe-xref.mjs` (строка или адрес → места использования → листинг), `probe-exe-window.mjs` (окно вокруг адреса, строка по адресу), `probe-exe-callers.mjs` (кто вызывает функцию, где хранится адрес), `probe-exe-kit-users.mjs`, `probe-exe-bodyflags.mjs`.
- **Порядок чтения.** Строка (имя таблицы, сообщение об ошибке) → ссылка на неё → функция → поля записи (смещения из `tools/dbd/*.dbd`) → сравнения и переходы. Таблицы клиента находятся по массиву указателей записей: глобальные `min id`, `max id`, `rows` лежат рядом (SpellVisualKit: `0xad4a4c/0xad4a48/0xad4a5c`, AnimationData: `0xad4a04/0xad4a00/0xad4a14`).
- **Типичные ошибки.** Считать вывод декодера истиной без проверки границ функций и целей вызовов; путать файловые смещения и адреса (база 0x400000, секции — `parsePe`); принимать «клиент делает X, когда бит установлен» за «клиент рисует X на верхней части тела» (это разные утверждения — см. 6.21).

### М-A10-6 «Бюджет запросов окружения» (`10.21` (в))
- **Назначение.** Один потолок одновременных запросов окружения (модели, группы WMO, сайдкары анимаций) вместо трёх независимых счётчиков, чтобы четыре из шести соединений браузера оставались гарантированно свободными для текстур слоёв юнитов.
- **Форма.** `src/browser/EnvironmentRequestBudget.ts` (чистый): `tryAcquire(kind, priority)` → освобождающая функция или отказ; предел по умолчанию 4, `critical` может занять один запас сверх предела; `fetch(..., { priority: "low" | auto })` по классу запроса.
- **Применение.** Три `#drain*` в `Terrain.ts` спрашивают бюджет перед запуском загрузки и освобождают в `.finally`; очередь по приоритетам и `MODEL_BACKGROUND_RESERVATION_MS` не меняются.
- **Тесты.** `tests/environment-request-budget.test.mjs`, `tests/terrain-request-cap.test.mjs` (максимум одновременных `fetch`).
- **Типичные ошибки.** Считать только модели (группы и анимации дают ещё до шести запросов); поднять предел «для скорости» (холодные сборки на gateway последовательны, лишний параллелизм только занимает сокеты); не отдавать слот при отмене загрузки (утечка бюджета).

  1. **id 0 в SpellVisualKit = нет позы — ЗАКРЫТО по коду клиента.** В `Wow.exe.clean` (база 0x400000) кит читается по массиву записей `0xad4a5c` (диапазон id `0xad4a4c…0xad4a48`; его выдаёт функция, пишущая `SPELLVISUALKITIDNOTFOUND|%d`, va 0x704b30). Три функции, читающие `StartAnimID` (+4) и `AnimID` (+8), сравнивают их **знаково с нулём**: va 0x7fa3a4 `cmp [kit+4],0 / jg play / cmp [kit+8],0 / jle skip` (запуск кита на юните: играть, если хотя бы одно поле > 0); va 0x80a077 и 0x73b24c `cmp [kit+8],0 / jle`. То есть 0 и −1 в клиенте — одно и то же «позы нет», а наш `kitNamesPose(animation) { return animation > 0; }` (`SpellVisuals.ts`) совпадает с нативным предикатом побитно. Данные: из 8 664 китов пару «(−1, 0)» имеют 317, «(0, −1)» 56, «(0, >0)» 28, «(0, 0)» 10 — 411 китов (4,7 %) называют 0; их держат 178 StateKit, 89 ImpactKit, 61 CastKit, 44 ChannelKit; 217 заклинаний имеют StateKit с одним лишь нулём. Практический довод (`A10/probe-621-data.out.txt`): будь 0 позой Stand, 178 строк SpellVisual (217 заклинаний) со StateKit «только 0» держали бы юнит в полнотелом Stand всю ауру (слой `state` в арбитре держит тело даже при беге). Оговорка: путь **отмены** (va 0x7fec68) проверяет `!= 0`, то есть срабатывает и для −1; он вызывает `SetAnimation(0, −1)` (va 0x73ac30: «вернуть анимацию по состоянию») и без активной позы ничего не меняет — в арбитре это `remove` записи, которой не было.
  2. **Бит 0x8 Bodyflags — ЧАСТИЧНО.** (а) *Данные*: 129 из 506 строк `AnimationData` несут 0x8 — реакции (StandWound, CombatWound/Critical, Dodge, Parry*, ShieldBlock), все Attack*, SpellPrecast/SpellCast*/ReadySpellOmni, жесты (Talk, Wave, Laugh, Rude, Point, Salute, Shout, Applaud, Chicken, Eat…) и их Fly-двойники; без 0x8 — вся ходьба/бег/плавание (0x1/0x41/0x141), Ready*-стойки (0x100), полнотелые эмоции (Dance, Kneel, Roar, Bow, Cry, Kiss, Flex, Beg, Shy — 0x100), Special*/Kick/Whirlwind (0x120), сон/смерть (0x300/0x500/0x900). Перекрёстная таблица `Emotes.dbc` (`probe-621-emotes.out.txt`) даёт ту же картину: жестовые one-shot эмоции — 0x8, «полнотелые» — нет (исключения: ONESHOT_CHEER 0x100, ONESHOT_CUSTOMSPELL* 0x0). (б) *Структура M2* (`probe-621-data.out.txt`, 33 риг-модели игроков): клипы с 0x8 ключуют ноги в 100 % и двигают их в 92,8 %, клипы без 0x8 — 99,6 % и 91,3 %. Значит клипы нарисованы полнотелыми, а разбиение на верх/низ — правило времени выполнения; из ключей бит не выводится. (в) *Код клиента*: бит 0x8 проверяется у **текущей анимации юнита** (id из байта данных +0x1d3, его отдаёт метод 0x71af70; тот же id ставит `SetAnimation` 0x73ac30) в двух местах — va 0x6da1cf (метод, внутри которого проверка играет через `Player_C.h`; адрес 0x6da130 передан обратным вызовом при регистрации вместе с числом 0x1d3 в va 0x6e5383 и 0x6e5b97 — тем же смещением, которое читает метод 0x71af70) и va 0x6ddbea (функция 0x6ddbb0, вызывается из 0x71b38b). Запись таблицы: `AnimationData` — массив `0xad4a14`, диапазон `0xad4a04…0xad4a00`, поле +0xC. В обоих случаях, когда бит **сброшен**, код сбрасывает спелл-анимацию юнита (0x518d50 → `SetAnimation(0,−1)`, либо 0x726ce0), когда **установлен** — оставляет её играть. Итог: клиент сам считает «0x8» признаком позы, которая переживает событие сброса, — это подтверждает половину решения (0x8 ⇒ пережить); **не доказано**: какое именно событие срабатывает (переход стойки/движение — байт +0x1d3 не сопоставлен полю UpdateFields), и что переживающая поза рисуется именно на верхней части тела, а ноги берут ход (из этих функций не видно; слой смешения костей лежит в коде M2, не разобран).

- **(а) Подход и сверено.**
  - `respondRevalidated` (`Gateway.ts`, в конце файла) сначала читает **весь** файл, затем SHA-1 всего тела: 304 на `HumanMale.anim.bin` (9 833 124 Б) — 8,8 мс (план). В памяти-телах (`/dbc/lfg-dungeons`, `declined-words`, `achievements`) SHA-1 считается один раз на датасет — их не трогаем.
  - Валидатор: `"e1-<size hex>-<mtimeNs hex>-<ino hex>"` — сильный, из `fs.stat(filename, { bigint: true })`; `ino` (когда не 0) ловит замену через `writeFileAtomic` (временный файл + переименование даёт новый идентификатор), которой пользуются все публикаторы; штамп `.src` **не входит**: `tools/restamp.mjs` переписывает только штамп, не меняя байтов, и штамп в теге лишил бы клиента 304 после переподписи. `e1` — соль схемы: смена схемы = смена соли.
