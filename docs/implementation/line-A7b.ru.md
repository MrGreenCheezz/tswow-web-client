### М-A7b-1 «Смена версии кеша тайлов» (и соседних кешей `data/`)

**Назначение.** Генератор в `tools/` меняет содержимое файла, а ключ кеша (путь, id) остаётся прежним; без смены «поколения» шлюз отдаёт старые файлы, браузер держит их в HTTP-кеше. Механизм один для всех правок формата в этой линии (7.02, 7.03, 7.06, 7.09, 7.11, 7.13, 7.14, 7.16, 7.19).

**Как устроено сейчас (сверено).**
- Штамп `<файл>.src` пишет `tools/source-stamp.mjs` (`stampGenerated`/`sourceStamp`): `generation` (необязательная строка), `chain` (состав архивов), `sources`, `files`. Сравнение — по сериализованной строке, поэтому смена `generation` делает файл устаревшим (`stampIsCurrent` → false; в шлюзе `fingerprint.ensureCurrent(filename, {generation})`), и **та же плитка перестраивается при следующем запросе** (`generateOnce(...Lane, ...)` — по одному процессу генератора на очередь).
- Тайлы окружения: `data/visual-tiles/<карта>/<x>-<y>.json`; поколение **`visual-tile-v4` записано в двух местах** — `tools/generate-visual-tile.mjs` (`stampGenerated(..., {generation})`) и `src/gateway/Gateway.ts` (маршрут `/visual/environment`, `fingerprint.ensureCurrent(filename, { generation: "visual-tile-v4" })`). Менять только вместе.
- Кеш наборов доодадов WMO: `data/visual-wmo-doodads/<sha1>.json`; ключ `wmo-doodad-light-v1\0<путь>` (хеш имени файла), `generation: "wmo-doodad-light-v1"` в штампе и `WMO_DOODAD_CACHE_VERSION = 1` в теле. Смена формы записи набора — менять все три.
- Артефакты WMO/M2: `data/visual-models/<sha1>.bin`; имя файла — хеш от **пространства имён** (`visualModelCacheNamespace` в `Gateway.ts`: сейчас `visual-v21` для M2 и `visual-wmo-v22` для WMO — параллельная сессия уже переходила v14→v17→v22). Смена пространства делает ВСЕ WMO-артефакты новыми файлами (старые остаются на диске мусором). Расширения артефакта WMO идут цепочкой секций WME1→WME2 (порталы)→WME3 (туман)→WME4 (комнаты доодадов) — новая секция (WME5) добавляется после WME4 через слово длины предыдущей, читатель без неё обязан работать (`decodeMetadata` в `WmoModel.ts`).
- Сплат рельефа: `data/terrain-textures/<карта>/<x>-<y>.{alpha.png,index.png,mccv.png,cover.bin,splat.json}`; **поколения нет**: `fingerprint.ensureCurrent(filename)` без параметров. Новое имя файла в семействе (как `cover.bin`) не требует версии — отсутствие файла и есть «ещё не опубликован»; правка существующего файла требует введения `generation` (в `sourceStamp` генератора и в `ensureCurrent` маршрута `/terrain-splat`).
- Слои земли `data/terrain-layers/<sha1>.png`, id = sha1(`terrain-layer-v1\0<путь>`): смена размера/фильтра слоя = новый префикс id (`terrain-layer-v2`), старые файлы не трогаются.
- Индекс миникарты `/minimap/<карта>/index.json`: `ensureCurrent` без поколения; правка формы требует `generation` + `?v=` в клиенте (`MinimapTiles.ts`, `#loadIndex`).
- Свет карты `/dbc/light/<карта>?v=4` (`LightClient.ts`, `#load`): версия только в запросе клиента; сервер держит индекс в памяти процесса (`indexes.lightIndex`) — новая форма ответа требует **перезапуска gateway** (решение владельца).

**Способ применения (по шагам).**
1. Определить, меняются ли **байты существующего файла** (тогда `generation`) или добавляется **новый файл/поле, которое старый читатель пропустит** (тогда версия не нужна, но новый читатель обязан переносить его отсутствие).
2. Поднять `generation` (или пространство имён, или `?v=`) **сразу в обоих концах** — генератор и маршрут; клиентский `fetch` дополнить `?v=<N>` (маршруты сопоставляют `url.pathname`, запрос игнорируют; HTTP-кеш `max-age=3600/86400` иначе держит старое до суток).
3. Клиент валидирует новые поля терпимо (`EnvironmentTileDecode.isEnvironmentObject`: неизвестное опциональное поле не должно ронять плитку; проверка полей — по объекту, см. 7.19).
4. Тест «версия на месте»: строковое утверждение в `tests/gateway.test.mjs`/новом тесте, что `generation` в генераторе и в `Gateway.ts` совпадают (регэкс по обоим файлам) — ловит забытый конец.
5. Перегенерация: ничего вручную; после **перезапуска gateway владельцем** плитки перестраиваются по запросу; прогрев города — заходом в город (`bench/lookdev.mjs` тянет недостающее с шлюза на `BENCH_GATEWAY_URL`). Стоимость измерить один раз: время `node tools/generate-visual-tile.mjs 0 32 48`-подобного вызова и число плиток в `data/visual-tiles` (сейчас 424).

**Файлы.** `tools/generate-visual-tile.mjs`, `tools/wmo-visual.mjs`, `tools/generate-terrain-splat.mjs`, `tools/generate-minimap-index.mjs`, `src/gateway/Gateway.ts` (маршруты `/visual/environment`, `/terrain-splat`, `/minimap`, `visualModelCacheNamespace`), клиенты `Terrain.ts` (`EnvironmentClient.#load`), `TerrainSplat.ts`, `MinimapTiles.ts`, `LightClient.ts`.

**Типичные ошибки.** Поднять поколение только в генераторе (маршрут не увидит устаревшего — плитки остаются старыми) или только в маршруте (бесконечная перегенерация: штамп никогда не совпадёт). Поднять пространство имён WMO ради одной правки, когда параллельная сессия делает то же — договориться об одном подъёме на пакет правок. Забыть, что порядок ординалов доодадов (`-(id*1e6 + ordinal + 1)`) — часть формата: смена состава набора (7.02) меняет ординалы, и таблицы комнат WME4 обязаны считаться той же функцией.

**Тесты.** `tests/gateway.test.mjs` (маршрут отвечает после смены), новый `tests/cache-generation.test.mjs` (строки `generation` совпадают в `tools/*.mjs` и `Gateway.ts`), `tests/environment-tile-decode.test.mjs` (новые поля).

### М-A7b-2 «Лестница повторов запроса»

**Назначение.** После сбоя запрос не повторяется до конца сессии: `LightClient.#load` пишет `null` в `#maps` (небо остаётся «полдень» и туман 180–640), `TerrainSplat.#load` пишет `null` в `#tiles`, `HorizonClient.#load` — `null` и `#errors.add` с комментарием «Null and never again». Единый помощник заменяет три копии.

**Форма.** Новый чистый модуль `src/browser/RetryLadder.ts`: `class RetryLadder<K>`; конструктор `(steps = IMAGE_RETRY_BACKOFF_MS, now = () => performance.now())`; `failed(key, permanent = false)`, `ready(key): boolean` (прошло `after`), `attempts(key)`, `exhausted(key)`, `clear(key)`, `retain(keys)` (забыть ключи вне активного набора). Шаги — **существующие** `IMAGE_RETRY_BACKOFF_MS = [2_000, 8_000, 30_000]` из `CharacterAtlas.ts` (так же считает `Terrain.ts#deferGroup`: `wait = steps[attempts-1]`, после лестницы — `failed`/`Infinity`).

**Применение.** (1) клиент при ответе 404 («карта без WDL/тайл без сплата») пишет **постоянное** отсутствие, при остальных сбоях — `ladder.failed(key)`; (2) `get()/sample()` возвращает `undefined` и, если `ladder.ready(key)`, запускает новый запрос; (3) успех — `ladder.clear(key)`; (4) на выходе тайла из активного набора запись забывается (`setActiveTiles`) — повторный вход даёт новую лестницу; (5) статистика (`stats.error`) считает только исчерпанные.

**Тесты.** `tests/retry-ladder.test.mjs` (новый; часы вводятся): 1-й сбой → `ready` через 2 с, 2-й → 8 с, 3-й → 30 с, 4-й → `exhausted`; постоянный 404 не повторяется; `retain` забывает; мутация: убрать `after` — повтор на каждом кадре (тест «за кадр — один запрос» падает).

**Типичные ошибки.** Повтор на каждый кадр (нет проверки `after`); повтор 404 (тайлы без сплата/карты без WDL — норма); утечка записей ушедших тайлов.

### М-A7b-3 «Офлайн-кадр lookdev и цена кадра»

**Назначение.** Для каждого визуального пункта нужен парный кадр «до/после» и таблица стоимости; оба берутся без серверов.

**Форма.** `node bench/lookdev.mjs --scenario city|movement --settings enhanced|<файл> --out bench/results/<имя> --frame имя=полминуты,yaw,pitch,orbit[,погода:сила][,@x/y]` (время в полуминутах суток 0–2880: полдень 1440, закат 2100; yaw 4.712 — на запад, 1.571 — на восток; `--population` ограничивает толпу; `--frames` — сколько кадров прогреть, для дождя ~300). Недостающие ресурсы подтягиваются с шлюза `BENCH_GATEWAY_URL` (по умолчанию 127.0.0.1:8090) и остаются в кеше стенда. Цена: `bench/run.mjs --scenario <city|movement|…>` даёт CPU-мс кадра (P-ядра), вызовы отрисовки, число программ и кучу; память GPU — `visitRetainedResources` (`worldRenderer.telemetry`).

**Применение к пункту.** Записать в спецификации: сцена, камера, время суток, погода, что должно измениться на кадре; до правки снять кадр и таблицу (мс/кадр, вызовы, программы, МБ), после — то же; порог приёмки — «не хуже +0,1 мс CPU и +0 программ» для правок без нового геометрического слоя, иначе явное число в пункте. Числа не оцениваются, а снимаются (правило «Measure before claiming»).

**Ограничения.** Кинематографичный путь (`--settings enhanced`) и контрольный профиль (`ComparisonProfile.ts`, 7.20) — разные кадры; пункт, меняющий базовый путь, снимается в обоих. Ночь и луна ранее не снимались (`docs/LOOKDEV.ru.md`, «Не проверено»).

**Типичные ошибки.** Сравнивать кадры разных прогревов (мало `--frames`), разных `--population`, разной погоды; мерить время на непрогретом кеше.

### М-A7b-4 «Эталон из клиентских шейдеров»

**Назначение.** Клиентские шейдеры лежат в MPQ как `Shaders\Pixel\arbfp1\*.bls`, `Shaders\Vertex\arbvp1\*.bls` — контейнер `HSXG` с **читаемым текстом ARB-ассемблера**. Это эталон формул для 7.06, 7.07, 7.09, 7.11 (то, что раньше брали из wowee/памяти).

**Способ.** `probe-bls.mjs`, `probe-bls2.mjs` в этой папке (читают MPQ через `tools/mpq.mjs`, печатают текст первой программы); выводы `probe-bls.out.txt`, `probe-bls2.out.txt`. Установленные факты: `terrain.bls` (вершинная): `лит = min(1, ambient + diffuse * clamp(N·L, 0, 1))`, выход ×0,5, фрагмент ×2 (`c[37] = {0,1,0.5}`, `MAX/MIN` вокруг `DP3 N, c[24]`); `terrain2.bls` (фрагментная): тень `= min(alphaMap.w, динамическая)`, альбедо × `(0.3·тень + 0.7)`, зеркальная часть × тень, итог `primary·albedo·2 + spec` (`c[12] = {0.2, 0.3, 0.7, 2}`); `psliquidmagma.bls`: `цвет = primary·tex0.rgb`, α=1; `psliquidwater.bls`: `primary·tex0 + tex1.rgb + tex1.a·(secondary+0.25)`.

**Ограничения.** Это программы для ARB-пути; константы `program.local[...]` задаёт код клиента (в `.bls` их значений нет), поэтому численные параметры (например, сила зеркального блика) берутся из таблиц (`LiquidType`) или калибруются кадром.

**Типичные ошибки.** Считать `.bls` из другой ветки (`nvfp2`, `ps_1_1`) — они упрощённые; в спецификациях ссылаться на `arbfp1`/`arbvp1`.

### 7.03 — Комнаты и доодады WMO дальше 60 ярдов: порталы снаружи ⚑
- **Что сделала параллельная сессия (текущее дерево, сверено).** Здания из одних комнат (`wmoInteriorOnly`, `WmoModel.ts`): при входе (`#enteredInteriorOnly`) комнаты выбираются обходом порталов с дальностью 400 (`INTERIOR_ONLY_RANGE = ENVIRONMENT_RANGE`, `#interiorOnlyRange`), прямоугольник видимости каждой комнаты сохраняется (`InteriorOnlyRooms.apertures`), доодады привязаны к комнатам по MODR (WME4, `INTERIOR_ONLY_DOODADS`, `interiorOnlyDoodadShown`, `wmoDoodadInAperture`), небо скрыто, свет пола (`wmoFloorLight`, `setWorldLightIndoor`), тесты `wmo-occlusion`, `wmo-render-path`. Снаружи такое здание сознательно держит короткий радиус комнат.
- **Что остаётся (сверено).** (1) `selectWmoPortalGroups` (`WmoOcclusion.ts`) начинает обход только от комнаты, в которой стоят камера или персонаж (`group.indoor && !group.exterior && contains(...)`); из открытого воздуха `used: false`, `#updateWmoGroups` зовёт его только при `this.#indoors || entered`. (2) `wmoGroupsInRange(..., roomRange = INTERIOR_RANGE = 60)`: комнаты дальше 60 ярдов не строятся, через дверь и окно на 80 ярдов виден пустой проём. (3) Все доодады WMO в плитке `interior: true` (`generate-visual-tile.mjs` `worldDoodad`): `environmentDrawRange` даёт им 60 ярдов, `environmentAdmissionTier` — квоту `interior` (360, расстояние ≤ 400): фасадные фонари, вывески и флаги исчезают на 60 ярдах, когда стены здания (`WMO_EXTERIOR_RANGE` 250, большие оболочки 750) ещё стоят. (4) Привязка доодадов к комнатам делается только в `#noteInteriorOnly`, то есть для «зашедших» зданий.
- **Подход (срезы; начинать после коммита параллельной сессии, п. 0.6).**
  - **Срез 1 — класс владельца доодада (генератор).** В `tools/wmo-visual.mjs` считать по MODR групп признак `indoorOwned` (есть владелец-группа с `WMO_GROUP_INDOOR`); в `worldDoodad` (`generate-visual-tile.mjs`) для доодадов, у которых **все** владельцы — наружные группы, выдавать `interior: false` (как у наружной мелочи: размерная дальность `environmentSceneryRange`, квота `scenery`, `admissionRadius` считается общим циклом). Замер до реализации (probe): доля таких доодадов у Штормграда, гостиницы Златоземья, Темнолесья. Версия плитки — общая с 7.02 (`visual-tile-v5`, М-A7b-1).
  - **Срез 2 — портал снаружи (`WmoOcclusion.ts`).** `selectWmoPortalGroups` получает режим «внешние семена»: когда нет комнаты-семени, семенами становятся группы с `!indoor || exterior` из списка-кандидата (апертура — весь экран), обход как сейчас (`projectPortal`, объединение апертур, консервативное расширение у near-плоскости), помеченными остаются достигнутые комнаты, наружные оболочки и «сироты» без порталов; результат `used: true`. Сигнатура: добавить необязательный последний параметр `{ exteriorSeeds: boolean }`, старые вызовы не меняются.
  - **Срез 3 — рендерер (`WorldRenderer3D.ts`, узкая точка подключения).** В `#updateWmoGroups`: для статического окружения при камере снаружи вызывать обход с внешними семенами над списком-кандидатом `wmoGroupsInRange(model, boxes, player, WMO_EXTERIOR_RANGE)` (комнаты до 250 ярдов, вместо 60); привязку доодадов к комнатам (`#noteInteriorOnly` → часть, отвечающая за `INTERIOR_ONLY_DOODADS.set`) вынести в `#bindWmoDoodads(placed)` и вызывать для каждого здания с `doodadRooms` и `portalSelection.used`; дальность доодада комнаты, признанной видимой, — `WMO_EXTERIOR_RANGE`, а не 60. Всё остальное (порядок построения комнат, `WMO_GROUP_BUILD_BUDGET`) без изменений. Настройка `wmoOcclusion` выключает всё разом.
- **Сверено вне кода.** Клиентский порядок: из открытого воздуха комнаты видны через порталы наружных групп (MOGP `0x8`), у порталов есть сторона (`MOPR.side`); текущий обход её не проверяет и потому только преувеличивает видимость (безопасно). ### 7.06 — MCSH: запечённые тени рельефа (генератор и шейдер)
- **Подход.** Повторить клиентскую раскладку: MCSH (64×64 бита на чанк, тот же растр, что у альфа-карт) кладётся в **четвёртый канал** `alpha.png` (`1` = освещено), шейдер множит альбедо на `0,7 + 0,3·свет`. Эталон формулы — программа клиента, не память.
- **Сверено.**
  - Клиент (`probe-bls.out.txt`, `Shaders\Pixel\arbfp1\terrain2.bls`): `TEX R0.w, texcoord[1], texture[1]` — канал `.w` альфа-текстуры; `свет = min(alpha.w, динамическая тень)`; `альбедо × (свет·0,3 + 0,7)` (`c[12] = {0,2; 0,3; 0,7; 2}`), зеркальная часть × свет. То есть запечённая тень темнит землю не более чем на 30 % и убирает блик; освещённость (`primary`) от неё не зависит.
  - Данные (`probe-mcsh.out.txt`, 12 ADT на континент): Azeroth 3 072 чанка, флаг `MCNK 0x1` и блок MCSH 512 байт **у всех**, в тени 18,5 % площади (1 874 чанка без единого бита, 60 полностью в тени); Kalimdor 2 816/2 816, 10,3 % (2 197 без бит, 83 в тени); Expansion01 флаг у 932 из 3 072, 41,9 %; Northrend 710 из 3 072, 19,8 %. ### 7.07 — Освещение рельефа: `max(N·L, 0)` плюс ambient по Light
- **Подход.** Клиентская вершинная программа рельефа — эталон: `лит = min(1, ambient + diffuse · clamp(N·L, 0, 1))`, без `abs` и без пола 0,2. Заменить у вида `terrain` и в CPU-двойнике; вид `foliage` (`abs`) и `surface` не трогать.
- **Сверено.** `probe-bls.out.txt`, `Shaders\Vertex\arbvp1\terrain.bls`: `DP3 R0.y, нормаль, c[24]` → `MIN(…, 1)`, `MAX(…, 0)` (константы `c[37] = {0, 1, 0,5}`) → `diffuse(c[26]) · N·L + ambient(c[25])` → `MIN(…, 1)` → цвет × 0,5; фрагмент множит на 2. `WorldLighting.ts`: `worldLightFactor(…, kind)` — `kind === "terrain"` → `Math.max(Math.abs(ndotl), 0.2)`; тот же расчёт в GLSL под `#if defined( WOW_LIGHT_TERRAIN )` (`float wowNL = max( abs( wowDot ), 0.2 );`), плюс сглаживание тени `smoothstep( 0.05, 0.25, abs( wowDot ) )`; `applyLightHeadroom` пересчитывает ambient и diffuse до умножения (82 % наборов превышают 1 в канале). Формула `abs` и пол 0,2 пришли из wowee; клиент их не содержит. В контрольном профиле рельеф — Lambert (`applyTerrainSplat`).
- **Изменения.**
  1. `WorldLighting.ts` (GLSL и `worldLightFactor`): `terrain` → `nl = max(ndotl, 0)`; сумма `ambient + diffuse · nl` для рельефа ограничивается 1 по каналу **только в контрольном профиле** (клиент насыщает, а не масштабирует); в улучшенном режиме остаётся `applyLightHeadroom`. Версию ключа программы света (суффикс `world-light-r185-vN`) поднять.
  2. Сглаживание тени у скользящих углов оставить (`abs(wowDot)`): при `N·L ≤ 0` прямая составляющая нулевая.
- **Тесты.** `tests/world-lighting.test.mjs` (расширить): `worldLightFactor` рельефа при `N·L = −0,5` → только ambient; при 0,5 → ambient + 0,5·diffuse; пол 0,2 отсутствует; GLSL содержит `max( wowDot, 0.0 )` для `WOW_LIGHT_TERRAIN` и не содержит `abs( wowDot ), 0.2`; `tests/terrain-shader-profile.test.mjs`: ключ программы обновлён. Мутация: вернуть `abs` — тест `N·L < 0` падает. Побайтность RND-4б (Lambert для M2/WMO) этой правки не затрагивает.
- **Офлайн-проверка (М-A7b-3).** lookdev `--scenario movement`, склоны Элвинна при закате `2100` и в полдень `1440`, режим по умолчанию (контрольный) и `enhanced`; парный кадр (yaw на солнце и от него): склон от солнца темнее (только ambient), склон к солнцу — как раньше. Цена: 0 (та же программа, меньше ALU).
- **Живая проверка.** → 14.25 (парный кадр земли), 14.24.
- **Зависимости.** RND-4б (решение 0.4i: Lambert как база для M2/WMO; здесь только рельеф, конфликта нет), 7.06 (тень), 7.20 (профиль).
