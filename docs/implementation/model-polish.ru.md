# Улучшение моделей заранее (проба 7.62, 04.11)

Просьба владельца: пройтись по моделям инструментами и сделать их лучше, проверить затенение, сглаживание и рельеф, а для апскейла текстур существ и предметов посчитать вес.

Всё офлайн и вне игры: `tools/model-polish.mjs` (три чистые функции), `tools/polish-models.mjs` (запуск), `src/browser/ModelVertexAo.ts` (чтение затенения), `tests/model-polish.test.mjs`. Шлюз обработанные модели не отдаёт, игрокам ничего не меняется. Стенд: `bench/lookdev.mjs --model-variants <папка>`.

```powershell
node tools/polish-models.mjs --out .runtime/model-polish/scene --steps smooth,relief,ao --relief-only "rock,cliff,boulder" --tile 0/48-30
```

## Что делает

- **Затенение.** 64 луча на вершину по своим треугольникам модели и по земле, если модель на ней стоит. Хранится в длине нормали: новых данных нет, размер файла тот же. Читается только у модели с флагом `WVM9_NORMALS_CARRY_AO`.
- **Сглаживание.** PN-треугольники (Vlachos 2001) по авторским нормалям, ребро делится только там, где нормали говорят о кривизне. Старые вершины не двигаются, новые получают смесь весов костей и UV, анимации те же.
- **Рельеф.** Карты высот DeepBump из `.runtime/neural-relief/content/`, сетка уплотняется до деталей карты, копии точки двигаются вместе, поэтому трещин нет.

Правила против поломок (на каждое есть тест, каждый проверен поломкой правила):

| Что ломалось на снимках | Правило |
| --- | --- |
| Квадратные столбы раздувались, как гроб | нормаль дальше 42° от своей грани, складка больше 65°, поворот нормалей больше 55° |
| Полотно картины уходило за стену | ребро не прогибается внутрь; наклонённая нормаль на плоской поверхности не считается кривизной |
| Трещины на швах UV | новая точка считается один раз на сваренное ребро |
| Авторская острая кромка | вершины с разными нормалями на ребре его запрещают |
| Листва и прозрачное | делится только сплошное и освещённое |

## Апскейл текстур существ и предметов: вес

Формат тот же, что у набора мира: BC7 с мипами, измерено 1,334 Б на HD-пиксель. PNG-вход занимает примерно столько же, игрокам не отдаётся.

| Что | Текстур до 512 px | BC7 (×2 всё до 512) | Только до 256 px |
| --- | --- | --- | --- |
| Существа | 6 511 | 4,36 ГБ | 0,53 ГБ (2 380) |
| Предметы на модели | 7 130 | 1,34 ГБ | 0,91 ГБ (6 572) |
| Куски брони на теле | 20 360 | 1,09 ГБ | 1,09 ГБ |
| Кожа и волосы персонажей | 13 755 | 2,61 ГБ | 1,37 ГБ |

- **Видеопамять не растёт.** BC7 ×2: четыре пикселя по байту, столько же, сколько один исходный пиксель RGBA. Счётчик на улице Штормграда: 323,1 МБ и без набора мира, и с ним.
- **Растёт загрузка.** Там же 348 текстур: 78,4 МБ вместо 21,2 МБ, в 3,7 раза, и только для того, что игрок увидел.
- **Что сокращает.** Только до 256 px: существа и предметы 5,70 → 1,44 ГБ (−75 %), текстуры 512 px в основном уже HD из патчей. Сжатие при отдаче: gzip 69 %, brotli 67 % от размера BC7 (150 образцов); сейчас `.wht` идёт без него, его типа нет в `compressibleType` (`src/gateway/ResponseCompression.ts`), а добавление снизит загрузку и у уже готового набора мира. По http браузер предлагает только gzip. Подгрузка HD только рядом с игроком: не мерили. BC1 не стоит того: непрозрачных лишь 26 % пикселей, выигрыш около 13 %.
