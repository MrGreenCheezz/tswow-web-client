# Линия ARC-4: интерфейс на PUC Lua 5.1.5 в WASM вместо fengari

**Решение владельца (09.10):** принять ARC-4 вопреки порогу памяти (A) прототипа P2-12 и переписать VM интерфейса.
**База:** прототип `.runtime/perf-step23/arc4/` (README — полный разбор) и вердикт в `PERF_STATUS.md` («Шаг 23 — P2-12»):
мост FrameXML (OnUpdate + 20 событий) 9,4–9,7 → 1,7–1,8 мс на кадр (5,5×), только OnUpdate 4,9×, загрузка стокового
интерфейса 1,85×, куча JS 300 → 164 МБ (−136 МБ), объектов Lua в куче JS ≈ 576 тыс. → 0. Корпус на обеих VM —
25 046 виджетов, 0 ошибок Lua и XML. Прототип прошёл 13 из 14 обязательных тестов на wasm (`glue-lua` 9/10 — молчаливые
экранирования 5.1).

## Цель и готовность

Интерфейс (glue-экраны и стоковый FrameXML с аддонами модулей) работает на PUC Lua 5.1.5 в WASM; fengari удалён.
Готово, когда: (1) весь набор тестов проходит на wasm; (2) корпус и HUD дают ту же перепись, что сегодня; (3) стенд
`framexml-lua-bench` и живая запись показывают выигрыш моста; (4) владелец прошёл живой чек-лист (вход, выбор персонажа,
HUD, книга заклинаний, чат, журнал боя, аддоны модулей, сохранённые переменные); (5) fengari удалён из зависимостей.

## Архитектура

- `third_party/lua-5.1.5/` — копия исходников Lua 5.1.5 (MIT, с `COPYRIGHT`) из `CPPClientExample/wowee/extern/lua-5.1.5/src`,
  чтобы сборка не зависела от `CPPClientExample`. Правки Wow.exe (число → строка `%.14g` MSVC, `fistp`, часовой пояс хоста)
  накладываются сборкой, а не правкой копии.
- `tools/lua-wasm/` — `wow_lua.c` (экспорты API 5.1, обёртки 5.3-вызовов, трамплин JS-функций, ошибки без проброса JS
  через кадры wasm), `wowbit.c` (`bit`), `build.mjs` (wasi-sdk 34.0 из `.runtime/tools`, флаги прототипа, `BUILD.json`
  с SHA-256 исходников и результата, списками импортов и экспортов). Тулчейн в репозиторий не входит.
- `src/browser/lua/lua51.wasm` — собранный артефакт в git (≈ 620 КБ, legacy-исключения: Node 22, Chromium ≥ 95, Electron).
- `src/browser/lua/LuaWasm.ts` — один экземпляр модуля на процесс: в браузере `fetch(new URL("./lua51.wasm",
  import.meta.url))`, в Node — чтение файла; заглушки WASI без `node:wasi`; `heap()` с переоткрытием после `memory.grow`.
  Инициализация — top-level `await` (цель сборки es2022 его позволяет), поэтому API для вызывающих остаётся синхронным.
- `src/browser/lua/LuaApi.ts` — фасад с именами и сигнатурами fengari (`lua`, `lauxlib`, `lualib`, `to_luastring`,
  `to_jsstring`, `push`/`tojs`), перенос `fengari-facade.mjs` в TS со строгими типами по `src/types/fengari*.d.ts`.
  `lua_topointer` — `Map<адрес, жетон>` с явным освобождением в `releaseFrame` (в прототипе жетоны не освобождались).
- `src/browser/lua/LuaVm.ts` — выбор VM на время перехода: wasm по умолчанию, `?luavm=fengari` (и переменная для тестов)
  — прежний путь. Девять файлов, импортирующих `fengari` (`GlueLua`, `GlueLuaBase51`, `GlueLuaFormat`, `GlueLuaNatives`,
  `GlueWidgetFormat`, `GlueWidgets`, `FrameXmlEuropeanNumbers`, `FrameXmlLuaEnvironment`, `FrameXmlSavedVariables`),
  импортируют его отсюда.

## Риски и как их ловить

- **Отличия 5.1 от 5.3** (список прототипа: `coroutine.running`, аргументы `xpcall`, уступка через `pcall`, тексты ошибок,
  порядок `pairs`, `'?'` в «bad argument», `math.fmod(-2^31,-1)`): каждое — тест на обеих VM; поведение 5.1 ближе к
  Wow.exe, поэтому правится наш код, а не VM. Модули TSWoW, работавшие в Wow.exe, обязаны работать и здесь (правило
  полной совместимости модулей).
- **Утечки и переиспользование адресов** (`lua_topointer`, реестр JS-функций): тесты на освобождение; счётчики в телеметрии.
- **Линейная память не сжимается** (рост до 31 МБ за 1 200 кадров): `lua_gc(LUA_GCSTEP)` в запасе кадра; замер после часа игры.
- **Хвост p99 моста** (5–7 мс в прототипе): профиль в браузере на этапе A5.
- **Отравление VM** при переполнении стека (`RangeError`): тест и понятная ошибка вместо зависания.

## Ход работ

- **09.10 — A1–A5 сделаны, VM по умолчанию — wasm.**
  - A1: `third_party/lua-5.1.5/` (MIT), `tools/lua-wasm/{build.mjs,wow_lua.c,wowbit.c,BUILD.json}`,
    `src/browser/lua/lua51.wasm` (619 426 байт, сборка воспроизводима: `build.mjs --check`); тест `lua-wasm-artifact` 4/4.
    `wowbit.c` приведён к исправленной Lua-версии `bit` (остаток по модулю 2^32 для любого конечного числа).
  - A2: `LuaWasm.ts` (top-level `await`, Node — `process.getBuiltinModule`, из `dist/code` — откат на `src`), `LuaApi.ts`
    (фасад со строгими типами; жетоны `lua_topointer` освобождаются; декодер fengari для битого UTF-8, чтобы строки
    совпадали на обеих VM; `push`/`tojs` мимо объекта `lua`, как у fengari-interop); тест `lua-wasm-api` 8/8, мутации пойманы.
  - A3: `LuaVm.ts`; десять модулей рантайма и девять тестов импортируют Lua отсюда.
  - A4: 5.1-тексты (`GlueLua51NativeShims.ts`, `FrameXmlLua51NativeShims.ts`), родные `next/pairs/tostring/fmod` и
    `setfenv/getfenv/newproxy` на wasm; переносимые исправления защищённых обёрток (`coroutine.running() or "main"`,
    `xpcall` через замыкание) для обеих VM; на wasm числа из JS кладутся как double (`-0` остаётся `-0`, как в Wow.exe);
    освобождение жетона таблицы в `releaseFrame`. Тесты, которые сверяли поведение эмуляций, теперь сверяют 5.1 на
    wasm (имя `'?'` в «bad argument» через `pcall`, свой `next` у `pairs`, `-0` у C-шного `fmod`, порядок хеш-части PUC);
    тесты самих эмуляций и их стоимости (`lua_sethook`) на wasm пропускаются с причиной. Полный набор на wasm — без
    падений, кроме двух тестов с порогами времени, которые проходят по отдельности.
  - A5: в браузере (Vite, `framexml.html`) на wasm и fengari одна перепись — 25 156 виджетов, 138 Lua-файлов без
    ошибок, 294 обработчика, 9 622 ответа нейтрального API; загрузка интерфейса **1,8 с против 11,2 с**. Сборка Vite
    кладёт `lua51-*.wasm` в `dist/web/assets`. Мост (`bench/framexml-lua-bench.mjs`, Node, медианы, мс на тик):
    `stock` 1,50 → 0,23 (6,6×, 3 пары), `decode` 2,06 → 0,23, `api` 6,42 → 0,62, `iter` 18,8 → 0,86, `format`
    2,39 → 0,85, `tooltip` 18,1 → 7,1; сырьё `.runtime/perf-step23/arc4-src/bridge-bench.jsonl`.
