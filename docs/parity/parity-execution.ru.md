# Выполнение плана сопоставления с WoW 3.3.5a

Начало: 23 сентября 2026 года. Цель и критерии: `CLIENT_PARITY_PLAN.ru.md`. Это журнал текущей задачи, а не устойчивые правила проекта.

## Исходная точка

- Рабочая ветка: `perf/optimization`; рабочее дерево уже содержит многочисленные чужие незакоммиченные изменения. Их нельзя откатывать или включать в «чистый» baseline по `HEAD`.
- Целевой комплект по `AGENTS.md`: TSWoW, `F:\Circle` (`ruRU`, build 12340), `F:\tswowRoot\tswow\cores\TrinityCore`, dataset установки TSWoW. `Wow.exe` имеет версию `3.3.5.12340` и SHA-256 `203B4B111DDC2D71612054D7AAF627FA6A7C929ED4F57E81B3C58DF8284854A4`. Текущий `sourceClientDirectory()` разрешается в `F:\Circle`; путь запущенного realm и переданного конфига совпадает с выбранной установкой, но происхождение бинарника из текущего дерева исходников не подтверждено.
- Локальный bundled Node: `.runtime/node/node.exe` v22.23.2; системный `node` v20.18.0. Source hook требует Node ≥22.15.
- Браузерный инструмент доступен как Codex In-app Browser. Порты web/gateway/auth/world `5173/8090/3724/8085` отвечают локально. Проверка исполняемых путей владельцев портов показала: auth/world запущены из `F:\tswowRoot\tswow-install\bin\trinitycore\RelWithDebInfo`, web/gateway — из WebClient `.runtime/node`. Несекретные поля `node.conf`, `realm.conf`, `dataset.conf`, `worldserver.conf` связывают `default.realm`, `default.dataset`, `F:\Circle` build 12340 и world-port 8085. Санитизированная проверка командной строки работающего worldserver подтвердила путь именно этого `worldserver.conf`, без вывода аргументов или секретов. Позднее пользователь предоставил доступ к уже существующей тестовой учётной записи; её данные не записывались в отчёт.
- Проверенные соседние материалы: `../AGENTS.md`, отдельные рабочие копии `wc-ui`, `wc-visual`, `wc-world`, `wc-ground`, `wc-fix`, а также `tswow-tests`. Копии имеют самостоятельные изменения и не являются эталонными кадрами оригинала.
