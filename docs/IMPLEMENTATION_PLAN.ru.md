## 2. Как делается срез

**Готов к работе, когда:** спецификация пункта сверена с текущим кодом (строки плавают — искать по имени функции); зависимости закрыты; файлы среза не держит другая дорожка (§3); для UI работает офлайн-фикстура.

**Шаги.**
1. Перечитать места из спецификации. Если код разошёлся — сначала поправить спецификацию в плане.
2. Написать регрессионный тест и убедиться, что он **падает** на текущем коде: это доказательство дефекта. Тест, проходящий и на сломанном коде, — дефект спецификации.
3. Реализовать. Новый модуль вместо роста горячего файла: в горячий файл идёт только строка подключения.
4. Узкие тесты: `npm run test:file -- tests/<файл>` (после 0.3); до этого — `.runtime/node/node.exe --import ./tools/register-test-sources.mjs --test --test-concurrency=1 --test-timeout=240000` с `NODE_OPTIONS=--max-old-space-size=4096`. Не более одного прогона `bench`/lookdev одновременно.
5. Мутационная проверка: сломать исправление → тест падает → вернуть, сверить хеш файла. Не на файлах, которые правит другая дорожка.
6. `node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit` → 0 ошибок (никогда `npx`).
7. **UI:** офлайн-фикстура (`framexml.html?toc=vertical`, `.runtime/ui-audit/native.html`, MPQ vertical-тест). Перепись `frameXmlWorld().errors` и `frameXmlWorld().api` — без новых ошибок и неотвеченных имён; кадр при визуальных изменениях.
8. **Рендер:** цена — строгий A/B `bench/run.mjs` при совпадающем fingerprint или офлайн-кадры `bench/lookdev.mjs`; записать мс на кадр и число вызовов.
9. **Ревью** двумя независимыми проверяющими: (а) корректность против TrinityCore и стокового Lua; (б) регрессии, цена, соседние сценарии. Затем исправление замечаний.
10. **Отметка:** `[x]` в плане работ (дата, тест), строка в журнале, живая проверка — в очередь этапа 14.

**Готово, когда:** тест падал до правки и проходит после; `tsc` чистый; нет новых ошибок Lua и неотвеченных имён; замечания ревью закрыты; запись в журнале; живая проверка назначена. **В конце вехи:** один полный прогон под сторожем; `npm run build`, если менялись точки входа; окно перезапуска gateway, если менялся `src/gateway/**`; живая сессия этапа 14.

**Нельзя:** передавать фреймы моста в `assert` (сравнивать `?.name`); запускать полный прогон из нескольких агентов; запускать и перезапускать серверы владельца (auth/world/MySQL) и gateway; работать вне WebClient без просьбы; коммитить без просьбы; править сгенерированные таблицы руками (запуск генераторов допустим); открывать раздачу наружу; снижать качество освещения ради скорости; трогать Parsec и перечислять модули чужих процессов (для проверки процесса — только лёгкий запрос имени образа).
