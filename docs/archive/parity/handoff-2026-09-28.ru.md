## 4. Инцидент с памятью и обязательные правила

В 15:13 и 15:17 Windows зафиксировал нехватку памяти (журнал System, Resource-Exhaustion-Detector): node.exe 21784 — 101 ГБ и node.exe 28572 — 131 ГБ виртуальной памяти; в 15:17:16 chrome.exe упал в KERNELBASE (0xe0000008), интерфейс приложения Claude опустел, три линии оборвались. Скрипты репозитория никакой Chrome не закрывают (bench/lookdev убивают только свой дочерний процесс по PID) — Chrome умер от нехватки памяти. Причина: восемь параллельных агентов, двое из которых запустили полный набор тестов (`node --test` на 5 000+ тестов, до 19 воркеров каждый на 20-поточном CPU), плюс headless Chrome для lookdev; размеры отдельных процессов указывают на «убежавший» тест. Подробности: заметка памяти `parallel-test-runs-oom`.

Конкретная бомба найдена: `tests/framexml-character-vertical.test.mjs` считал `PetPaperDollFrame` заглушкой; после включения PetPaperDollFrame.xml в TOC его `assert.equal(bridge.getFrame(...), undefined)` падал, и Node формировал сообщение об ошибке, инспектируя граф из ~20 000 связанных виджетов — процесс уходил за десятки гигабайт за секунды (воспроизведено: 3,7 ГБ за 12 с). Все такие сравнения в тестах переписаны на примитив (`getFrame(...)?.name`), сам тест обновлён под реальный фрейм.

Правила:

- Никогда не передавать объект фрейма моста в `assert.*`; сравнивать `?.name`/`?.type`/примитивы.
- Никогда не запускать полный набор тестов из нескольких агентов; полный прогон — один, в конце, `--test-concurrency=4`, под watchdog (PowerShell-цикл, `Stop-Process` для node с `register-test-sources`/`--test` в командной строке и рабочим набором > 6 ГБ; процессы TSWoW-консоли, gateway и Vite не трогать).
- Всегда `NODE_OPTIONS=--max-old-space-size=4096` и `--test-timeout=240000`; отдельные файлы тестов, `--test-concurrency=1`.
- Пик памяти измерять, а не предполагать: контрольный прогон 17 файлов 28.09 — 1,6 ГБ на процесс; полный прогон при параллелизме 4 — см. §6.
- Node 22: `F:\tswowRoot\WebClient\.runtime\node\node.exe`; typecheck `node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit` (никогда `npx`).

## 7. Как воспроизводить офлайн

- Фикстура: `http://localhost:5173/.runtime/ui-audit/native.html?open=none`, затем в консоли `uiAudit.world.gameTime = {minuteOfDay: 720, minutesPerSecond: 1/60, weekday: 1, date: {day: 28, month: 9, year: 2026}}`, `await (await import('/src/browser/framexml/FrameXmlWorldMount.ts')).mountFrameXmlVertical({})`; книга — `uiAudit.windows.toggleGameWindow(uiAudit.dom.spellbookWindow)`; персонаж — `uiAudit.windows.openCharacterWindow('sheet'|'skills')`. Реальный список заклинаний владельца: `uiAudit.world.knownSpells = ids.map((id, slot) => ({id, slot}))` после `uiAudit.game.spellMetadataClient.load(ids)` (ids — в заметке памяти `live-realm-readonly-facts`).
- Перепись C API: `frameXmlWorld().api.filter(r => !r.neutral)`.
- Стоковый Lua: `curl -H "Origin: http://127.0.0.1:5173" "http://127.0.0.1:8090/client/file?path=Interface/FrameXML/<File>"`.
- Скрытая панель браузера (`document.visibilityState == "hidden"`, `innerWidth == 0`): rAF не идёт, кадр HUD не тикает. Кадр вручную: `const b = frameXmlWorld().boot; b.tickSeam(b.pump.now() + 1); b.bridge.tick(0.02); b.bridge.flushDeferredPaint();`. Для раскладки и снимка — `resize_window` 1600×900, затем `window.dispatchEvent(new Event('resize'))` и тот же ручной кадр; после проверки вернуть `preset: "desktop"`.

## 9. Решения владельца 28.09 (поздний вечер) и что по ним сделано

**Книга заклинаний.** Владелец: заклинания других классов — в отдельную вкладку, в «Общих» — обобщённые навыки вроде расовых. Правило (`src/browser/ui/SpellbookTabs.ts`, общее для штатной и native книги): заклинание уходит во вкладку другого класса, если строка `SkillLineAbility`, подходящая персонажу, лежит в линии чужого класса, а при отсутствии такой строки — если любая видимая строка лежит в такой линии. Класс линии — `TalentClient.skillLineClass`: классовая категория 7 и не меньше 10 строк с маской одного класса. Замер по DBC набора: 30 линий деревьев талантов и «Ковка рун» несут 11–183 таких строк одного класса; линии питомцев и прислужников — 0; «Средства передвижения» (777) — 4 строки паладина из 315; расовые линии — категория 9. Строки талантов в своих деревьях без маски («Взрыв трупа» 51328, два тотема) поэтому тоже определяются по линии, а собственное дерево стандартного класса с одними талантами теперь становится его вкладкой. Вкладка стоит последней; называется именем класса, если у класса нет своих классовых линий («Герой»), иначе «Другие классы»; картинка — иконка первого заклинания. Native книга больше не прячет такие заклинания. На реальных данных персонажа «Тестовый» (класс 13, 75 известных заклинаний; SELECT из `character_spell`): «Общие» — 16 (13 профессий, «Лечебное зелье», «Возврат на базу»), «Герой» — 15 (Автоматическая стрельба, Безрассудство, Конус холода, Порча, Доспех Скверны, Великое/Быстрое исцеление, Кара, Восстановление, Свирепый укус, Свет небес, Проклятие слабости, Взрыв трупа, два тотема); проверено в штатной и native книге фикстуры с `/dbc/talents` gateway. Тесты: `spellbook-other-class-tab` 5/5 (три мутации пойманы).

**Поведение приложения, а не страницы** (веб и Electron). `src/browser/app/NativeAppShell.ts`, подключён в `main.ts`: нет выделения текста интерфейса (кроме полей ввода), нет «призраков» при перетаскивании картинок (собственные перетаскивания интерфейса с `draggable="true"` работают), курсор-стрелка вместо текстового; брошенный файл не заменяет страницу; средняя кнопка не включает автопрокрутку, кнопки мыши «назад/вперёд» и шаг назад по истории не уводят со страницы (первый жест кладёт запись-ловушку); Ctrl+колесо и Ctrl+± не масштабируют; браузерные Ctrl+S/P/O/U/J/H/D/F/G/R, F1/F3/F5/F6/F7/F10, Alt и Tab вне поля не срабатывают (игра по-прежнему видит эти клавиши); после клика кнопка не держит фокус (следующий пробел — прыжок, а не повторный клик); в текстовых полях без явной настройки выключены проверка орфографии и подсказки браузера.
