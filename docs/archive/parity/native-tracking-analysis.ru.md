# Нативный API слежения на миникарте: адреса и пробел WebClient

## Проверенный источник

- `F:\Circle\Wow.exe`, WoW 3.3.5a build 12340, SHA-256 `203B4B111DDC2D71612054D7AAF627FA6A7C929ED4F57E81B3C58DF8284854A4`.
- PE32, image base `0x400000`. Для `.text`: RVA `0x1000`, файловое начало `0x400`. Для `.rdata`: RVA `0x5DF000`, файловое начало `0x5DD800`. Адреса ниже относятся только к этому хешу.
- Проверены пары `{nameVA, functionVA}` в таблице `.data` и код функций через `dumpbin /DISASM /RANGE`. Это статический анализ; живое поведение оригинального клиента не проверялось.

## Что видно из кода

- `GetNumTrackingTypes` (`0x57F170`) складывает число элементов массива по `0xBE8DE8` с результатом `0x57E980`. Последний перебирает 15 записей по 20 байт от VA `0xA11C50` (файл `0x610450`) и применяет маску к биту, полученному из данных персонажа. В таблице есть ключи `MINIMAP_TRACKING_REPAIR`, `...VENDOR_FOOD`, `...VENDOR_POISON`, `...INNKEEPER`, `...FLIGHTMASTER`, `...MAILBOX`, `...TRIVIAL_QUESTS` и другие. Значения масок для `POISON` (`0x10`), `AMMO` (`0x1A`) и `STABLEMASTER` (`0x8`) согласуются с фильтром по классу; точное происхождение читаемого байта отдельно не прослежено.
- `GetTrackingInfo` (`0x57F1B0`) принимает индекс Lua с единицы, проверяет диапазон и возвращает четыре значения для действительного элемента. Для элементов первого массива берёт данные через `0x4CFD20` и выдаёт категорию `"spell"` (строка VA `0x9FF168`). Для элементов из 15 записей вызывает `0x57EB00`, формирует путь текстуры с префиксом `Interface\\Minimap\\Tracking` (VA `0xA1206C`) и выдаёт категорию `"other"` (VA `0xA1205C`). В обоих случаях код выдаёт имя, текстуру, признак активности и категорию; при неудачном поиске возвращает ноль Lua-значений.
- `SetTracking` (`0x57F380`) также преобразует индекс с единицы и разделяет те же два источника. Для первого вызывает `0x80DA40` с элементом массива, для второго — `0x57E070` с записью из статической таблицы. Ветка без числового аргумента вызывает `0x57E070` с нулём. Как именно эти вызовы меняют ауры и состояние слежения, по этому фрагменту не установлено.
- `GetTrackingTexture` (`0x57F4F0`) сначала проверяет выбранную статическую запись, затем выбранный элемент первого массива; при отсутствии выбора использует строку `None` (VA `0xA12088`) с тем же префиксом пути. Детали приоритета при одновременной активности следует проверить в живом клиенте.

Штатный `Interface/FrameXML/Minimap.lua:427-454` вызывает `GetNumTrackingTypes`, затем `GetTrackingInfo(id)` для строк меню и передаёт выбранный `id` в `SetTracking` (`:421`); пункт «Ничего» передаёт `nil`. Для иконки кнопки `Minimap.lua:409` вызывает `GetTrackingTexture`.

## Пробел и критерии реализации

> **04.10: пробел для заклинаний слежения закрыт, абзац ниже — состояние на момент анализа.** Четыре API привязаны в таблице `FrameXmlWorldSeam.ts` (`GetNumTrackingTypes`, `GetTrackingInfo`, `GetTrackingTexture`, `SetTracking`; привязка перекрывает нейтральную константу `0` из `FrameXmlNeutralApi.ts`) и реализованы в `LiveWorldSeam.ts` (`trackingCount`, `trackingInfo`, `trackingTexture`, `setTracking`) по тому же снимку известных заклинаний, что и `ui/Tracking.ts`: 1-based индексы, четыре значения с категорией `"spell"`, `SetTracking(nil)` снимает все активные, включение — каст заклинания, выключение — `CMSG_CANCEL_AURA`. 15 статических записей `"other"` по-прежнему не моделируются.

В `src/browser/framexml/FrameXmlNeutralApi.ts` `GetNumTrackingTypes` сейчас отвечает постоянным `0`; `GetTrackingInfo`, `SetTracking` и `GetTrackingTexture` не имеют привязок в `FrameXmlWorldSeam.ts`. При этом `src/browser/ui/Tracking.ts` уже получает известные персонажу заклинания слежения, активность из серверных полей и реализует выбор через cast/cancel aura. Значит, пустое штатное меню не отражает доступное состояние мира. В текущем UI штатное управление слежением скрыто и оставлена собственная кнопка миникарты (`FrameXmlWorldMount.ts`), поэтому пробел прежде всего затрагивает совместимость FrameXML и аддонов; обычный путь пока обслуживает собственный интерфейс.

Первый реализуемый срез: дать FrameXML тот же снимок известных заклинаний, 1-based индексы, четыре значения `GetTrackingInfo` и выбранную текстуру; после выбора сверять активность с ответом сервера. Затем добавить 15 статических вариантов `"other"` с их условной доступностью и действием, когда будет проверена их семантика. Проверки должны покрывать непустой список, неверный индекс, выбор, повторный выбор, `nil` для «Ничего» и изменение после серверного обновления. Для полной идентичности нужны живое сравнение на персонажах разных классов и разбор действий `0x80DA40`/`0x57E070`; статический анализ не подтверждает точное поведение этих вызовов.
