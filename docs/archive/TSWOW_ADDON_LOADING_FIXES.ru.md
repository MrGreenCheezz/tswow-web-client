# Загрузка окон TSWoW: диагностика и исправление, 19.09.2026

Жалоба: зависание на 2–4 секунды при подгрузке аддонов/окон. Исследована текущая версия WebClient и реальные Lua/XML из выбранного клиента F:\Circle, ruRU. Игровой сервер, БД и исходники модулей не изменялись.

## Подтверждённые причины

- Обычный режим TSWoW использует общий FrameXML runtime со стандартными зависимостями: после загрузки в стенде получается 12 518 виджетов. Чтение закешированных файлов через Promise не предоставляет браузеру отдельную задачу для отрисовки и ввода.
- Диагностический сбор первого обращения к API вызывал полный `debug.traceback`. В Fengari этот путь ищет имена функций обходом растущих Lua-таблиц. CPU-профиль подтвердил большую стоимость именно диагностического обхода.
- Лексический анализ Lua создавал строки посимвольно и проверял длинную скобку на каждом символе. У `base-building/shared/generated/craftstationrecipes.lua` около 3,5 млн символов; анализ каталога особенно сильно нагружал GC. Поиск экспортируемых глобальных имён также повторял проход по исходнику для каждой строковой константы.

## Изменения

- Для диагностики читаются только источник и строка Lua-стека. Счётчики и место первого обращения сохранены; обработка настоящих ошибок по-прежнему сохраняет traceback.
- Lua сканируется фрагментами строки; поиск экспортов выполняется фиксированным числом проходов.
- Загрузка мира использует `GlueLoadScheduler` с мягким бюджетом 8 мс и реальной уступкой через задачу таймера. Проверки стоят между файлами, XML-декларациями, этапами анализа и начальными событиями. Загрузка дополнительных аддонов получает тот же механизм.
- Порядок TOC/Include/Script/OnLoad сохранён. Закрытие runtime во время уступки останавливает дальнейшее выполнение Lua.

## Непроверенное

Браузерный инструмент дважды завершился до подключения: `windows sandbox failed: helper_unknown_error: apply deny-read ACLs`. Поэтому реальный FPS, браузерная раскладка/отрисовка окон и проход по миру с подключением к серверу не измерены. Локальный стенд подтверждает устранение многосекундной непрерывной работы загрузчика, но отдельные тяжёлые Lua-файлы ещё могут давать короткие рывки.

Локальные артефакты: `.runtime/qa-addon-loading/` — исходные замеры `baseline-no-profiler.json`, итоговые `scheduled.json`, CPU-профили, сценарии `addon-behaviors.json`, журналы тестов/сборки и снимки исходников до правок. `profile.mjs scheduled --yield` запускается через `.runtime/node/node.exe --import ./tools/register-test-sources.mjs`.

## Восстановление браузерного инструмента

Позднее в этой задаче установлена точная причина сбоя: файл `C:\Users\Administrator\.codex\.sandbox\deny_read_acl_state.json` содержал 22 нулевых байта. Журнал sandbox указывал на ошибку разбора этого JSON. Повреждённый файл сохранён как `deny_read_acl_state.corrupt-20260919.json` в той же папке; штатный Codex автоматически создал корректное состояние. Настройка `windows.sandbox = "elevated"` сохранена. Обычная команда в sandbox и запуск CUA успешно проверены; в браузере открыт WebClient и прочитан экран входа. Это подтверждает восстановление инструмента, но не заменяет ещё не выполненный живой замер плавности аддонов.
