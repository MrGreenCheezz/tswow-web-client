# Оптимизации рендера оригинального клиента WoW 3.3.5a (build 12340)

Дата: 2026-09-29. Офлайновый статический разбор `F:\Circle\Wow.exe.clean` (SHA-256
`8D1067F7D3391248FEE97FD7426FD86AC4EF9B88C06BCE1B3E65F85C75112EDE`). Код рендера идентичен
текущему `F:\CircleClean\Wow.exe`/`Wow.exe.clean`: их `.text`/`.rdata` совпадают между собой,
а от анализируемого образа отличаются только 708 байтами патчей TSWoW (загрузка
`ClientExtensions.dll`, кастомные ID, отключение UI-подписей, кеш-путь, две float-константы) —
ни один диапазон не лежит в подсистемах рендера. Подробности: `research/original-client/patch-diff.md`,
`research/original-client/render-analysis/README-corpus.md`.

Материал собран Ghidra 12.1.4 (проект `research/original-client/ghidra-project/WoW335`,
`Wow.exe.clean`, 27 733 функции, 38 668 символов) и девятью параллельными разборами подсистем;
полные отчёты и декомпиляции — в `research/original-client/render-analysis/notes/` и
`render-analysis/ghidra-out*/`. Ниже — свод методов оптимизации. Это статический анализ:
он показывает механизмы, но не подтверждает, какие ветки выбираются настройками в конкретном
запуске. Часть тел функций не декомпилирована — границы указаны в заметках.

## 0. Ключевые находки (краткая выжимка)

- **Батчинг сцены**: записи-батчи (kind 0–5, stride 0x44); `BatchDoodad 0x00820AE0` и частицы
  `0x00821100` сливают инстансы в один динамический VB и один draw; лимиты `0x100000/stride` и
  `0x20000`, ёмкость чанка кратна 16; `M2ForceAdditiveParticleSort` (`0x004024D0`) сортирует
  аддитивные частицы по материалам ради склейки.
- **Состояние устройства**: теневая копия состояний `0x006A4C30` (пропуск избыточных
  `SetRenderState`) + журнал отложенных состояний `0x00685970`; фиксированные пулы
  `CGxPool`/`CGxBuf` (`0x006876D0`/`0x00687660`).
- **Видимость**: единый бит frustum-culling (bit5), per-triangle отбор террейна по hole-маске
  (`0x007D8840`), порталы WMO + `antiportal` по имени (`0x007D82E0`), покадровые плоскости
  `CWorldOccluder` (`0x007CC810`); hardware occlusion queries — только солнце/луна, не мир.
- **LOD/дальность**: terrain LOD (bit2), низкодетальный WDL-горизонт (bit26), затухание объектов
  битами 14/15, `waterLOD` принудительно 0 (`0x0078D8B0`), FOV-поправка дальности
  (`farclip/cos(fov/2) − farclip`).
- **Анимация/стриминг**: палитра костей пересчитывается не чаще раза в кадр по dirty-флагу
  (`0x00830DC0`), очередь команд модели, async-поток чтения `0x004BA680`, M2/blob/текстурные кеши.
- **Опции**: единый битфилд `0x00CD774C` (77 обращений), при входе в мир `|= 0x7104B73`;
  полная карта — `options-map.tsv`.
- **Тени**: 3 слота MapShadow с предвыделенными буферами (`0x007BA840`, 2×0x2000 + 2×0x18000),
  LUT-текстура `CWorld::shadowMod` 8×8 (`0x00780660`) с пересборкой только по смене цвета.
- **Бюджеты**: `particleDensity` (0.1..1.0), миникарта ≤4 юнитов и ≤40 меток, погода ≤0x95
  записей, `minimapPortalMax`.

## 1. Архитектура кадра (кратко)

- Колбэк кадра мира: `CGWorldFrame::Draw` `0x004FAF90` → Update `0x004FA5F0` (камера, свет,
  погода, `0x007831A0`) → небо `0x007E6480` → `DrawWorld` `0x004F8EA0` → `CGWorldScene::DrawFrame`
  `0x0079A870` → подсистемы (тени `0x007BB570`, M2-сборка `0x00821A20`, террейн `0x00798DA0`,
  миникарта `0x007F31C0`, сущности `0x00793980`, `Liquid::CInstance` `0x008A2240`).
  M2-батчи флашатся уже после `DrawFrame`, в `DrawWorld`.
- Отрисовка мира — через абстракцию устройства: глобал `g_theGxDevicePtr = 0x00C5DF88`,
  D3D9-реализация имеет vtable `0x00A2E718` (84 метода). Слоты: +0x04 состояние `0x006A4C30`,
  +0x28 инициализация `0x00690750`, +0x98 EndFrame `0x006A3450`, +0xA8 draw `0x006A3620`,
  +0xD0 реаллокация буфера, +0xD8/+0xDC Lock/Unlock `0x0068FCE0`/`0x0068FAE0`,
  +0xF8..+0x10C occlusion query.
- Кадр устройства: `BeginFrame 0x006A3350` держит `BeginScene` открытым до `EndFrame 0x006A3450`,
  который делает `EndScene` → курсор → Present. При `gxFixLag` — синхронизация через
  `D3DQUERYTYPE_EVENT` (`0x006A3A60`, поле `+0x3B48`).

## 2. Битфилд опций `0x00CD774C` — единые выключатели оптимизаций

77 обращений в коде рендера. При входе в мир `FUN_00780F50` выставляет `|= 0x7104B73`
(включены, среди прочих, culling и terrain shadow); часть битов включается условно от видеоопции
`*(FUN_00532AF0()+0xC4)`. Полная карта: `render-analysis/options-map.tsv`.

| Бит | Эффект | Доказательство |
| --- | --- | --- |
| 0x4 (bit2) | Terrain LOD | `FUN_0078D610` «Terrain LOD enabled/disabled», гейты `0x00793B10`, `0x00793C30`, `0x007989C0` |
| 0x20 (bit5) | Frustum-culling во всех подсистемах | `FUN_0077F650` «Terrain culling enabled/disabled»; проверки `0x0078F6A0/F900/FC40/FDC0`, `0x00793760`, `0x00799D40` |
| 0x40 (bit6) | Terrain shadow | `FUN_0077F7E0`, `FUN_0078D660`; гейты в `0x007B9890/B99B0/B9EE0`, `0x007D0D70` |
| 0x400 (bit10) | Следы (footprints) | `FUN_0078D8F0` «Showing/Hiding foot prints»; потребители `0x0079FCC0`, `0x00723A50` |
| 0x4000/0x8000 (bit14/15) | Затухание объектов (objectFade / ZFill-проход) | `FUN_0078DB90`/`FUN_0078DBE0`, потребители `0x00791CB0`, `0x007BDB10` |
| 0x40000 (bit18) | не читается в `.text` (вероятно мёртв; низкая детализация — bit26) | `options-map.tsv` |
| 0x100000 (bit20) | Detail doodads | `FUN_0077F5B0`; гейты `0x007D3FE0`, `0x00820AE0`-линия |
| 0x200000 (bit21) | Портальный проход WMO | `0x007C7AE0`, `0x007D8840`, `DrawFrame:216` |
| 0x1000000 (bit24) | Сортированные `Liquid::CInstance` | `0x0079A870:189`, `0x008A2240`, `0x00790A80` |
| 0x2000000 (bit25) | Водные particulates/рябь | `FUN_0077F6B0`, `0x0077F9D0`, `0x007831A0`, `0x00790920` |
| 0x4000000 (bit26) | Низкодетальный WDL-горизонт | `0x00791980` (через `0x0079A790`) |
| 0x8000000 (bit27) | Specular | `FUN_0078DE60` |
| 0x10000000 (bit28) | Шейдеры DetailDoodad | `FUN_007B2760` (требует также видеоопцию) |

Отдельно: `waterLOD` принудительно обнуляется (`FUN_0078D8B0` пишет `DAT_00CDFFD0 = 0` и печатает
«waterLOD fixed to 0»; одноимённая команда `SetWaterDetail` — no-op). Значения прочих битов
(bit0/1/8/9/11/13/29) подтверждены не полностью: у них найдены потребители
(`0x007964A0`, `0x007CD930`, `0x004F8EA0` и др.), но их семантика не расшифрована.

## 3. Батчинг и пулы буферов

Сцена собирает «записи инстансов» (stride 0x44: тип батча 0..5, указатель на инстанс,
индекс модели, число записей группы) и отдаёт диспетчеру `FUN_00823130`, который за один вызов
рисует всю группу; перед проходом толкает 11 стеков трансформаций устройства.

1. **BatchDoodad `0x00820AE0`** — несколько инстансов одной M2-модели в один динамический
   вершинный буфер и один draw (дескриптор `{primType=3, indexStart, indexCount·N, 0, vertexCount·N−1}`
   через vtable+0xA8). Два пути: без вершинных шейдеров — конвертеры вершин
   `DAT_00D4118C` пекут 32-байтные вершины; с шейдерами — на каждый инстанс копия M2-вершин
   (страйд 0x30) плюс ushort-буфер костей `0x008360A0`/`0x008362B0`, а транспонированные
   костные матрицы (0x40 байт/кость) уходят в staging-область устройства
   `0x00683560`/`0x00683580`. Батч не дробится по освещению: при ненормированных нормалях
   просто включается состояние «normalize normals» (`FUN_00685970(5)`). Ёмкость чанка —
   `0x00836DF0` (кратна 16, потолок `model+0x194`), т.е. на практике 1 draw на батч.
2. **Батч частиц `0x00821100`** (включается CVar `M2BatchParticles`, `0x00402470`) — эмиттеры
   сливаются, пока совпадают текстура (`emitter+0xD0`), флаги блендинга (`+0xD4`), хэндл
   текстуры и ключ эмиттера (`0x0081F800`); лимиты: суммарно `< 0x20000` индексов и буфер
   `< 0x100000/stride` байт. Квады частиц — один triangle strip (`i mod 2n`, `0x009808A0`),
   один draw на группу. CVar `M2ForceAdditiveParticleSort` (`0x004024D0`) разрешает аддитивным
   частицам не сортироваться по глубине, а сортироваться по материалам ради склейки.
3. **Detail doodad'ы** — пул инстансов (128 блоков, вершина 0x24 байта) и batched-mesh
   колбэк `FUN_00681CB0`; количество `min(DAT_00CD773C*0x40, 0x1000)`; включается битом 28
   и видеоопцией.
4. **WMO-группы** — на группу одна текстура (`+0x184`) и один шейдер-объект (`+0x194`);
   статическая геометрия карты отдельным проходом `0x007CD930` (VB/IB, страйд 0x18, один draw).
5. **Динамическая очередь геометрии** `0x006855C0/0x00685640/0x006845B0` — накапливает до
   0x20000 элементов, сама делает flush и один indexed draw; индексный буфер — один на устройство.
6. **Пулы** `CGxPool`/`CGxBuf` (`0x006876D0`/`0x00687660`): фиксированные блоки вместо
   per-object аллокаций. Примеры: `FVBBList_vtx` (16 Б × 545 вершин × 24 блока ≈ 204 КБ),
   `CMap::lowDetailIndexPool` (2 блока × 1536 индексов — ровно максимум holes-тайла WDL:
   256 ячеек × 6 индексов), пулы `WCHUNK`/`WMAPOBJ`/`WMAPOBJGROUP`/`WDOODADDEF` и т.д.

## 4. Управление состоянием устройства

- **Теневая копия состояний**: слот +0x04 `0x006A4C30` сравнивает запрошенное Gx-состояние с
  тенью на устройстве (`+0x3E60…+0x3E98`) и вызывает `SetRenderState` только при изменении;
  таблицы конверсии `0x00A2F8D4/964/994/FA14/FA24`; override-битфилд `+0x2758`.
- **Журнал состояний** `FUN_00685970`: записи 0x18 байт (id, значение, поколение, used) в
  `device+0x28F4`; используется десятками мест сцены (батчи, террейн) для ленивой установки
  состояний без немедленных вызовов D3D.
- Буферы создаются `CreateVertexBuffer(size, usage, FVF=0, pool)` (`0x0069FB00`) и
  `CreateIndexBuffer(..., D3DFMT_INDEX16)` (`0x0068E180`); usage = WRITEONLY, для динамических
  батчей +DYNAMIC (0x200); lock/unlock регистрируют буфер в пуле устройства
  (`device+0x2778[type]`), обновление — `0x0068FD00` (lock → memcpy → unlock).
- Draw-дескриптор 16 байт `{primType, startIndex, vertexCount, minIndex, maxIndex}`, количество
  примитивов — через таблицы `0x00AD8B4C/0x00AD8B64`; вызовы `DrawIndexedPrimitive`/
  `DrawPrimitive` (+0x148/+0x144).

## 5. Видимость и отсечение

- **Frustum-отсечение** — общий выключатель бит 5. Для террейна — per-triangle отбор
  `0x007D8840` (проверка hole-маски `MCNK+0x3C`, таблица вершин, треугольник рисуется, если не
  все три вершины снаружи; нормали — SIMD-кросс при поддержке CPU). Дальность кадра считается
  с FOV-поправкой: `_DAT_00CD877C = farclip / cos(fov/2) − farclip` (`0x0079A870`).
- **Порталы WMO**: у группы массив порталов `+0xF8` (0x18 Б), таблица целевых групп `+0x160`
  (0x40 Б), флаги `+0x198`; группа с именем `antiportal` не регистрирует портальную геометрию
  (`0x007D82E0` → `0x007D81C0`). Геометрия портального набора копится в общих массивах кадра
  (индексы до 0xC000, вершины до 0x4000) и рисуется одним проходом. `CPortalView` — это плоские
  0x1C-байтовые записи кадра (тег аллокатора), а не полиморфный класс. Команда `TogglePortals` —
  заглушка `FUN_008E5250` (`xor eax,eax; ret`); портальный проход управляется битом 21.
- **Программные окклюдеры**: `CWorldOccluder` — 0x20-байтовые плоскости, строятся покадрово
  (`FUN_007CC810` → `FUN_007927E0`) по 5 per-map записям `0x00D2DC40`; `CClipVolume` — мелкие
  клип-объёмы per-map обработчиков, проверяются при обходе списка видимых объектов
  (`0x0079A160` → `0x007CCE00`). `CWorldAntiOccluder` — мёртвая ветка (только деструктор).
- **Hardware occlusion queries**: реализованы (D3D9 + `GL_ARB_occlusion_query`), CVar `occlusion`
  (гейт `0x009AC3C0`, хэндл `0x00CD85B4`), результат — доля перекрытой экранной площади
  (`0x009ABE00`, samples/площадь). Но единственные потребители — **солнце/луна и их гало**
  (`0x007F0870` → `0x009AC400`/`0x007EF6E0`), а не объекты мира. Для видимости мира клиент
  использует frustum + порталы + программные плоскости, а не GPU-запросы.
- Отладочные счётчики «Active objects: %u objects (%u visible)» — команда `ObjUsage`
  (`0x004D49E0`/`0x004D4AC0`, TLS-списки `ObjectMgrClient`), а не пофреймовый вывод.

## 6. LOD, затухание, дальность

- Террейн: `lod` бит2; низкодетальный горизонт WDL бит26; предвычисленные боксы/счётчики
  индексов тайлов при загрузке (`0x007CC310`), пул индексов низкой детализации (`0x0079E7C0`).
- Погружение/появление моделей: биты 14/15 (objectFade / ZFill-проход), альфа модели
  `model+0x19C`, «SWModelFadeout»; ZFill-дубликат записи для стабильного порядка.
- Настройки теней и воды: `shadowLOD`, `extShadowQuality`, `mapShadows`, `Terrain shadow map mip
  level`, `mapObjLightLOD`, `waterLOD` (принудительно 0), `maxLOD`.
- Текстуры: `texLodBias` (-1..1), `baseMip` (0/1), число мип-уровней текстур персонажей,
  `CMipBitsCache`.
- LOD моделей по дистанции в сборщике сцены не обнаружен: видимость определяется готовностью
  и порогами альфы, дальние модели гасятся затуханием (биты 14/15), а не заменой геометрии.

## 7. Обновление анимации, кожа (skinning), стриминг

- **Кости/skinning**: палитра 0x40 байт на кость, аппаратный путь с костными матрицами в
  константах шейдера (ветка `DAT_00D43020 != 0`; флаг выставляется при инициализации устройства,
  мест записи в корпусе нет); программный fallback — конвертеры вершин `DAT_00D4118C`.
- **Троттлинг**: палитра/матрицы модели пересчитываются не чаще одного раза за кадр по грязному
  флагу (`model+0x3C` против `scene+0x14` в `0x00830DC0`); интервального «каждый N-й кадр» нет.
- **Очередь команд модели**: записи 0x50 байт (`model+0x34`), проигрываются в `0x00832EA0`
  с восстановлением времени — анимации/эффекты применяются пакетно.
- **Асинхронная загрузка**: поток `AsyncFileReadThread` `0x004BA680`, ожидание
  `AsyncFileReadWait/All` `0x004BA060`/`0x004BAE10` (45 загрузчиков: M2, mapobj и др.),
  CVar `asyncThreadSleep`/`asyncHandlerTimeout` (`0x004026B0`); при отсутствии async
  (`DAT_00CE0494`) группы WMO готовятся синхронно.
- **Кеши**: M2-кеш по нормализованному пути (`0x0081C390`: hash по имени, `.mdx/.mdl→.m2`,
  refcount `0x00835970`), пул `CM2Model` (0x2F0 × 0x800), «model.blob»/`CModelBlob`,
  текстурные кеши `CTexCache`/`CMipBitsCache`/`CTextureBlob`, пулы текстур карты.

## 8. Тени, вода, частицы, погода, миникарта (точечно)

- **MapShadow**: 3 слота, для каждого заранее выделены буферы (2×0x2000 + 2×0x18000) —
  ноль аллокаций в кадре (`0x007BA840`); два режима обработки (позиции/цвет и агрегирование);
  CVar'ы `shadowInstancing`, `shadowScissor`, `shadowCull`, `Terrain shadow enabled`.
- **`CWorld::shadowMod` `0x00780660`**: процедурная 8×8-текстура из одного цвета, пересоздаётся
  только при смене цвета (`DAT_00CD7878`); дешёвый LUT для затенения.
- **Вода**: `Liquid::*` (материалы, `CWaveManager`, `CClientEnvironment`); `waterLOD` глушится,
  `SetWaterDetail` — no-op; сортированные инстансы воды — отдельный проход (bit24).
- **Частицы**: CVar `particleDensity` (`0x0078D860`: 0.1..1.0 → `0x00980F70`), сортировка
  `CSortableParticleRecord`; батчинг — см. раздел 3.
- **Погода**: 5×5 сеток по 1024 float, лимиты жизни/дистанции, список ограничен 0x95
  (`0x00788090`, `0x0078C500`).
- **Миникарта**: кеш плитки по дистанции, не более 4 юнитов и 40 меток
  (`0x007F3F40`, `0x007F4320`, `0x007F4390`), `minimapPortalMax`.

## 9. Что осталось не установлено

- Выбор чанков/LOD и дистанции террейна (тела `0x007CFBE0`, `0x007989C0`, `0x00793B10`,
  `0x00793C30`); финализация видимого набора по портальному графу
  (потребители массивов `0x00CB7528/7530/7534`).
- Потребители плоскостей `CWorldOccluder` (`0x009DC5B0`, `0x009CECxx`).
- Семантика битов 0/1/8/9/11/13/29 и условие включения бита 28 при старте.
- Точные форматы вершин (3/5/8/0xC) и страйды в шейдерном пути.
- Фактические значения CVar и выбранный backend/настройки в реальных запусках (не трассировались).

## 10. Применимость к нашему WebClient

Наш рендер (карта — `notes/webclient-renderer.md`): один RAF-цикл, стриминг террейна LRU/бюджеты,
`InstancedMesh` для сцены и травы, каскадные тени, воркеры декодирования, кеши моделей/материалов.
Главные боли по `docs/PERF_STATUS.md`: число draw-вызовов (p50 1103 / p95 2602, 14–16 мкс/вызов,
~2000 вызовов ≈ 30 мс в толпе), ~465 смен материала за кадр, теневой проход, мусор ~0.8 МБ/кадр.

Сверка с каталогом оптимизаций — [OPTIMIZATION_CATALOG.ru.md §9](OPTIMIZATION_CATALOG.ru.md):
пункты 1–4 и 7–8 там уже есть (RND-16, RND-3, UNT-1, UNT-4, ARC-1, UNT-12; фейд уже в коде),
слияние материалов мерилось как шаг 18 (+4,2 % FPS, отклонено), а цена кадра — в JS-обвязке three
(вызовы GL — 0,64 из 8,9 мс `render`), а не в числе вызовов как таковом. Новые пункты —
RND-23 (`antiportal`) и ENV-23 (поправка дальности на FOV); RND-17 понижен по п. 6.

Приоритетные заимствования:

1. **Слияние батчей в общий VB с лимитами и одним draw** (по образцу `0x00820AE0`/`0x00821100`):
   группировать по (модель, материал, текстура, флаги блендинга), заливать вершины в один
   динамический буфер чанками (`< 0x100000/stride` по объёму и `< 0x20000` по индексам),
   один draw на группу. Это прямо бьёт по нашим 2000+ вызовов.
2. **Общий индексный буфер устройства** и очередь динамической геометрии с авто-flush на
   131072 элементах (схема `0x006855C0/0x00685640/0x006845B0`) — меньше переключений IB и
   меньше мелких draw.
3. **Теневая копия состояний** (слот +0x04 `0x006A4C30`): пропускать установку идентичных
   состояний/униформ. У нас уже есть кеш float-униформ — расширить на depth/blend/cull и
   «материальные» состояния; ориентир — сокращение 465 смен материала.
4. **Отложенные состояния через журнал** (`0x00685970`): записывать намерения и применять
   пачкой перед draw, вместо немедленных вызовов Three.js.
5. **Отсечение**: глобальный дебаг-выключатель culling (bit5), per-triangle отбор террейна по
   hole-маске (у нас маска уже есть в `TerrainGeometry`), FOV-поправка дальности
   (`farclip/cos(fov/2) − farclip`) для дистанций стриминга и scenery.
6. **Не вкладываться в GPU occlusion queries для мира**: в оригинале они применяются только к
   солнцу/луне. Наши порталы WMO + frustum — ровно тот путь, что использует клиент; стоит лишь
   добить antiportal-группы (по имени), плоские массивы портальных записей без аллокаций и
   единый флаг портального прохода.
7. **Затухание вместо pop-in** (биты 14/15): альфа-фейд дальних объектов; у нас уже есть
   «рост растительности» и дальние shell-модели — добавить фейд для инстансов сцены.
8. **Обновление костей/поз не чаще раза в кадр по грязному флагу** (`0x00830DC0`) и очередь
   команд модели — пригодится для толпы; у нас pose-воркер уже даёт +26%, латч по dirty-флагу
   дешевле.
9. **LUT-текстура для мелких обновлений** (образец `CWorld::shadowMod`): обновлять 8×8
   `DataTexture` только при смене параметров вместо пересборки материалов.
10. **Малые бюджеты** (миникарта ≤4 юнитов/40 меток, погода ≤0x95, порталы миникарты) —
    простые ограничители на случай пиков.
