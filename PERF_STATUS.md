### Незавершённый шаг 7

**Шаг 7 — F1a: отсутствующая регистрация основной скелетной модели в прогреве.**
Trace `2026-09-20T10-31-12-882Z`: исходный opaque skinned Standard отсутствует среди
подготовленных программ; появляется при render после fade вместе с depth.

Основной критерий — ≥5% уменьшения максимальной CPU длительности, без регресса FPS/картинки.

Исходный профиль без affinity не используется для принятия новых оптимизаций.

## Как будет устроен харнесс

1. Отдельная страница и Node runner в `bench/`, команда `npm run bench`.
   Production bundle собирается из текущего TypeScript через установленный esbuild,
   без изменения алгоритмов рендера. Runner сам поднимает временный loopback HTTP-сервер
   и headless Chrome через Puppeteer, затем закрывает только свои процессы.
2. Использовать реальные пути `WorldRenderer3D`, `Terrain`, `Visuals`, `AnimatedModel`,
   `ModelBuild` и `TextureLoad`, локальные модели/текстуры/тайлы текущего клиента.
   Уже существуют `BenchmarkReplay`, публичные методы диагностики `WorldRenderer3D`
   и `lab/CharacterLab.ts`, позволяющие работать без аккаунта/worldserver.
   Предыдущие `.runtime/qa-*` пробы полезны как пример, но не заменяют новый baseline.
3. Зафиксировать seed, 1280×720, DPR/pixelRatio 1, настройки графики, время суток,
   маршрут и длительность 20 секунд. Прогрев описывается явно и исключается из выборки.
   Передвижение должно проходить через границу тайлов и упражнять настоящий streaming;
   стресс-профили — 10, 50 и 200 анимированных персонажей. Не подменять их кубами.

## Гипотезы

### Открытые / подтверждённые причины в порядке ожидаемого эффекта

**Толпа (CPU-bound):**

0. **C6 — открыта: главный расход внутри world submission в живой толпе.**
   Историческая игровая запись: ~31 ms world submission против ~11 ms pose
   в отобранных медленных кадрах. Нужна актуальная разбивка matrices / skeleton /
   shadows / draw calls. CPU профили однотипных HumanMale не заменяют её.
1. **C1 — причина подтверждена, проверенная оптимизация отклонена.** На 200 моделях baseline CPU 39.44 ms,
   GPU 5.04 ms. В CPU profile `Object3D.updateMatrixWorld` — 34.37% self,
   `Matrix4.multiplyMatrices` — 19.75% self (54.12% вместе, без суммирования inclusive).
   Есть 45600 костей. Приоритет: специализированный эквивалентный путь аффинных матриц
   для управляемых костей; обычный Three-путь оставить для нестандартных/ручных матриц.
   Ожидание: CPU 24–30 ms, FPS 33–41 (+32–64%); вершины, кости и частота анимации сохраняются.
2. **C2 — проверена в шаге 3, оптимизация отклонена (<5%).**
   19.98% inclusive профиля (пересекается с multiplyMatrices выше). Проверить возможность
   убрать лишнюю общую математику без исключения нужных костей. Ожидание отдельного шага:
   ещё 2–4 ms CPU на 200 моделях.
3. **C3 — подтверждена стоимость, решение открыто: применение анимаций.**
   Baseline animation 12.49 ms; `PropertyMixer.apply` 15.59% self профиля,
   обновление Euler из quaternion 3.64% self. Рассматривать только точные преобразования,
   без снижения частоты и синхронизации фаз разных персонажей. Ожидание: 2–5 ms CPU.

**Фризы при перемещении:**

1. **F1 — подтверждено: синхронное создание новых shader programs при первом render.**
   Trace: CPU 133.2 / 83.0 ms, submit 116.4 / 74.8 ms, в каждом кадре +2 программы.
   `GLES2Implementation::GetProgramiv` блокировал поток на 78.626 и 34.104 ms.
   Первый случай — depth + opaque skinned Standard после появления персонажей;
   следующий — новые surface/foliage варианты. Требуется подготовка точных вариантов
   до первого видимого использования. Ожидание: >30ms 3 → 0, max CPU 118.2 → <30 ms.
2. **F2 — подтверждена вторичная стоимость: terrain rebuild / scenery / grass.**
   Terrain в trace до 17 ms, целый такой кадр 24.2 ms; baseline ground до 10.6 ms.
   Рассматривать после F1/C1, если останутся кадры >30 ms.
3. **F3 — вторичная нагрузка: GC.** В trace MinorGC max 2.702 ms,
   MajorGC 6.763 ms; они не объясняют два крупнейших фриза.
